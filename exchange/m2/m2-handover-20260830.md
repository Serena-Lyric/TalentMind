## 二、岗位数据格式（队友整合接口）

### job_definition.json 每条岗位定义结构

```json
{
  "job_name": "Data Architect",
  "core_duties": "...",
  "required_skills": ["aws", "etl", "data warehousing", "sql"],
  "bonus_skills": ["python", "redshift"],
  "scenarios": ["...", "..."],
  "source": ["linkedin"],
  "quality": 0.73,
  "is_emerging": false,
  "evolution": {"stage": "growth", "stage_confidence": 0.6, "indicators": {...}},
  "first_seen": "...",
  "collected_at": "...",
  "updated_at": "...",
  "source_jd_count": 3
}
```

### job_skill.json 每条技能结构

```json
{
  "job_name": "Data Architect",
  "skills": [
    {
      "skill_id": "s_aws",
      "name": "aws",
      "weight": 0.15,
      "confidence": 0.9,
      "evidence": "JD #112345: Knowledge of AWS services",
      "evidence_jd_count": 2,
      "verification": "verified",
      "is_required": true
    }
  ]
}
```

**关键字段说明**：
- `evidence`：技能在原始 JD 中的**原文引用**（赛题要求的"数据源"）
- `verification`：`verified`（双模型确认有依据）/ `suspicious`（单模型存疑，confidence 已降 0.15）
- `source_jd_count`：该岗位由多少条 JD 聚合而来

## 三、岗位筛选范围（赛题要求）

**新一代信息技术领域**：AI/大模型、大数据、智能系统、物联网、云原生、网络安全、软件工程。

已排除：传统 IT 运维（网管/桌面运维）、ERP/CRM 管理员、非技术岗位（医疗/法律/金融/教育/零售等）。

## 四、数据质量保障

1. **L2 双闸门筛选**：标题快筛 + 正文判定 + 客观技术信号交叉
2. **L5 双模型证据验证**：qwen3.7-plus ∥ mimo-v2.5-pro 独立核查每条技能
   - 双证通过 → verified
   - 单证存疑 → suspicious（降级）
   - 双证失败 → 删除（幻觉）
3. **质量过滤**：技能 <3 的残缺 JD、0 技能的提取失败、>50 技能的复合岗位自动剔除

## 六、增量更新机制（重要）

后期刷新岗位数据**不需要全量重跑**：

```bash
# 新数据包到达后，只处理新增/变化的部分（分钟级）
python main.py <新数据包路径>

# 全量重跑（数据源大换血时）
python main.py <数据包路径> --force
```

机制：
- 指纹对比：内容未变的跳过（零成本）
- 新岗位自动进管道；下架岗位记变更日志
- 变更日志标注新增/删除/修改的技能 + 数据源
