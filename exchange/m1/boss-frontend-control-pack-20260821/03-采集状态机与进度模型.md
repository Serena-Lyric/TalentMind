# 03 采集状态机与进度模型

## 设计原则

- 不把“端口监听”“浏览器有页面”“采集进程运行”“数据库有新增”混为一个状态。
- 不承诺全量百分比：BOSS 搜索结果会变化，当前没有可计算的全站总任务量。
- 进度以“当前轮次 + 当前关键词/城市 + 本轮计数 + 最后心跳/日志时间”为主。
- `new=0` 是有效结果，不等于失败；它表示本轮识别到的岗位 URL 都已存在。

## 建议状态枚举

| 状态 | 含义 | 前端建议 |
|---|---|---|
| `idle` | 没有采集任务 | 显示可启动 |
| `preparing` | 已接收启动请求，正在校验参数 | 显示准备中 |
| `waiting_for_browser` | 等待 9333/CDP 或 BOSS 页面 | 显示需要打开独立 Edge |
| `running` | 正在抓列表或详情 | 显示当前轮次和计数 |
| `waiting_next_round` | 当前轮完成，等待下一组合 | 显示倒计时/下次时间 |
| `stopped` | 用户主动停止或有限轮数完成 | 显示停止原因 |
| `completed` | 单轮/有限轮数正常结束 | 显示汇总 |
| `error` | 非 CDP 类未处理异常或启动失败 | 显示错误和日志入口 |
| `auth_required` | 页面要求登录 | 引导用户人工登录，不自动处理 |
| `verification_detected` | 页面出现验证/风控提示 | 停止并提示人工处理 |
| `cdp_unavailable` | CDP 端点不可用或无可用页面目标 | 提示检查 Edge 和 9333 |

```json
{
  "run_id": "boss-20260821-110438",
  "status": "waiting_next_round",
  "mode": "forever",
  "started_at": "2026-08-21T11:04:38+08:00",
  "finished_at": null,
  "current_keyword": "机器学习",
  "current_city": "上海",
  "current_round": 116,
  "total_rounds": null,
  "listed": 12,
  "details": 8,
  "new": 1,
  "skipped": 11,
  "errors": 0,
  "last_error": null,
  "next_run_at": "待根据切换间隔计算",

```

上述 JSON 是前端联调示例，不是当前已提供的 API 响应。

## 进度口径

- `listed`：本轮从列表页识别并进入处理范围的岗位数。
- `details`：本轮实际尝试补采详情的岗位数，不代表详情字段全部完整。
- `new`：本轮通过来源 URL 去重后新写入 `jd_pool` 的岗位数。
- `skipped`：因已存在 URL 等幂等原因跳过的岗位数。
- `errors`：本轮记录的异常数；CDP/登录异常会让循环安全停止。
- `database_boss_total`：数据库中当前 `source='boss'` 的累计条数。
- `database_new_count`：本次运行相对启动前的累计新增，建议由后端启动时保存基线后计算。

## 状态转换

```text
idle
  -> preparing
  -> waiting_for_browser
  -> running
  -> waiting_next_round -> running
  -> completed          （单轮/有限轮次正常完成）
  -> stopped            （用户停止）
  -> auth_required      （需人工登录）
  -> verification_detected（需人工处理）
  -> cdp_unavailable    （端口或页面目标不可用）
  -> error
```

恢复方式建议是“重新启动一次任务”，而不是自动重试登录、验证码或风控流程。
