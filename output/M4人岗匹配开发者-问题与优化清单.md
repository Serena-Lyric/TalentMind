## P0 必须处理

### M4-P0-01 实现 pathfinder

当前 Resume 上传实测能返回 score、matched、missing，但 `missing[].tip` 为空，且没有 `path` 字段；Learning 没有真实数据源。

要求输出至少包含：

```json
{
  "target_job":"Senior Software Engineer, Back End",
  "score":42,
  "matched":["python"],
  "missing":[
    {"name":"go","level":"medium","tip":"..."}
  ],
  "path":[
    {"skill":"go","reason":"岗位必备技能缺口","prerequisites":[]}
  ]
}
```

- `level/tip` 必须基于技能类别、岗位必备/加分属性和 evidence；
- 不编造学习时长、薪资提升或成功概率；
- path 应能被 M5 Learning 直接消费；
- 没有缺口时返回空路径并说明已满足。

### M4-P0-02 明确目标岗位匹配协议

当前前端有目标岗位选择，但后端上传接口没有接收目标岗位，会自动选择最高匹配岗位。请新增 `target_job_id` 或稳定 `job_name` 入参，并在响应中回显。

### M4-P0-03 提供脱敏标注测试集和准确率报告

项目要求至少 30 份简历标注测试集并报告提取/匹配准确率。测试集不能含真实简历，若测试写入 resume/talent_raw 等表，必须在 finally/fixture teardown 中按唯一夹具标记精确删除本次写入；禁止按 source 等宽泛条件 DELETE；运行后查询夹具计数为 0，确认无真实数据被误删。

## P1 重要优化

- 修复中文紧邻英文技能提取，如 `熟悉Python`；
- Resume 上传成功后是否写入 `resume` 表应由 A/M4 明确，若写入必须有脱敏和清理策略；
- `skill_extractor`、`resume_parser`、`matcher` 的输出结构统一，避免 `matched_skills/unmatched_job_skills/resume_extra_skills` 与 API 的 `matched/missing/strengths` 多套命名；
- missing 技能排序应按 required、weight、confidence 和岗位级别综合排序；
- 对 PDF/DOCX/TXT 分别做编码、空文本、超大文件、损坏文件测试；
- skill canonical 归一失败时保留原文和复核标记，不能静默丢失；
- 匹配分数要能解释：总分、必备技能覆盖、加分技能覆盖分别返回。
