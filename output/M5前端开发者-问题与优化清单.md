# M5 前端开发者问题与优化清单

## P0 必须处理

### M5-P0-01 Dashboard 显示了与后端不一致的统计

**证据**

- `frontend/src/views/Dashboard.vue:153-159` 初始化了 2468、8932、1847、376 和 28/24/04 等固定数字。
- `frontend/src/views/Dashboard.vue:227-243` 只调用 `getDashboardOverview()`，只更新四个 `statCards` 的 `value`，但 `animatedNums` 在 `animateNumbers()` 中提前捕获了初始化数字。
- 实测后端 `/api/dashboard/overview` 返回 `totalJobs=22`，页面仍显示 `2468`。

**要求**

1. 页面显示值必须来自 API；
2. 数字动画的 target 必须在 API 返回后重新设置，不能捕获初始演示值；
3. `coralBlocks` 也必须来自后端，若后端没有数据则显示 `—` 或“暂无数据”；
4. 所有趋势箭头和百分比必须有明确数据来源，不能写死。

**验收**：后端返回 22 时页面显示 22；刷新页面和网络慢时不会短暂显示 2468。

### M5-P0-02 Dashboard 趋势和岗位列表不能继续伪造

**证据**

- `Dashboard.vue:170-180` 的月份、趋势和薪资数据是固定数组。
- `Dashboard.vue:186-201` 的 15 条岗位列表是固定数组。
- 前端只请求 overview，没有请求 `dashboard/trend`、`dashboard/skill-distribution`、`jobs`。
- 后端 `/api/dashboard/trend` 当前返回空 series，应由页面显示空态而不是继续展示旧曲线。

**要求**

- 接通真实接口；
- 空数据使用空图表、说明文字和重试按钮；
- 在真实接口未就绪前，删除固定数字，或显式标记“演示数据”；
- 岗位列表至少从 `/api/jobs` 读取，并显示后端真实 `title/name_en/skills/updated`。

### M5-P0-03 修复 ResumeDemo 空白页

**证据**

- `frontend/src/views/ResumeDemo.vue:134`：`const resume = ref<any>({})`。
- 模板从第 21 行开始直接读取 `resume.basic.*`、`resume.education.*`、`resume.skills.details`。
- 浏览器访问 `/#/resume-demo` 时只有公共布局，没有页面内容。

**建议**

采用二选一：

1. 推荐：在 Pinia 中保存最近一次上传解析结果，ResumeDemo 读取该结果；无结果时显示“请先上传简历”的空态；
2. 如果只保留演示页：提供明确的脱敏演示数据，并在标题中标注“演示”，不能初始化为空对象后直接解引用。

**验收**：直接访问、刷新访问、从 Resume 页面跳转三种情况都不白屏。

### M5-P0-04 Learning 页面必须诚实降级

**证据**

- `frontend/src/components/LearningRoadmap.vue:392-394`：`jobPaths` 永远初始化为空，没有 API 加载。
- `LearningRoadmap.vue:454-470` 中大量操作只改本地状态或弹“功能开发中”。
- 浏览器访问 `/#/learning` 没有业务正文。

**要求**

- 在 M4 pathfinder 未完成前，显示明确空态：当前尚未生成学习路径，请先完成简历诊断；
- 接口准备好后再显示路线、阶段、任务、技能缺口；
- 不使用 `src/mock` 或内嵌岗位学习路线冒充真实结果；
- 依赖 `job` 查询参数时，必须使用后端支持的岗位 ID/key，并处理无效参数。

### M5-P0-05 Jobs 的写操作不能弹假成功

**证据**

- `frontend/src/views/Jobs.vue:400-403` 的 `batchDelete()` 没有调用 `batchDeleteJobs()`。
- `Jobs.vue:433` 的 `importJds()` 只清空文本并提示成功。
- `Jobs.vue:448` 的 `saveJob()` 只提示成功并关闭弹窗。
- 当前页面导出逻辑 `Jobs.vue:405-415` 是浏览器端 CSV 拼接，不是后端 `/jobs/export`。

**要求**

- 新增/编辑调用 `createJob/updateJob`，成功后重新拉取列表；
- 导入调用 `importJobs`，处理导入数量和失败项；
- 批量删除调用 `batchDeleteJobs`，删除成功后重新拉取列表；
- 导出若以 Excel 为产品承诺，应调用后端 Blob 接口，不要按钮写 Excel 但实际下载 CSV；
- 所有写操作有 loading、失败提示和重复提交保护。

## P1 重要优化

### M5-P1-01 Jobs 筛选字段与真实数据不匹配

页面筛选城市、赛道、技能演进状态、薪资，但后端 `/api/jobs` 当前返回的 `company/city/type/salary/track` 多为空。结果是筛选下拉框没有真实选项，筛选功能看似存在但无法产生业务价值。

建议：

- 后端未提供字段前，隐藏对应筛选项或标记“暂无数据”；
- 不要对空字段显示孤立的 `· ·`；统一显示 `—`；
- 过滤条件要么传给后端分页查询，要么明确是当前页过滤。

### M5-P1-02 Jobs 详情应调用详情接口

现在点击详情直接使用列表行 `openJdDetail(row)`，没有调用 `getJobDetail()`。后续岗位详情字段增加后，列表对象不完整会导致详情缺字段。

验收：点击详情时根据 `id` 请求 `/api/jobs/{id}`，失败可重试，关闭弹窗不丢列表状态。

### M5-P1-03 Graph 的筛选、聚焦和导出目前不完整

**证据**

- `GraphPanorama.vue:192-193` 有 `selectedTrack/selectedLevel`，但 `loadGraphData()` 固定调用 `getGraphData()`，没有使用筛选值。
- `GraphPanorama.vue:155` 只导入 `getGraphData`，`getGraphJobs/getGraphYears/getGraphSkillRadar` 没有使用。
- `GraphPanorama.vue:739-740` 的导出按钮只提示“功能开发中”。
- 后端 `/api/graph/data` 当前也没有真正实现 `year/focus_job` 过滤。

要求：

- 先和 A/M3 确定过滤语义，再实现真实查询或前端过滤；
- 岗位下拉/年份下拉应加载接口数据，而不是空壳；
- 节点详情中需要真实 radar 时调用对应接口；
- 导出按钮要么导出当前可视图/JSON，要么暂时隐藏。

### M5-P1-04 Graph 视图需要控制节点密度

当前 97 节点/222 边在树状图中右侧标签严重重叠。建议：

- 默认显示岗位聚焦或技能 Top N；
- 支持“仅显示关联节点”；
- 标签按缩放级别显示；
- 对树状图设置最大展开深度或分页。

### M5-P1-05 Resume 上传交互需要真实校验

页面提示最大 10MB，但没有看到前端 size 校验；顶部隐藏 input 接受 `.txt`，拖拽上传又只接受 `.pdf,.doc,.docx`，规则不一致。

要求：

- 统一支持格式；
- 上传前校验扩展名和字节数；
- 使用 `before-upload`/统一校验函数；
- 错误时保留页面状态，不把失败文件标记为成功。

### M5-P1-06 Resume 雷达图不能固定空数组

`ResumeDiagnosis.vue:213-217` 的 `radarData` 永远是三个空数组，且没有调用 `getSkillDimensions()`。

要求：

- 上传成功且有目标岗位后请求技能维度；
- 空响应显示“暂无能力维度数据”；
- 不要渲染空 ECharts 雷达图造成视觉误导。

### M5-P1-07 Resume 目标岗位必须参与匹配

当前页面允许用户选择目标岗位，但上传函数只调用 `uploadResume(file)`，没有把目标岗位传给后端。后端会遍历岗位并选最高分岗位，可能与用户选择不一致。

要求：明确协议：

- 推荐：上传接口接收 `target_job_id`，按用户选择匹配；
- 或者：后端返回所有岗位排名，前端再选择；
- 页面展示的“目标岗位”和返回的 `target_job` 必须一致，否则提示用户。

### M5-P1-08 统一前端类型和 API 命名

当前存在 camelCase/snake_case 混用：`pageSize/page_size`、`matchResult/target_job`、`totalJobs/total_jobs`。建议由 A 冻结 DTO，前端 API 层统一转换，组件内不要同时维护两套字段名。
