### 2.1 作品设计实现方案文档

**文件名**：`docs/submit/作品设计实现方案.md`
**目标页数**：20-30 页（导出 PDF）
**负责人**：A 统筹架构，各模块负责人补技术细节

#### 文档结构

```
1. 项目概述（2-3 页）
   1.1 背景与痛点
       - 数字经济转型、人口红利→人才红利
       - 结构性矛盾：企业招不到人、青年职业规划模糊
       - 传统关键词匹配的局限性
   1.2 项目目标
       - 构建"人才能力大脑"，实现静态画像→动态感知
       - 三大核心难题对应（新岗位发现、数据质量、人岗匹配）
   1.3 系统定位
       - 面向新一代信息技术领域（AI、大数据、智能系统、物联网）

2. 系统总体架构（3-4 页）
   2.1 技术架构图
       - 五层架构：数据采集层 → 数据清洗层 → 岗位分析层 → 图谱构建层 → 应用服务层
       - 附架构图（Mermaid 或手绘）
   2.2 模块划分与数据流
       - M1 数据采集：多源异构 JD 爬虫 + Signal 信号采集
       - M2 岗位分析：新岗位发现 + 既有岗位能力动态更新
       - M3 图谱构建：Neo4j 知识图谱 + 可视化
       - M4 简历解析：PDF/Word 解析 + 人岗匹配 + 学习路径
       - M5 前端：Vue 6 页面（岗位列表/图谱/匹配/学习路径等）
   2.3 部署架构
       - docker-compose 单点部署
       - 后端 18000 / 前端 18080
       - MySQL + Neo4j 双存储

3. 核心技术创新（8-10 页）★ 评分重点（25 分）
   3.1 多源异构数据采集与交叉验证 ★
       - 数据源矩阵：LinkedIn（123,849 条）、HN（1,796 条）、BOSS（488 条）、GitHub Trending、技术博客 RSS
       - 合规采集策略：robots.txt 遵守、受控人工登录 CDP（BOSS）、公开 API（HN Algolia）
       - 时滞/噪声/抄袭检测：
         * 时滞：采集时间戳 + 帖子发布时间双记录
         * 噪声：HTML 剥离、字段归一化、experience 长度截断修复
         * 抄袭：cross_validate 双向包含 + 长度比 ≥0.6 判定，887+ 对交叉验证
       - 质量分体系：quality 独立字段 + cross_source 标记
       - 幻觉防控：skill_dict 约束抽取（≥200 canonical 技能词表），LLM 输出限定在词典内

   3.2 新岗位发现机制 ★
       - 技术路线：聚类（技能组合特征）→ 与既有岗位比对 → LLM 候选生成 → 人工确认
       - 判定标准：is_emerging 字段，基于技能组合新颖度 + 出现频率趋势
       - 输出：岗位定义五要素（名称、核心职责、必备技能、加分技能、典型场景）
       - 当前成果：从 424 条 JD 提取 22 个岗位定义

   3.3 既有岗位能力动态更新 ★
       - 能力项变化检测：多轮采集时间序列对比
       - 变更类型（change_type）：新增/删除/修改 + 扩展（duties_changed、scenarios_added/removed、evolution_changed）
       - 审计追踪：job_change_log 表记录每次变更的数据源与说明
       - 演化阶段：萌芽/增长/成熟/衰退（P0 基于技能组合特征静态分类，P1 时间序列真实趋势）

   3.4 知识图谱构建 ★

       - 存储：Neo4j（97 节点/222 边）

   3.5 简历解析与技能提取

       - 技术方案：NER + skill_dict 匹配 + 正则抽取

   3.6 人岗匹配与差距分析

       - 差距分析：缺失技能项、技能熟练度差距
       - 学习路径规划：基于图谱最短路径 + 技能依赖关系

4. 系统功能展示（3-4 页）
   4.1 功能截图
       - 岗位列表页（支持按技术栈/级别筛选）
       - 全景图谱页（Neo4j 可视化，技能点级）
```

### 2.2 ≥100 条 JD 测试集构建（关闭 P1）

**文件名**：`data/test/jd_test_set_100.json` + `docs/submit/测试方案.md`
**负责人**：M2（岗位分析）主导构建，M4（匹配）参与验证，A 验收
**硬性要求**：≥100 条 JD + 测试用例 + 三项准确率 ≥90%

#### 构建方案

```
测试集构成：
├── 新岗位类 JD：30 条（AI Agent、AIGC、大模型应用等）
├── 既有岗位类 JD：50 条（Java、前端、数据分析师等，覆盖初级/中级/高级）
├── 边缘/异常 JD：20 条（超长描述、格式混乱、非技术岗混入、重复抄袭 JD）
└── 总计：100 条

每条 JD 需标注：
- 原始文本
- 期望解析结果（岗位名称、技能列表、经验要求、薪资范围）
- 标注来源（人工标注，至少 2 人交叉确认）
- 是否用于准确率计算（边缘案例可不计入）
```

#### 准确率验证方法

| 指标 | 测试方法 | 达标线 |
|------|---------|--------|
| JD 解析准确率 | 系统解析 100 条 → 与人工标注对比 → 计算字段级准确率 | ≥90% |
| 简历提取准确率 | 准备 20 份测试简历 → 系统提取 → 与人工标注对比 | ≥90% |
| 人岗匹配准确率 | 20 份简历 vs 10 个岗位 → 人工判定匹配合理性 → 对比系统输出 | ≥90% |

**注意**：准确率计算需排除边缘案例，核心字段（岗位名称、技能列表）权重更高。

## 七、关键检查清单

提交前必须逐项确认：

- [ ] 作品设计实现方案 ≥20 页，含架构图/数据流图/ER 图
- [ ] 方案中明确写出数据来源量化数字（126K+ JD、433 Signal、22 岗位等）
- [ ] 幻觉防控机制有详细说明（skill_dict + cross_source + quality）
- [ ] 新岗位发现流程有完整案例（从原始 JD 到岗位定义）
- [ ] 既有岗位能力更新有对比案例（如 Java 工程师新增 AI 辅助编程）
- [ ] ≥100 条 JD 测试集已构建并验证
- [ ] 三项准确率均 ≥90%（有测试报告支撑）
- [ ] 1 新岗位 + 1 既有岗位能力图谱示例完整（含输入输出）
- [ ] PPT 20-25 页，含系统截图和指标
- [ ] 演示视频 ≤10 分钟，包含新岗位发现 + 既有岗位更新
- [ ] 部署说明完整，docker-compose 可一键启动
- [ ] 单元测试覆盖率 ≥60%（附截图）
- [ ] 源代码仓库已开放评审权限或提供开源链接
- [ ] 所有材料已按提交包目录结构整理
