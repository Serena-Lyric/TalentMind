一、测试概述

1.1 被测系统

TalentMind 为多源异构数据驱动的岗位能力动态演化与分析系统，按模块划分为五个部分及统一数据接口层：

采集源（BOSS直聘/智联招聘/猎聘）

  ↓

  ↓

M3 能力图谱（Neo4j）── 岗位-技能-行业全景图谱

  ↓

M4 简历解析与匹配 ──── 简历技能提取 / 人岗差距分析

  ↓

  ↓

1.2 赛题要求与测试章节对照

1. 新岗位发现与定义：岗位名称/核心职责/必备技能/加分技能/应用场景，支持人工优化与动态更新 —— M2，见 2.2。

2. 既有岗位能力动态更新：新增/删除/修改的能力项 + 更新说明 + 数据源 + 时间标注 —— M2、时间演化测试集，见 2.2。

3. 新一代信息技术岗位全景图谱：粒度到技能点，按技术栈和级别切换视图 —— M3、前端，见 2.3、2.5。

4. 人岗匹配度诊断与差距分析：简历解析（PDF/Word）提取准确率 ≥90%，差距分析 + 改进建议 + 学习路径规划 —— M4、前端，见 2.4、2.5。

5. 创新性：多源异构数据清洗与交叉验证：解决 JD 时滞、噪音、抄袭、通胀问题 —— M1，见 2.1。

6. 创新性：能力幻觉防控：提升图谱构建科学性 —— M2，见 2.2。

7. 可验证性：完整测试方案：≥100 条岗位 JD 及测试用例；JD 解析准确率 ≥90%；简历提取准确率 ≥90%；匹配准确率 ≥90%；单元测试覆盖率 ≥60% —— 全系统，见 2.2、三。

8. 测试数据：1 个新岗位 + 1 个既有岗位的能力图谱及岗位数据源（含输入输出示例）—— M2，见附录 B。

二、模块测试

2.1 M1 数据采集与清洗

2.1.2 测试步骤

前置条件：Docker Compose 服务在线（MySQL/Redis）；后端 Python 虚拟环境就绪；采集目标平台账号登录态可用（BOSS/智联/猎聘需人工登录，仅用于页面采集）。

TC-M1-01 多源采集功能测试

1. 执行 BOSS 直聘采集命令。预期：控制台输出本轮采集/详情/新增统计。

2. 执行智联与猎聘采集命令。预期：输出两平台各自的采集/详情/新增统计。

3. 查询 MySQL 各数据源计数（GROUP BY source）。预期：各平台数据入库，source 字段无空值。

4. 查询 source_detail 空值计数。预期：计数为 0。

TC-M1-02 低速采集循环与异常处理测试

1. 启动 BOSS 低速采集循环。预期：循环以低速随机间隔运行，每轮输出采集/详情/新增/跳过统计。

2. 连续观察 24 小时。预期：循环稳定运行，无连续异常退出。

3. 触发登录失效/验证码场景。预期：循环检测到异常即自动停止，不重复尝试。

TC-M1-03 数据清洗测试

2. 核对清洗后数据状态字段。预期：全部为已清洗。

3. 核对 source_detail 字段。预期：空值 0、占位 URL 0。

TC-M1-04 去重与交叉验证测试

1. 输入含重复 JD 的样本。预期：按内容指纹去重，重复条目标记去重跳过。

2. 执行多平台交叉验证。预期：生成交叉验证报告，跨源命中岗位被标记跨源验证。

2.2 M2 岗位分析管道

2.2.1 测试目的

验证管道的新岗位发现与定义、既有岗位能力动态更新与幻觉防控能力。

管道分层：L0 硬规则（乱码/去重）→ L1 BM25 预筛 → L2 相关性判定（唯一筛人闸门）→ L3 质量评分 → L4 结构化提取（逐字证据）→ L5 双模型证据验证 → 合并 → 对比存量生成变化日志 → 岗位名归一化 → 导出。

2.2.2 测试步骤

前置条件：大模型服务可用（Qwen / MiMo 槽位池配置）；输入 SQL 快照就绪；已有存量数据就绪。

TC-M2-01 全量管道运行测试

1. 执行全量管道命令（输入 JD 池快照，输出至 M2 交付目录）。预期：管道按 L0→L5 顺序执行，控制台逐层输出通过/拒绝计数。

2. 检查 L2 阶段输出。预期：不属于新一代信息技术领域的岗位被拦截，输出拒绝原因。

3. 检查 L4 阶段输出。预期：每条技能附带证据（JD 原文逐字引用），证据为空触发重试。

4. 检查 L5 阶段输出。预期：技能验证结论为已验证 / 存疑 / 已删除之一。

5. 核对导出文件。预期：岗位定义 / 岗位技能 / 变化日志三类文件生成，含版本头。

6. 逐条核对岗位定义字段与分类口径。预期：717 条定义，岗位名称、核心职责、数据源、演化阶段与技能均齐全；新一代 342 条、现有 375 条。

TC-M2-02 增量更新测试

1. 构造新快照（原快照 + 新增 JD + 修改 1 条 JD）。

2. 执行增量更新命令。预期：仅处理新增/变化 JD（指纹跳过），已处理数据不重复计算。

3. 核对变化日志。预期：新增日志含检测时间与证据数据时间双重时间。

4. 快照中删除 1 条 JD 后再次执行。预期：对应岗位记录下架，生成下架日志。

5. 连续执行两次。预期：第二次无重复处理（幂等）。

TC-M2-03 能力更新日志测试

1. 读取能力更新日志数据并核对字段。预期：275 条记录，每条含变化原因、来源、检测时间、证据数据时间。

2. 按 change_type 统计并抽查职责变化。预期：added 187 / scenarios_added 75 / evolution_changed 5 / duties_changed 8（其中 32 条为 7 个岗位的能力动态演示记录）；duties_changed 须经语义判定确认"显著变化"方写入。

TC-M2-04 幻觉防控测试

系统按三层部署防幻觉机制：

第一层：提取层自约束（L4）。提取提示词硬性要求每条技能的证据为 JD 原文逐字引用（≤50 字，禁止改写/翻译/总结）；找不到支持引用的技能不得输出。结构校验兜底：证据为空触发重试。L4 提取与 L5 验证使用同一份清洗后文本，证据引用始终可回溯。

第二层：双模型证据核查（L5）。两个异构大模型（Qwen与 MiMo）并行核查每条技能（只报异常），核查输入为技能证据前后各 400 字的证据窗口（不截断全文，避免长 JD 误判）。融合规则：双模型均判异常 → 删除（幻觉）；仅一个判异常 → 降级存疑，置信度 −0.15，保留；均通过 → 已验证；任一模型出错/解析失败 → 该岗位不判定、不删除（遵循不误删原则）。

第三层：聚合闸门。合并后技能 >50 的复合岗位（多岗位聚合帖）剔除；同名技能仅保留最高置信度证据并统计独立 JD 支撑数；核心职责变化须经轻量模型确认"显著语义变化"方写入变化日志，防止虚假更新记录。

测试步骤：

1. 全量运行管道（管道运行统计记录）。预期：提取技能全部带证据。

2. 抽查技能证据。预期：每条证据均可在对应 JD 原文中逐字检索到。

3. 构造无依据技能样本输入 L5。预期：双 Judge 均判异常 → 删除。

4. 构造模糊依据样本（如"熟悉主流框架"对应 React）。预期：模糊表述不计为支持 → 判异常。

5. 模拟单个 Judge 调用失败。预期：该岗位不判定、不删除。

TC-M2-05 时间演化测试集测试（≥100 条测试用例）

用例集构成：

150 种岗位 × 3 个时间版本 = 450 条 JD（新一代 85 + 现有 65），全部来自 BOSS/智联/猎聘中文平台的管道真实筛选结果。

每个岗位准备了同一岗位在三个不同时间点的 JD（相当于同一岗位在不同时期发布的招聘信息）：版本 1 时间最早、技能要求最少；版本 2 处于中间、新增了部分技能；版本 3 时间最新、技能要求最全。三个版本时间跨度 8~14 个月。

版本 3 = 真实 JD：编号 / 原文 / 采集时间与数据库记录逐字一致，预期技能为管道真实提取的技能（真值）。

版本 1/2 = 演化回溯版：时间戳按真实变化规律回拨、技能按"最新技能（低置信度）"递减、正文按证据句删减，每条变化附变化标注（如"新增技能要求：resnet、人工智能"）。

每条用例含：岗位名、分类、来源、3 个版本（各含岗位正文、预期技能、变化标注）、时间跨度（月）、真实 JD 编号。

测试用途：将三个版本分别输入管道，对比管道对同一岗位在三个时间点的提取结果，验证管道能捕捉技能要求随时间的变化（如 6 个月前新增 tensorflow/pytorch、最近又新增 resnet），即赛题②"既有岗位能力动态更新"的演示机制。

测试步骤：

1. 将每个岗位的 3 个版本分别输入管道。预期：提取结果按版本输出。

2. 对比各版本提取技能与预期技能真值。预期：命中率 ≥90%。

3. 对比版本 1→2→3 的技能差异。预期：捕捉到技能随时间的变化。

4. 核对变化时间标注。预期：变化时间与版本时间戳一致。

5. 交付数据与版本 3 真值一致性核对。预期：一致性 ≥90%。

TC-M2-06 人工优化与动态更新测试

3. 提交新全量快照后执行增量更新。预期：新增岗位自动分类、变化日志追加、接口数据实时更新。

4. 核对人工优化结果持久化。预期：再次导出后人工修改内容保留，不被下次自动运行覆盖。
