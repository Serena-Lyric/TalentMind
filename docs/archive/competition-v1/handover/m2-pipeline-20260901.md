# M2 岗位分析管道源码(最新版 2026-09-01)

> 新一代信息技术岗位筛选与标准化管道,含增量更新、中英同岗位合并、数据接口。

## 环境

```bash
pip install -r requirements.txt
```

Python 3.10+。config.py 里带 LLM API 密钥(DeepSeek 官方 + go 端点),队友可用自己的 key 替换。

## 快速开始

### 1. 数据接口(页面取数)

```bash
uvicorn api:app --host 0.0.0.0 --port 8000
```

| 端点 | 返回 |
|---|---|
| `GET /api/jobs?category=新一代` | 岗位定义列表 |
| `GET /api/jobs/{job_id}` | 单岗位详情 |
| `GET /api/skills/{job_id}` | 技能详情(含 JD 原文证据) |
| `GET /api/changes?since=2026-09-01` | 变化日志(带时间+证据) |
| `GET /api/categories` | 分类汇总 |

数据源:`exchange/M2_final/`(719 岗位:新一代 344 / 现有 375,变化日志 243 条)。

### 2. 全量跑管道(输入 SQL 快照)

```bash
python main.py <jd_pool.sql> --output exchange/M2
```

### 3. 队友新数据接入(增量更新,★日常用这个)

```bash
python scripts/incremental_update.py <新全量快照.sql>
```

自动完成:只处理新增/变化 JD(指纹跳过)→ 中英同岗位合并 → 新增岗位自动
分类(新一代/现有)→ 变化日志(每条带 created_at + source_jd_time + JD 原文
证据)→ 原子更新 exchange/M2_final(接口实时读到)。

### 4. 时间演化测试集生成

```bash
python scripts/make_evolution_testset.py
```

150 岗位 × 3 时间版本 = 450 条 JD,最新版 = 真实筛选原文,用于演示
"既有岗位能力动态更新"。

## 管道结构

```
输入 SQL/JSON
  → L0 硬规则(乱码/去重)→ L1 BM25 预筛
  → L2 相关性(deepseek-v4-flash,官方端点,唯一筛人闸门)
  → L3 质量评分(qwen3.8-max)
  → L4 结构化提取(deepseek-v4-flash 主力 / pro 分流,带逐字证据)
  → L5 双模型证据验证(qwen3.7-plus ∥ mimo-v2.5-pro,防幻觉)
  → 合并(>50 技能/多岗位聚合帖剔除)
  → 对比存量(变化日志,duties_diff=deepseek-v4-flash)
  → 双语岗位名(mimo-v2.5)
  → 导出(版本头 JSON)
```

## 核心脚本

| 脚本 | 用途 |
|---|---|
| `scripts/incremental_update.py` | 增量更新(幂等、断点安全、中英合并、变化日志累积) |
| `scripts/merge_cross_lang.py` | 中英同岗位一次性合并(按 name_en 归一化键) |
| `scripts/deliver_zh_split.py` | 分类(新一代/现有)+ 全中文翻译 + 分文件交付 |
| `scripts/make_evolution_testset.py` | 时间演化测试集生成 |
| `scripts/merge_cn_en.py` | 英文存量 + 中文跑出结果合并 |
| `scripts/finish_export.py` | 断点续导出(漏斗已完、只补尾部) |
| `scripts/fill_translate.py` | 漏译补翻 |

## 注意事项

- 数据在 `exchange/M2_final/`,接口实时读文件,增量更新后自动生效
- 增量输入是全量快照(含历史 + 新增);缺 id 的记录会按下架处理
- 分类口径:新一代 = evolution.stage ∈ {emerging, growth};现有 = {mature, declining};分类清单留有人工复核栏
- 技能证据为 JD 原文逐字引用;技术专有名词保留英文 canonical(canonical_name 字段)
