# TalentMind「岗位能力图谱」产品演示演讲稿 v4（仅前端画面 · 按目录顺序）

> 说明：第一人称口播；【画面】仅指**前端页面/交互**；后端、数据库、Docker、测试等一律不上屏，只用口播或字幕角标说明。数据以演示机实际为准（示例：岗位 717＝新一代 342＋现有 375、原始 JD 2984、能力更新日志 275、图谱 7852 节点/11423 关系）。

## 0. 开场（约 20 秒）
【画面：片头主视觉 → 主界面导航】

各位老师好，我演示的是 TalentMind「岗位能力动态演化与分析系统」。它聚焦新一代信息技术领域，在浏览器里完整呈现从岗位数据、能力图谱到人岗匹配的闭环。系统后端基于 Python FastAPI，MySQL/Neo4j/Redis 由 Docker 编排，前端是 Vue3；今天我用前端界面带大家走一遍六大功能模块。

## 1. 登录（约 10 秒）
【画面：登录 → 工作台，展示左侧导航】

登录后进入工作台，左侧是：采集模块管理、JD 岗位管理、能力动态更新、岗位星云图谱、简历分析、技能学习路径。前四个是"岗位侧"，后两个是"个人侧"。

## 2. 采集模块管理（约 60 秒）
【画面：采集模块管理页——运行状态、数据库统计、采集历史】

先看数据底座。这一页展示原始岗位库的运行状态：当前已积累 2984 条清洗后岗位，BOSS、智联、猎聘分布清晰；技术信号 1540 条。这里背后支撑的是多源异构采集——除中文招聘平台，还有 LinkedIn、Hacker News 和技术博客信号，并且坚持公开数据与合规边界。往下是采集历史，每一次任务跑了几轮、新增多少、跳过多少都有日志可查。针对行业里 JD "时滞、抄袭、通胀"的问题，我们在后端做了来源归一化与交叉验证：多个独立来源同时出现的岗位会被标记并提高可信度，从而区分"真需求"和"互相抄的 JD"。

【口播亮点】多源归一化＋质量分机制，把数据噪音变成可量化的工程指标。

## 3. JD 岗位管理：岗位五要素 + 增删改查（约 90 秒）
【画面：岗位列表（搜索/筛选/分页）→ 打开详情 → 编辑技能保存 → 新增岗位 → 删除/批量删除 → 导入与导出】

第二个模块是岗位目录，我把它当作一张可维护的"岗位表"来演示——查询、新增、修改、删除、导入导出都在界面上完成。

- **查（查询与详情）**：列表支持关键词、来源、类别组合检索与分页；搜索"AI 智能体"可以看到新一代岗位，目录共 717 个岗位（新一代 342、现有 375），覆盖人工智能、大数据、智能系统、物联网。点开任意岗位，查看完整五要素：岗位名称、核心职责、必备技能、加分技能、典型行业应用场景，以及来源与"新一代/现有"分类。说明一句：这些五要素由后端大模型从大量 JD 中抽取，并被限制在 285 项 canonical 技能词典内、附 JD 证据与置信度，而不是人工手敲。
- **改（编辑）**：我直接修改某项技能或职责，点击保存立即落库生效；列表刷新即可看到变化——这就是"人工可优化"。
- **增（新增）**：再演示新增：录入岗位名称与五要素，创建一条全新的岗位定义，纳入目录。
- **删（删除/批量删除）**：选中岗位可以删除或批量删除，删除前有确认提示，避免误操作。
- **批量导入/导出**：岗位数据还支持文件导入（JSON/CSV）一次建多条岗位，也可以把整个目录导出成 Excel，方便线下评审与归档。

【口播亮点】岗位知识库"既能自动生长（大模型约束抽取生成五要素），也能人工治理（完整增删改查＋批量导入导出）"。

## 4. 能力动态更新（约 55 秒）
【画面：能力动态更新 → 选 Java 开发工程师类岗位 → 时间线逐条展开 → 人工确认】

第三个模块回答"成熟岗位的能力在怎么变"。我选 Java 开发工程师这类既有岗位，时间线把能力项变化全部记录：新增、删除、修改技能，职责变化、场景变化都带**更新说明与数据源**——依据来自真实行业报告或职位 JD，可以逐条溯源。实现上，是后端对多轮岗位画像做差异比对生成变更日志，再由评审人工确认合并；当前库里已有 275 条这样的能力更新记录。

【口播亮点】把"变化"变成带来源、可人工确认的版本化数据。

## 5. 岗位星云图谱（约 65 秒）
【画面：Career Nebula 图谱 → 缩放/拖拽 → 搜索岗位 → 展开技能 → 技能反查岗位】

第四个模块是全景图谱。当前图谱含 7852 个节点、11423 条关系：岗位 719、技能 4671、行业 2462。我先缩放、拖拽感受一下星云布局；搜索一个 AI 智能体相关岗位，就能看到它依赖哪些技能节点——这是岗位到技能的 REQUIRES 关系；再点开技能，又能反查它被哪些岗位需要。这套图谱由后端 Neo4j 知识图谱支撑，导入是幂等的，可反复重建不产生脏数据；而且每个技能都来自同一套 canonical 词表，可视化与可溯源是一体的。

【口播亮点】知识图谱不是画出来的装饰，而是由受约束的结构化数据自动构建。

## 6. 简历分析（约 75 秒）
【画面：简历分析 → 拖入 PDF 演示简历 → 左右分栏画像 → 自动推荐与真实分 → 点击推荐】

第五个模块是个人侧起点。我上传一份 PDF 简历：支持 PDF/Word/TXT，背后用文档解析技术抽取文本，再按技能库做同义词归一。解析完成后，左侧是头像、姓名、岗位意向、学历、公司、工作年限和技能标签，右侧是项目经历与竞赛荣誉——都来自简历真实内容。系统随后遍历全部岗位做匹配，至少给出 3 个推荐；注意这里展示的是**真实匹配分**，这份 AI 智能体简历拿到 95 分、对应岗位第一推荐。匹配算法按技能类别加权，必备技能占 70%、加分技能占 30%，所以分数是可复算的，不是演示数字。我点击推荐卡片，还能看到该岗位的技能缺失项与已掌握项——这就是差距分析。

【口播亮点】解析层做格式适配与同义词归一，匹配层用可解释的加权模型。

## 7. 技能学习路径（约 60 秒）
【画面：学习路径 → 缺口概览 → 基础/核心/专项/加分分层 → 逐技能建议（含 JD 证据）→ 简历预览导出 PDF】

最后一个模块把差距变成行动。页面锁定刚才点击的推荐岗位，先展示已掌握与缺口技能；缺口按"基础与工具 → 核心框架与平台 → 岗位专项 → 加分拓展"形成有序的学习步骤。每条技能都有一条针对性建议：它属于什么类别、岗位 JD 里的原始证据是什么，以及"你简历里已经具备同类别技能，可以顺延补齐"的衔接提示。这些建议全部由岗位目录、JD 证据和简历画像三处真实数据生成，不虚构课程和资源。回到简历页点"预览简历"，可以一键导出 PDF，个人侧闭环完成。

【口播亮点】建议可溯源，才敢让用户照着学。

## 8. 收尾（约 30 秒）
【画面：回到岗位星云图谱定格 → 尾屏技术主线字幕】

系统配套完整的测试与部署方案：岗位 JD 与测试用例规模在 100 条以上，JD 解析、简历提取、匹配三项指标按统一测试集量化、目标≥90%，后端可一键复测；部署层面 MySQL/Neo4j/Redis 走 Docker，并提供数据库导出与新机还原。最后用一句话总结：**大模型理解语义、canonical 词表与证据链防幻觉、多源归一化交叉验证除噪音、Neo4j 承载技能级知识、可解释加权模型做人岗匹配**——每个环节都可溯源、可复测、可部署。我的演示到此结束，谢谢各位老师。
