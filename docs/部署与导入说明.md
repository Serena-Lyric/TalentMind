# TalentMind 部署与数据导入说明（2026-09-05）

> 适用对象：在全新机器上按提交物独立部署与复现数据（评委 / 演示机）。
> 数据基线（与三份 Word 文档、`exchange/`、README 一致）：岗位定义/技能 **717/717**（新一代 342 / 现有 375）、能力更新日志 **275**（含 32 条演示）、原始 JD **2984**、signal **1540**、skill_dict **285**；图谱 **7845 节点 / 11412 关系**（Job 717 / Skill 4671 / Industry 2457）。

## 0. 前置条件

- Windows 10/11 + Docker Desktop；Python 3.11+（本项目实测 3.14.5）；Node.js 与 pnpm（仅前端本地开发需要）。
- 请把提交目录放到**纯英文/ASCII 路径**（中文目录名会让 docker compose 报 `project name must not be empty`）。
- 建议让 compose 项目名固定为 `talentmind`（这样容器名是 `talentmind-mysql-1`，与本说明命令一致）：
  ```powershell
  $env:COMPOSE_PROJECT_NAME = "talentmind"
  ```
  再执行下面的 `docker compose` 命令。
- 创建后端虚拟环境并配置 `.env`（提交物不含 `.venv` / `.env`）：
  ```powershell
  cd backend
  py -3 -m venv .venv
  .\.venv\Scripts\python.exe -m pip install -r requirements.txt
  Copy-Item .env.example .env     # 默认值即连接本机 Docker 的 MySQL/Neo4j/Redis
  ```
- 前端首次运行前：`cd frontend; pnpm install`（提交物不含 `node_modules`）。

## 1. 方式 A（推荐）：完整数据库快照还原

提交目录 `部署数据/talentmind-db-full-2026-09-05.sql` 是**完整 MySQL 快照**（8 张表全量：jd_pool 2984、job_definition 717、job_skill 717、job_change_log 275、skill_dict 285、signal 1540、resume 0、talent_raw 0），与文档口径一致。

1. 启动基础设施：
   ```powershell
   docker compose up -d
   ```
2. 导入 MySQL 快照（幂等覆盖，快照内含 `CREATE DATABASE/USE talentmind`）：
   ```powershell
   Get-Content -Raw "部署数据\talentmind-db-full-2026-09-05.sql" |
     docker exec -i (docker compose ps -q mysql) mysql -uroot -ptalentmind
   ```
3. 重建图谱（Neo4j 由 `exchange/m3/graph.json` 清空重导，幂等）：
   ```powershell
   cd backend
   .\.venv\Scripts\python.exe -m app.integration.import_graph
   # 预期返回 {"nodes": 7845, "edges": 11412}
   ```
4. 启动系统：双击 `start_system.bat`（或手动起 uvicorn 18000 + vite 18080），浏览器打开 `http://127.0.0.1:18080/`。

核验：`/health` 返回 code=0；`/api/jobs` total=717；`/api/graph/data` 返回 7845 节点 / 11412 关系；`/api/evolution/timeline/<岗位id>` 可看到 275 条日志中的记录。

## 2. 方式 B（无快照时）：从 exchange 数据重建分析层与图谱

适用：只拿到源码与 `exchange/`，没有 SQL 快照。仅重建分析层与图谱；**原始层（jd_pool/signal）不会被此方式重建**，如需原始层请用方式 A。

> 前提：导入器已支持 `exchange/m2` 标准交接布局（`job_definition.json` / `job_skill.json` / `job_change_log.json`），见 `backend/app/integration/m2_package.py`。
>
> 2026-10-22 起，下列命令还必须提供绑定**实际目标身份**和具体操作的独立、限时授权文件；环境变量与 pytest 标记不能授权写入。

授权文件使用严格 JSON。`target` 与 `target_fingerprint` 必须是待写实例的实测值，不能把示例占位符直接用于正式库。`connection_port` 是 SQLAlchemy 实际连接的宿主映射端口，`server_port` 是 MySQL 服务端 `@@port`；两者必须分别记录并同时参与指纹：

```json
{
  "schema_version": 1,
  "operation": "mysql.import_all",
  "target": {
    "kind": "mysql",
    "host": "127.0.0.1",
    "connection_port": 23307,
    "server_port": 3306,
    "database": "talentmind_isolated",
    "hostname": "<实测@@hostname>",
    "server_uuid": "<实测@@server_uuid>",
    "version": "<实测VERSION()>"
  },
  "target_fingerprint": "sha256:<对target按key排序、紧凑JSON后的SHA-256>",
  "authorized_by": "<人工授权人>",
  "purpose": "<本次限定用途>",
  "expires_at": "2030-01-01T00:00:00+08:00"
}
```

将文件路径加入 `TALENTMIND_DESTRUCTIVE_AUTHORIZATION_FILE`。授权文件不提交 Git，授权人应核对隔离实例实际身份、操作和有效期。

```powershell
cd backend
# 重建 MySQL 分析层（全量重建 717/717/275；会把现有分析层清空重写）
.\.venv\Scripts\python.exe -c "import json; from app.integration.import_exchange import import_all; print(json.dumps(import_all(r'..\exchange\m2'), ensure_ascii=False))"
# 重建图谱（Neo4j 清空重导 7845/11412）
.\.venv\Scripts\python.exe -m app.integration.import_graph
```

## 3. 与测试的关系（评委 / 新机器视角）

- 提交物 `backend/tests/` 含全部测试源码，测试分两类：
  - **单元测试（不写库、不依赖原回包）**：`cd backend; .\.venv\Scripts\python.exe -m pytest -m "not integration" -q` —— 提交物上可直接运行通过。
  - **少数以"原 M2 回包"为输入的用例**（回包一致性、默认导入幂等）：其输入是开发仓库才有的 `input/岗位数据-新一代与现有/`（原 M2 回包，**不随提交物提供**）。在提交物环境运行时会**自动跳过（skipped）而非报错**，不影响系统运行与其余测试。
- 系统运行与演示数据不依赖回包：用**方式 A**（SQL 快照）或**方式 B**（exchange/m2）即可得到 717/717/275 与图谱 7845/11412。
- `backend/tests/conftest.py` 默认跳过全部 `integration` 用例。只有显式设置 `TALENTMIND_ALLOW_INTEGRATION=1` 且人工确认隔离目标后才允许进入；进入测试仍不能绕过各写入口自己的目标身份与授权文件校验。
- 开发仓库不要裸跑指向正式库的全量集成测试。验证非集成回归使用 `-m "not integration"`；任何隔离写入都按 `backend/app/integration/README.md` 的授权要求单独执行。

## 4. 常见问题

| 现象 | 处理 |
|---|---|
| `未找到 backend\.venv` | 按第 0 节创建 venv 并安装依赖 |
| `project name must not be empty` | 目录名含中文；放英文路径或设置 `COMPOSE_PROJECT_NAME` |
| 前端 18080 打不开 | `cd frontend; pnpm install` 后重新 `start_system.bat` |
| 页面有数据但图谱空 | 未执行方式 A 第 3 步 / 方式 B 的 `import_graph` |
