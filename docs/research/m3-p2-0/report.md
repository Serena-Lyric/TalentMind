## 1. 推荐与证据边界

推荐采用**保留事实来源的多层模型 + 可重建派生图 + 独立呈现层**。先把岗位定义、标准岗位发布、要求陈述、技能身份、行业/场景和算法结果分开；保持正式 V1 快照及消费者，另建版本化实验产物。候选模型详见 [契约草案](contract-draft.md)，团队可引用范围见 [一页能力清单](capabilities.md)。

算法上保留完整 Jaccard 为可解释基线，IDF 加权 Jaccard 作为区分度对照；在同一图、同一目标函数上优先继续验证 Leiden，保留 Louvain 回退。建议下阶段用 **Jaccard 0.10、Leiden、resolution=1、seed=7** 作结构探索起点，再按局部视图调整边预算；这是研究者选择，尚未成为正式阈值或产品方案。它覆盖的岗位更多，且不受单次 IDF 估计过度稀疏的影响，但仍有 187 个孤点，不能强行放进职业群落。

不推荐沿用固定 0.35 阈值生成全景骨干：修复投影只有 36 条岗位边、668 个岗位孤点。也不推荐直接把 7,864 节点的离线投影导入正式库：新 ID、nullable 冲突、来源数组和顶层 audit 还没有完整消费者支持，快照也缺失原始明细。

所有相似性和社区指标均为**现有历史交接快照的结构实验**；没有人工职业相似度真值，不能宣称准确率提升、真实市场规律、社区等于职业类别、路径等于成长或学习顺序。用户本轮说明 19 个标准岗位已经完成产品审核；仓内可机读的正式发布目录仍为 **0**。审核完成不等于版本发布，本研究不据此创建 StandardJob 节点，也不伪造审核记录或反向否认用户告知的审核状态。

上列 `6565…` 是本机 **CRLF 工作副本原字节**摘要；Git 保存的 LF blob SHA 为 `e8e3fe6aab4ffd359a16c8c62ee8edd4684504266fafe1534d36599cd7af742f`。本轮两者均未修改，不能因 Git 换行转换把旧证据重写成另一个哈希。输出额外保存 `normalized_lf_source_hashes` 与 `portable_lf_sha256`，仅对这些文本输入 CRLF→LF 后提供跨检出比较；原字节摘要仍独立保留。portable 不承诺不同 Python/原生库版本或平台构建之间浮点结果必然逐位一致。LF/CRLF 合成入口对照已实际验证：原字节摘要变化、portable 相同。

复现（仓库根目录，PowerShell；研究环境须先装本项目后端依赖，研究依赖不加入生产 requirements）：

```powershell

& data/local/m3-p2-0-env/Scripts/python.exe -m pip install -r backend/requirements.txt

```

依赖安装需要网络；**实验与验证命令阻断网络**，新输出目录必须不存在。`verify_offline.py` 在临时目录安装父子 Python 进程的 socket 审计钩子，只放行标准库 socketpair 自身内部通信，服务配置替换为合成不可用端点；结束报告连接尝试与临时目录清理。它是防误连核查，不是对任意本机原生代码的安全沙箱。实验模块不导入 DB、API、LLM 或采集模块。

不带包装器的纯入口：在 `backend` 执行 `python -m app.graph.research --snapshot ../exchange/m3/graph.json --output <新目录>`。没有默认输入或默认正式输出；拒绝把结果写到 exchange、input、output、frontend、backend/app 或 .git 中。输入和源码在运行前后回读校验；旧文件不覆盖。原始来源索引的完整映射可通过现有 `python -m app.graph.diagnose_snapshot ../exchange/m3/graph.json` 只读重建；结果保存其条数和摘要，避免重复提交 11,419 行映射。

结果 JSON 分两部分：`deterministic` 为可复算正文，`runtime` 记录机器/解释器、计时和内存。正文摘要不含耗时；源字节或依赖版本变化会改变摘要，不能为了相同数字修改旧证据。社区运行引用 `partition_sha256`，`partitions[hash]` 再引用 `community_members[group_hash]`，完整成员均可展开；组摘要和分区摘要用排序键、UTF-8、紧凑 JSON 的 SHA-256。

### 3.1 为什么 7,845/11,412 与修复投影不同

| 数量 | 正式历史快照 | 同身份全对复算 | #21 身份修复后的快照投影 |
|---|---:|---:|---:|
| Job | 717 | 717 | 717 |
| Skill | 4,671 | 不改变原节点 | 4,690 |
| Industry | 2,457 | 不改变原节点 | 2,457 |
| REQUIRES | 8,866 | 不改变原边 | 8,880 |
| APPLIES_TO | 2,539 | 不改变原边 | 2,539 |
| RELATED_TO（0.35） | 7 | 41 | 36 |
| 总节点/边 | 7,845 / 11,412 | 仅重算岗位相似关系 | 7,864 / 11,455 |

历史完整图构建器的倒排枚举只查看每个岗位后面的 10 个同技能岗位（基线的父提交 `425aef5^` 中 `names[index+1:index+11]`）；所以同旧身份全对复算有 41 对，正式文件漏 34 对。它与旧 builder 的全对 0.25 算法是不同入口，不能混称“旧 builder 截断”。

旧 `_slug` 会把 C/C++/C# 合并到 `skill:c`，引入虚假共享；修复身份后重算变为 36 对，**41→36 是身份语义改变，7→41 是候选枚举缺失修复**。净新增 19 个技能节点、14 条要求边、29 条岗位相似边，共增加 19 节点/43 边，不是新增采集或真实岗位增长。

诊断发现 16 组旧技能键一对多，例如 `c`、`c-语言`、`linux-shell`、`kubernetes-k8s`；其中部分空白/格式变体未来可能是同义词，当前没有足够证据自动合并。原岗位技能数组支持重新区分部分身份，已有 Industry 只保留最终名称，无法从图文件恢复被覆盖场景名、原始明细、JD 引文或不在数组中的技能。行业节点数没变不证明行业无碰撞。

### 3.2 要求冲突与来源索引

修复投影有 **9 个岗位、11 条历史要求冲突边**。同岗位同身份技能在历史 required/bonus 中出现，必须保留 `is_required=null`、`weight=null`、`status_conflict=true`、`needs_review=true` 及全部来源；它不自动等于 M2 新版的 uncertain，也不代表已完成 JD 语义复核。

投影保存 `source_names/source_states/source_fields/source_row_indices/source_indices`；数组字段的行索引为 -1，元素索引按**原数组位置**保留，空白过滤不重新编号。此次 8,891 次历史技能出现均回查到原岗位数组。研究重建的临时数字 id 是内存顺序，不是 MySQL 主键；有原始明细时两级索引才可定位到传入的 skill_rows/skills 项。本次 skill_rows 为空，不能声称恢复了明细或获得新的 JD 原文验证。

## 4. 隔离算法设计与结果

### 4.1 相似关系

以修复投影的岗位技能**存在集合**为输入；不使用历史 1.0/0.6 作为新版要求强弱，不解释为满足率。包括历史冲突边只表示“数组里曾出现该技能”；另跑剔除冲突边对照。共 717 岗位、256,686 全岗位对，倒排得到 46,682 对共享技能候选，并用独立穷举集合交集 oracle 核查完整性。

- 基线：`J(A,B)=|A∩B|/|A∪B|`。
- 候选：`idf(s)=1+ln((N+1)/(df(s)+1))`；`J_idf=Σ共同技能idf/Σ并集技能idf`。df 是当前快照中含该技能的岗位定义数，不是 JD 数或真实职位需求。
- 各阈值直接比较未舍入值；同阈值并不代表两种指标有相同业务含义。无向、不含自环；没有人为限制“后续 10 个岗位”。

| 阈值 | Jaccard 边 / 孤点 / 最大分量 | IDF Jaccard 边 / 孤点 / 最大分量 |
|---:|---:|---:|
| 0.10 | 4,104 / 187 / 508 | 1,251 / 289 / 385 |
| 0.20 | 413 / 513 / 138 | 104 / 617 / 26 |
| 0.25 | 156 / 605 / 42 | 56 / 654 / 9 |
| 0.35 | 36 / 668 / 6 | 15 / 691 / 3 |
| 0.50 | 10 / 703 / 3 | 4 / 709 / 2 |

剔除冲突边后 Jaccard 0.10 为 4,074 条（少 30），0.20 为 412（少 1）；0.25/0.35/0.50 不变。IDF 每次重新估计 df，0.20 的 104→105 说明重新计算分母和 IDF 可能让其他边越过阈值，不能把该对照误作固定打分下的简单删边。完整数量与旧身份对照均见 JSON 的 `graphs`。

### 4.2 社区与质量

两种方法在**同一岗位投影图**上比较，加权广义模块度、resolution 0.5/1/2、seed 7/19/42；Leiden 使用 RBConfigurationVertexPartition、迭代到不再改善，Louvain 用 NetworkX 默认模块度改善终止条件。阈值 5 档、指标 2 类，共 180 组配置，各重复一次同种子测试。没有目标群落数、没有八大类标签输入。

Leiden 的细化阶段针对 Louvain 可能产生不连通社区的问题；本次仍逐社区实际核查连通性，而不是把论文保证当成本数据已验证。参见 [Leiden 原始论文](https://www.nature.com/articles/s41598-019-41695-z)、[NetworkX Louvain 参数说明](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.community.louvain.louvain_communities.html) 与 [leidenalg 官方参考](https://leidenalg.readthedocs.io/en/stable/reference.html)。

代表配置（resolution=1、seed=7；社区数只列规模 >1，孤点不计作职业群落）：

| 图 | 算法 | 非单点社区 | 最大三组 | 模块度 Q | 社区内权重比例 |
|---|---|---:|---|---:|---:|
| Jaccard 0.10 | Louvain | 16 | 165/74/72 | 0.544820 | 0.734459 |
| Jaccard 0.10 | Leiden | 16 | 175/82/70 | 0.545525 | 0.738099 |
| IDF 0.10 | Louvain | 27 | 64/55/54 | 0.688315 | 0.825561 |
| IDF 0.10 | Leiden | 27 | 65/56/55 | 0.691512 | 0.825682 |
| Jaccard 0.35 | 两者相同 | 19 | 6/6/3 | 0.906283 | 约 1 |

全部运行的同种子重复结果一致，观察到的不连通社区为 0；这不证明 Louvain 一般能保证连通，也不证明输出语义正确。每次运行保存全部规模、完整成员、分区摘要、模块度、内部权重比例和 conductance 中位数；包含孤点的 ARI 容易显得稳定，因此同时保存仅有边岗位的 ARI。

0.10、resolution=1 时，三对种子 ARI：Jaccard 的 Louvain 约 0.886–0.951，Leiden 约 0.943–0.968；IDF 的 Louvain 约 0.813–0.869，Leiden 约 0.944–0.950（此处为全岗位 ARI，活跃节点结果见 JSON）。Leiden 在这份数据上较稳定、Q 略高，足以支持下一轮优先试验，不能据此宣称通用最优。

resolution 同样敏感：Jaccard 0.10、seed=7 下两方法的非单点社区从 0.5 时 14 组、1 时 16 组到 2 时 25 组，最大组大小也变化。不同 resolution 的 Q 目标函数不同，不能按 Q 大小选胜者；不同阈值/打分图的 Q 也不应直接竞赛。

**失败解释：** Jaccard 0.35 的 Q≈0.906 高于 0.10，但 668 个孤点使绝大多数岗位没有进入有意义的关系图；conductance 中位数常为 0，是大量断开分量没有割边的结果，不能解释成职业分类质量极佳。模块度还存在分辨率限制，较小结构可能被合并，见 [Fortunato 与 Barthélemy 原论文](https://arxiv.org/abs/physics/0607100)。不预设群落数量，不将“16 组”变成正式职业类别。

### 4.4 路径验证

路径仅使用真实快照可重建的 `REQUIRES` / `APPLIES_TO` 关联，按无向邻接做有跳数上限的 BFS；`traversed_reverse` 明示反向浏览，并不反转业务含义。不允许 RELATED_TO 代替事实关联，不生成 prerequisite/learn_before/next_career。

共享技能解释强制为 Job→Skill←Job，每跳附完整关联属性与投影边索引。一般局部路径也允许 Job→Scenario←Job，不能把同场景说成同技能。示例最高相似对的通用 BFS 优先返回共享场景，两类说明必须在界面中明确区分。

另有机械选取的无共享技能岗位对 `job:j-008bb9a49f5eb12b` 与 `job:j-00d5430c67bed4b2`：两跳范围无路径，四跳范围可通过另一个岗位和两个技能连接。四跳连通只说明图中关联存在，不证明从一个岗位到另一个岗位的可行学习路线。测试同时覆盖缺失端点、跳数不足和仅有派生边的诚实无路径结果。

### 4.5 实际运行开销

Windows 11、Python 3.14.5、NetworkX 3.6.1、igraph 1.0.0、leidenalg 0.11.0；完整矩阵含 180 次首次运行及 180 次同种子复跑。交付版本两次独立进程总耗时约 **55.69/55.05 秒**，投影/诊断及全对 oracle 约 7.82 秒；首次社区调用耗时中位数 Louvain 约 0.173 秒、Leiden 约 0.055 秒，最大约 0.334/0.280 秒。这是本机带 tracemalloc 的观测，不能推广为两种库的一般速度比。逐配置计时及独立复跑记录见 JSON 和阶段报告。

tracemalloc 的 Python 分配峰值约 **144 MB**，**不含 igraph/Leiden 原生分配**，不是整个进程 RSS；不能据此比较 native 与纯 Python 内存效率。没有启动服务、执行数据库查询或测量前端帧率。空图/无边图已实际运行，模块度返回 null；缺输入或缺依赖明确失败、不发布伪结果；本轮并未实现缺依赖自动回退。

## 5. 空间与交互候选

这部分为**已提出、未视觉验证的工程方案**，不修改 #30/#31，不实现新坐标或渲染器。

结构实测：4,690 技能中 3,772 为度 1 叶子（约 80.4%），918 共享；行业/场景节点 2,457 中 2,404 为度 1。最大岗位技能集 88 项，一跳关联最多需要 97 个节点（含岗位本身及技能/场景）。python 关联 222 岗位、sql 104、java 74；大枢纽不能简单贴到一个岗位边上。

| 层 | 候选空间安排 | 可核查信息/边界 |
|---|---|---|
| 社区骨干 | 在岗位投影上计算社区；社区之间按跨组真实共享技能/相似边汇总权重，连通分量分开布置 | 显示算法/版本/阈值；孤点有独立区域；不以八类硬塞或虚构连线 |
| 社区内岗位 | 固定种子、稳定排序和缓存坐标；局部力导向或谱初始化，保留用户视角 | 需要后续比边长、重叠、标签遮挡、跨版本位移；本轮未测视觉优劣 |
| 共享技能 | 参考多个岗位/社区的加权重心；保留全部所属，跨社区高频技能放在连接区 | 一个语义实体一个真 ID；多处显示代理必须标记 proxy_of，统计去重；不重复计数 |
| 度 1 叶子 | 折叠为数量提示，放大/主动展开时稳定扇出；场景长文本进详情 | 全量边仍可查询；返回可见/总量/截断原因，不用前 900 条数组顺序决定业务重要性 |
| 局部关联 | 单击原位高亮；主动查看全部关联时分层/分页展开，支持返回原视角 | 真实边、派生相似边、社区归属分别图例；无路径显示空态 |
| 装饰银河 | 独立粒子实例和坐标参数，不参与节点/边/社区/查询/命中计数 | 装饰密度不能伪装知识密度；与 #30/#31 的后续视觉结合需另行确认 |

候选骨干可以用最大生成森林减少远景线，但只能作为**显示子集**，不能把被隐藏边从事实图删除；孤立分量不补桥。M5 应消费 M3 同版本结果，避免前端自行再聚类造成两套“社区真相”。

## 6. 架构选择比较

| 方案 | 收益 | 代价与适用结论 |
|---|---|---|
| A：原 Neo4j 三类节点上继续补属性/布局 | 成本低、旧消费者可继续用 | 要求陈述/聚合/派生边混杂；旧 ID 无法表达碰撞；适合作正式 V1 回退，不足以承载新语义 |
| B：事实来源层、版本化投影、派生计算、呈现分层（推荐） | 原始证据与冲突可追踪，派生可重建；接口可分步双读；不要求当前一次迁库 | 需定义版本、来源解析与适配；前期维护两个显式版本，但可小步验证 |
| C：立即换本体、全量迁 Neo4j/GDS 或另换图数据库 | 后续图计算集中 | 当前源证据缺失、正式标准目录为空、消费者未适配；高风险且未经授权，不推荐本轮实施 |

无需因为 Leiden 引入生产 Neo4j GDS；本轮 717 岗位的内存实验已可运行。是否把研究依赖带入正式部署，须根据后续需求和维护成本决定。

## 7. 实施阶段、测试与回退

1. **P2-0（本轮）**：只读实验、报告、契约草案与 Draft PR；独立审查。所有生产路径不改。
2. **P2-1（待授权）**：与 M2/M5 确认发布目录引用、断言/证据契约、旧 ID 解析；建立版本化只读 v2 文件及测试适配器，不写正式库。
3. **P2-2（待授权）**：在隔离输出做同一批输入双投影，验证五态/组合/冲突和旧客户端退化；M5 局部算法展示试验与 #30/#31 分别评审。
4. **P2-3（另获生产许可）**：审查备份/新旧计数与一对多映射后，设计隔离库迁移演练、运行时兼容与渐进切换；不得直接解除 rebuild 禁用。

最低门禁：输入和代码摘要一致；重复运行同配置稳定；完整候选 oracle；每个来源索引可回查；每条解释路径实际边存在；nullable 不强化；any_of 不拆必备；旧 ID 多解返回待选择；catalog_version 与已发布条目相符；API/导入/前端保持类型与版本；缺算法依赖、计算失败和无路径可诚实回退。

后续视觉门禁另测真实演示机的 FPS、标签/遮挡、交互响应、可达关联与视角保持；本轮 Python 耗时不能当作前端帧率证据。未来社区评测需人工审核的职责/职业边界样本，不能把 M2 合成测试或同算法输出充当真值。

回退：本轮只移除新增研究入口与文档即可，正式图/API/前端未切换；生成目录保留哈希再由用户按需删除。未来双版本用显式配置回到 V1 ID 和原文件/旧渲染器，保留 v2 证据与新旧映射；回退客户端不删除新事实、不回写旧 bool、不因回退丢失审核版本。
