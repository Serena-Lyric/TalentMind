- 本轮范围为 M2 及直接相关的 M1 输入原则；不扩写 M3–M5 尚未讨论的功能、算法或指标。未决项经用户确认后分批更新本文与决策索引，不要求每项决策单独提交。

## 2. M1 输入与原始证据原则

以下沿用已确认规则，具体实现边界见 [M1 说明](../backend/app/collect/README.md) 与 [有效 JD 陷阱记录](superpowers/traps/2026-10-15-cn-jd-validity.md)。

- **来源真实**：`source` 只表示实际来源平台，数据集标识等来源细节另行记录，质量与交叉验证不能伪装成来源。岗位 JD 与技术热度信号分别管理，信号不能当作招聘事实（D17、D38、D39）。已有数据集、公开 API 和用户人工登录后可见页面只是已记录的获取渠道，不代表自动授权新一轮采集；不绕过登录、验证码或反爬（D40、D45 及后续受控采集规则）。
- **有效 JD**：BOSS、智联、猎聘不因字数短、缺公司/薪资/地点而拒绝 JD；简短职责、技能要求或技能标签可以有效。仅有公司介绍、薪资地点、福利、招聘宣传或占位且没有有效岗位内容的材料不应成为分析事实。当前规则对未知剩余内容保守放行，不能声称完整识别了招聘意图；其他来源的实现边界须单独核查。
- **原始证据保留**：有效性判定使用的副本不改写原始入库文本；M2 判断须能追溯到来源 JD 和原文，不能用清洗、翻译、标准化名称或聚合摘要替代原始证据。既有清洗与字段存储不等于完整网页原件已保存，证据存储细节仍待设计。
- **时间与版本可追溯**：保留来源、采集时间及证据的对应关系，区分原始数据、分析结果与交接快照。沿用既有交接版本与变更审计原则（D11、D16），重分析应能分辨使用的输入及分析版本；具体版本字段、保存方式和重算策略待决策。不因重新分析覆写原始事实，也不把合成回溯版本当作真实历史观测。

## 3. M2 已确认产品规则

以下编号对应本轮确认的 14 项要求，均为**已确认的产品目标**，不表示已全部实现。

| 编号 | 已确认规则 |
|---|---|
| M2-01 | 对单条 JD 独立提取事实，再进行岗位聚合。单条 JD 是事实判断的来源。 |
| M2-02 | 技能要求区分为：**明确要求、加分优先、仅提及、明确不要求、待判断**。不能以简单的必备/非必备二分替代这些语义。 |
| M2-03 | 待判断是分析不确定状态；未提及不等于明确不要求，不能把证据缺失转换成否定事实。 |
| M2-04 | 已知技能规范化；未知技能保留原文证据进入候选池。高可信候选在严格验证后可自动准入，争议候选等待人工确认。严格验证规则与阈值尚未确定，不能据此直接开放无门槛准入。 |
| M2-05 | 技术技能、专业能力、工程实践与软技能分开管理；行业场景、任职条件另行分类，不能全部混入技能集合。 |
| M2-06 | 软技能可用于统计招聘需求；简历未提及某项软技能，不能据此推断求职者缺乏该能力。此处只约束事实解释，不选定匹配算法。 |
| M2-07 | 岗位采用分层体系：**职业大类、标准岗位、技术方向、岗位级别**。 |
| M2-08 | 技术方向可以有多个；岗位级别支持总体与分层统计。证据不足时允许未明确，不能强行赋值。 |
| M2-09 | 混合岗位用主岗位与辅助岗位关联表达；辅助关联不能重复计入招聘总数。 |
| M2-10 | 全栈等成熟复合职业可作为独立标准岗位；一份材料招聘多个职位，不能直接当作一个混合岗位。 |
| M2-11 | 岗位标题与实际职责综合判断，实际职责有较高解释权；冲突无法解决时保留不确定状态，不凭标题或单一模型强行裁决。 |
| M2-12 | 技能识别与分类优先使用规则；轻量模型、生成式模型按需处理歧义。最终模型尚未指定，不能沿用旧配置作为新的产品选型结论。 |
| M2-13 | 单条 JD 的岗位分类与技能判断保留原始证据；确定性证据校验由程序完成，不能仅依赖模型自述“已验证”。校验算法与验收标准待定。 |
| M2-14 | 聚合不能改变单条 JD 事实；某条 JD 将某技能列为必备，不代表全部同类岗位都必备。聚合表达须遵守这一边界，具体统计口径待决策。 |

### 3.1 后续确认：统计、职位关联与增量边界（2026-10-15）

以下十项是在 M2-01～14 基础上的补充与细化，属于**已确认设计，不代表已经实现**。M2-14 及历史讨论中“具体统计口径待决策”的范围，由下列已确认原则收窄；剩余执行细节仍见第 5 节。

| 编号 | 已确认规则 |
|---|---|
| M2-15 | 岗位需求采用多维度统计，综合分数仅是可选派生指标；不得将主观评分冒充招聘需求比例。 |
| M2-16 | 独立职位采用分级去重：确认重复、疑似重复、确认不同，并允许未判定；不直接修改或删除 M1 原始记录。 |
| M2-17 | 时间统计同时保留首次观察、时间窗口内观察和有证据的同职位变化追踪；分阶段实现，不虚构历史版本。 |
| M2-18 | 原始观察变化与可比性分析并存；样本结构不可比时不得声称市场需求可靠增长。 |
| M2-19 | 统计展示根据可检查的样本数量、分析覆盖率、去重质量和来源结构自动降级；具体阈值待定。 |
| M2-20 | 单条 JD 保留各自技能证据；同一独立职位的不同来源出现明确要求状态冲突时，在职位层单独标记，不能擅自选择更强要求。 |
| M2-21 | 统计默认保留全部符合条件且完成相应分析的独立职位作为分母；冲突与不确定分别计数，确认要求率不等于全部真实需求率。证据条件满足时可额外展示不确定范围，不是统计置信区间。 |
| M2-22 | 长期保存单条 JD 分析结果与岗位聚合结果；职位关联与完整历史版本体系后续分阶段完善。 |
| M2-23 | 采用单条 JD 增量分析、聚合结果可重建。新增或变化的数据按需重分析；聚合规则变化尽可能复用单条事实。 |
| M2-24 | 采用分阶段失效机制：第一阶段使用输入指纹与分析版本；无法可靠判断影响范围时保守重分析。正确性、可追溯性与一致性优先于性能优化。 |

## 4. 与历史方案、现有实现的关系

| 历史入口 | 本次替代或保留范围 |
|---|---|
| D8、D11 及旧团队设计的必备/加分字段 | 作为历史与现有契约记录保留；新的单条事实语义由 M2-01～03、M2-13～14 约束，不能从现有字段推断五类状态已实现。 |
| D31 的 stage3 候选限定 `skill_dict` | 由 M2-04 扩展产品边界：已知技能仍规范化，未知技能可保留证据进入候选池并经严格验证准入。保留反幻觉目标；不再把“词典外永远不可接纳”当作当前产品约束。 |
| 旧 M2 三模型管道与模型配置 | M2-12 是当前处理原则；具体模型、调用顺序、参数和阈值仍待定。旧方案与配置只能说明历史选择或当前代码行为。 |
| 旧相似去重、必备技能并集、权重和演化 diff | M2-15～24 约束新的统计、独立职位、时间与失效语义；旧 SimHash 跳过、权重、岗位级 diff 或文件覆盖不能作为这些能力已经实现的证明。现有契约保留，适配方案另行评估。 |
| D14、D17、D23、D36、D37、D55/D56 | 冻结契约、来源语义、目录、私有数据和测试安全约束继续有效；D56 对 D55 的既有覆盖保留。本次技能“待判断”不等于重新加入岗位定义的审核 `status`。历史导入授权不自动授权再次导入或清理。 |

本轮只读核对：现有 `stage3_extract.py` 仍输出 `is_required`、置信度和逐字证据，`merge.py` 负责合并同类岗位，DDL 仍有必备/加分字段。局部已有证据提取能力不能证明五类状态、候选自动准入、岗位四层体系与新统计规则已实现。详细差距与验收须在后续 M2 开发阶段检查源码并验证；本次未运行应用测试或模型管道。
