## 2. M1 输入与原始证据原则

以下沿用已确认规则，具体实现边界见 [M1 说明](../backend/app/collect/README.md) 与 [有效 JD 陷阱记录](superpowers/traps/2026-10-15-cn-jd-validity.md)。

- **来源真实**：`source` 只表示实际来源平台，数据集标识等来源细节另行记录，质量与交叉验证不能伪装成来源。岗位 JD 与技术热度信号分别管理，信号不能当作招聘事实（D17、D38、D39）。已有数据集、公开 API 和用户人工登录后可见页面只是已记录的获取渠道，不代表自动授权新一轮采集；不绕过登录、验证码或反爬（D40、D45 及后续受控采集规则）。
- **有效 JD**：BOSS、智联、猎聘不因字数短、缺公司/薪资/地点而拒绝 JD；简短职责、技能要求或技能标签可以有效。仅有公司介绍、薪资地点、福利、招聘宣传或占位且没有有效岗位内容的材料不应成为分析事实。当前规则对未知剩余内容保守放行，不能声称完整识别了招聘意图；其他来源的实现边界须单独核查。
- **原始证据保留**：有效性判定使用的副本不改写原始入库文本；M2 判断须能追溯到来源 JD 和原文，不能用清洗、翻译、标准化名称或聚合摘要替代原始证据。既有清洗与字段存储不等于完整网页原件已保存，证据存储细节仍待设计。
- **时间与版本可追溯**：保留来源、采集时间及证据的对应关系，区分原始数据、分析结果与交接快照。沿用既有交接版本与变更审计原则（D11、D16），重分析应能分辨使用的输入及分析版本；具体版本字段、保存方式和重算策略待决策。不因重新分析覆写原始事实，也不把合成回溯版本当作真实历史观测。

| M2-11 | 岗位标题与实际职责综合判断，实际职责有较高解释权；冲突无法解决时保留不确定状态，不凭标题或单一模型强行裁决。 |

| M2-13 | 单条 JD 的岗位分类与技能判断保留原始证据；确定性证据校验由程序完成，不能仅依赖模型自述“已验证”。校验算法与验收标准待定。 |
| M2-14 | 聚合不能改变单条 JD 事实；某条 JD 将某技能列为必备，不代表全部同类岗位都必备。聚合表达须遵守这一边界，具体统计口径待决策。 |

### 3.4 阶段 B2：技能要求语义（2026-10-16）

以下五项为用户本轮明确确认的产品原则，追加编号 M2-32～36。原则已确认；第一轮只实现离线确定性语法子集，复杂语境、词典治理与正式评测并未因此完成。工程实现状态及限制见 [M2 README](../backend/app/job_analysis/README.md)。

| 编号 | 已确认规则 |
|---|---|
| M2-32（B2-01） | 正式五态为 required（明确要求）、preferred（加分优先）、mentioned（仅提及）、not_required（明确不要求）、uncertain（待判断），均须有本条 JD 原文证据。未提及不等于不要求，识别/执行失败不伪装为 uncertain；历史 legacy_required/legacy_bonus 不能自动升级为已验证语义。 |
| M2-33（B2-02） | 支持明确的全部满足与任选其一，组合要求状态与成员的独立要求分开。Java 或 Python 至少掌握一种是必备组合，不能据此认定二者各自必备；复杂嵌套、模糊范围及不可靠解析保留原文与原因，不强建逻辑树。 |
| M2-34（B2-03） | 同一 JD 保存原始要求陈述及上下文，先比较程度、条件和要求对象，合理差异不直接判冲突。真实冲突且无明确修订依据时，有效状态为 uncertain，独立保存冲突标记与全部证据；不选最强或最后一句。 |
| M2-35（B2-04） | 要求状态与熟练程度分开；基础了解、熟悉、熟练掌握、精通等程度绑定具体陈述并保留原文，允许未明确。不同程度要求可共存；“不要求精通 Python，但需了解 Python 基础”不能折叠为完全不要求或虚假冲突。年限不换算为程度，不开发能力评分。 |
| M2-36（B2-05） | 综合章节、句子与相邻上下文保守判断。任职要求的明确能力描述可支持 required，加分章节支持 preferred；技术栈列表、工作使用场景不能仅凭出现升为 required。区分否定范围、条件作用对象与主体；复杂上下文不可靠时保留不确定性，不制造确定事实。 |

B2 第一轮只允许免费离线、单 JD 分析与持久化/恢复验证，规则和结构变化须反映在版本中；原文位置可核验不等于语义真值。未解析片段使覆盖不完整；无技能识别结果与执行失败分别记录，不输出市场需求率、独立职位统计或匹配评分。不接入真实模型、外部 LLM、生产数据库或旧正式管道。可只读复用已有别名；该限制描述第一轮范围；第二轮已按 §3.5 授权名称/分类/候选治理和离线评测基础，正式词典写入与自动准入仍关闭，B3/B4 亦未启动。

## 7. M3/M5 创新方向、可视工作台与第一批页面决策（2026-10-17）

> 以下三层竞赛创新框架已经用户确认；**其中第一创新点另经指导教师确认**，第二、第三创新点及其具体算法尚不能写成教师逐项验收或已经实现。以下第一批图谱视觉/交互目标同样属于已确认设计，不等于实现/效果验收。详细工程与设计限制见 [Career Nebula 视觉设计基线](superpowers/specs/2026-10-17-career-nebula-visual-design.md)。

### 7.1 三大创新点（作为竞赛材料与 README 开头的主线）

| 创新点 | 已确认的定位 | 实现/验证边界 |
|---|---|---|
| **创新一：可追溯的岗位能力动态演化** | **可信性 + 时效性**，招聘来源、原文证据、观察时间/版本与动态分析，形成持续更新且可追溯的能力演化基础。此项已与指导教师确认、必保留。 | M1/M2 已有阶段性事实/证据/版本基础，但正式可靠趋势、完整时间可比性和跨模块闭环不能笼统称已实现或已验证。 |
| **创新二：多维异构岗位能力知识网络与关系计算** | M3 组织岗位、技能、行业/场景和经确认的语义关系，提供可计算、可解释的知识关联；M2 判断事实，M3 组织、计算，不重复评判 JD 要求。 | 知识本体、算法集合、M2 新旧 ID/语义兼容及图谱迁移尚未全部确认；旧 Neo4j 图谱不等于新版多层语义完成。 |
| **创新三：图分析驱动的交互式智能可视分析** | 融合图计算实用成果、智能能力路径/关系解释和高视觉表现的 Career Nebula 工作台；图计算与前端展示互相促进，作为创新体系的升华。 | 视觉技术、具体算法与三种模式最终产品形态仍待原型；“选用 Three.js/GDS”等工具本身不能替代创新机制及评测。 |

总体表达：**可信的数据基础 → 可计算的知识关系 → 可交互的智能分析**。竞赛创新性权重高（用户描述创新性 25 分、实际效益 10 分），优先展示技术差异和可验证的分析能力，不以炫目特效冒充技术创新。三个方向允许成员准备材料，但 README 必须明确实现阶段，任何尚未完成的能力不能写成现有成果。

### 7.2 分工与演进方向

- **M1/M2**：提供有证据来源的输入、稳定身份、可追溯时间/版本、技能/岗位语义与可信状态；不因可视需要修改单条事实。
- **M3**：从真实事实形成可重建知识网络、关联路径/相似性与社区等图计算结果；算法猜测、图谱社区与事实之间保留明确区分。
- **M5**：以可交互视觉表达分析结果，避免与 M3/M2 各自重算一套不同的“需求率”或事实。
- “全景知识宇宙 / 探索能力路径 / 演化时间比较”目前为**认可的工作台研究方向**，可以相互促进；各模式 UI 与算法、是否作为三个独立视图、开发期次仍未最终裁决。深度重构方案 A/B/C **仍未选择**。
- 数据建模的需求：可引用证据/时间/语义条件、可区分职业/标准岗位/技术方向/级别、四类技能与非技能条件，但具体 M3 模型/接口/迁移设计尚待研究。

### 7.3 Career Nebula 界面与交互已确认事项

1. 整体视觉方向：**大型、连续、多色的知识银河**；第一轮重点参考《诗云 · Poetry Cloud》的程序化粒子、空间纵深/密度、辉光、星核等视觉语言，后续一项项修改适配 TalentMind，不允许 Agent 仅凭“未来感”自行重新设计。优先复用成熟组件库和可维护渲染/布局工具；视觉效果优先于极致性能，只需演示机基本流畅。
2. **仅在 `/graph` 页面**隐藏原全局顶栏的 `岗位能力图谱 > 岗位星云图谱`、`系统运行中`、管理员信息及其顶栏操作；登录页面和实际鉴权、注销逻辑暂时保留。后续将账户/相关操作融入“设置”的**方向已确认，设置具体方案暂不开发**。其他业务页面顶栏保持原样。
3. 右侧**图谱主窗口**与左侧导航卡片顶部、底部视觉对齐；图谱内左侧搜索/图例/筛选菜单和右侧按需出现的详情菜单暂时保留。此项不是要求内部详情菜单高度撑满左侧导航。
4. 保留原版交互语义：单击节点**原位高亮且不强制移动视角**；“查看全部关联”由用户主动触发、可“返回原视角”；搜索结果可切换、按需定位；放大时分层显示岗位/技能/行业名称，不因缩放无限放大节点。默认不强制三维自由旋转或自动飞行。
5. 真实节点、可解释推断社区与装饰粒子必须隔离；不允许装饰粒子计数为知识节点，或使用随机绘制位置宣称是经过验证的职业聚类。新旧渲染器和图算法待原型比较后定案；明确的参考图或已实现截图要标注真实来源。
