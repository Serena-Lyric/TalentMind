## 2. 恢复私有资料到新目录

```powershell
python -X utf8 scripts/backup_assets.py --backup D:\backup\TalentMind-2026-10-14 --restore-to D:\TalentMindPrivateRestore
```

目标必须不存在，工具不会覆盖旧资料。对象恢复为原路径，按需要从暂存区恢复原版回包/交接、原始 CSV/JSONL/历史 SQL、真实简历、原 DOCX/PPT 和实际配置。不同原路径的相同内容只在 ZIP 中保存一次，恢复时可重建多个路径。实际 `.env` 私有保存；使用前核对新机器数据库地址，密钥不得公开。

被省略的等价 ZIP/gzip 封装可从已保存内容重新压缩，压缩包字节及时间戳可能不同；必要内容和原文件哈希/表示方式见私有记录。旧 venv/node_modules、编译缓存、浏览器登录缓存不恢复。保留或重新创建 `data/local/PAUSE_COLLECT`，恢复核验不启动采集。

## 3. 安装依赖与镜像

从 Git 的 `backend/requirements.txt`、`frontend/pnpm-lock.yaml` 安装；第一轮实际包版本见 `docs/archive/competition-v1/runtime/python-installed-20261014.txt`。实测 Python 3.14.5、Node 24.15.0、pnpm 11.5.1，本轮没有重新验证从零安装。

```powershell
Set-Location D:\TalentMindRestore\backend
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
Set-Location D:\TalentMindRestore\frontend
pnpm install --frozen-lockfile
pnpm run build
```

不要覆盖已有 `.env` 或接受不明依赖 purge；在新目录安装。Docker 镜像重新下载，可按第一轮实际摘要固定版本（第二轮 registry manifest 查询均成功）：

## 4. 恢复数据库：只对新实例执行

**SQL 含建库/选库及表覆盖语句，图谱导入会清空 Neo4j。以下步骤只适用于新容器/新卷，禁止直接用于现有演示库。** 先核查端口未占用（Windows 用 `Get-NetTCPConnection`），使用新的 Compose 项目名：

```powershell
Set-Location D:\TalentMindRestore
docker compose -p talentmind-v1-restore up -d
$restoreMysql = docker compose -p talentmind-v1-restore ps -q mysql
docker cp D:\backup\TalentMind-2026-10-14\snapshots\mysql-v1-20260904.sql "${restoreMysql}:/tmp/restore.sql"
docker exec -it $restoreMysql sh
```

在该新容器 shell 内执行二进制文件重定向，避免 PowerShell 文本管道改编码：

```sh
MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 < /tmp/restore.sql
exit
```

如需保全时当前版本，将文件改为 `snapshots/mysql-current-20261014.sql`。V1 JD=2984（BOSS 1133），当前 JD=2988（BOSS 1137）；其余分析层 717/717/275、signal 1540、skill_dict 285、resume/talent_raw 0。两份 SQL 已在第一轮实际空白实例恢复，本轮只核对文件 SHA，不重复测试。

Neo4j 可从 Git `exchange/m3/graph.json` 在新实例重导，预期 7845 节点/11412 关系；或者在新空卷、Neo4j 未启动时，用保存版本的镜像执行 `neo4j-admin database load neo4j --from-path=<snapshots目录>` 加载 `neo4j.dump`。此 dump 已实际加载验证，保存业务库，不包含 system 用户库；新实例认证重新配置。隔离验证使用专用 internal 网络而不发布端口，避免 `--network none` 的 hostname 解析问题。

禁止默认 `import_all()`：它会读取原 719/243 回包并覆盖演示分析层。仅有 Git 时可显式导入 `exchange/m2` 重建分析层，但不能恢复原始 JD/signal；旧图谱 builder 也不能替代已核验交接文件。
