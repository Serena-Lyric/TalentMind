五人分工

M1 数据采集（A）

爬取岗位 JD 与简历/人才原始数据，清洗去重交叉验证，建原始库；兼主库/API/集成

  • 产出：jd_pool、talent_raw、signal
  • 对接：向 M2 交 jd.json

M2 岗位分析

原始 JD → 结构化岗位定义（五要素），技能归一，新岗位发现，动态演化

  • 产出：skill_dict/job_definition/job_skill/job_change_log
  • 对接：交文件给 M3/A

M3 图谱

岗位关系解析成点和线，产出图谱数据

  • 产出：graph.json（nodes/edges）
  • 对接：交文件给 A 导入 Neo4j

M4 简历+匹配

解析用户上传简历，匹配库内岗位，输出差距分析与路径建议

  • 产出：可运行模块 + 测试集
  • 对接：代码交给 A 集成进 API

M5 前端

所有岗位 / 图谱 / 岗位匹配三个页面

  • 产出：三页代码（Mock→真 API）
  • 对接：消费 A 的 API

数据契约（MySQL）

层表产出说明
原始层jd_poolM1岗位原始 JD（含清洗、质量分、去重分组）
talent_rawM1简历/GitHub 人才原始线索
signalM1（P1）技术/社区热度信号
分析层skill_dictM2技能归一词典（全队共用）
job_definitionM2岗位定义五要素 + source/quality/collected_at/is_emerging/evolution
job_skillM2岗位技能证据链（weight/confidence/evidence/is_required）
job_change_logM2能力变更审计（增/删/改 + 数据源 + 说明）
resumeM4简历解析结果

交接文件格式

统一 UTF-8、JSON 数组、snake_case，目录 exchange/<模块>/，字段冻结于 backend/app/contracts/ddl.sql。

[
  {
    "job_name": "RAG工程师",
    "core_duties": "负责检索增强生成系统的搭建与优化",
    "required_skills": ["langchain", "rag", "embedding"],
    "bonus_skills": ["faiss", "fine-tuning"],
    "scenarios": ["智能客服", "企业知识库问答"],

  }
]

接口与 API（模块自定 → A 统一 → MVP 定稿）

页面API说明
所有岗位GET /jobs列表 / 搜索 / 筛选 / 分页
图谱GET /graph/overview全景图谱
GET /graph/job/{id}岗位技能子图
岗位匹配POST /resume/analyze简历上传解析
POST /match匹配 + 差距分析 + 路径

接口由各模块自行定义、A 集成时统一（D19）；轻量惯例：统一响应 {code, message, data}、snake_case、Mock 先行（D20）；开发期 M5 使用 Mock。
