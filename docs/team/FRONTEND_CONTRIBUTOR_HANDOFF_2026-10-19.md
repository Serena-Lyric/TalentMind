# TalentMind 前端成员接入与并行开发指引（2026-10-19）

> **用途**：供新加入的前端开发者阅读；只说明接入路径、当前技术事实、协作边界与交付要求。此文档不授予合并、数据库写入或产品决策权限。
>
> **时效性**：目前 Career Nebula 正在独立 Draft PR 开发，本文随成员交接使用。正式产品状态以 `docs/PRODUCT_DECISIONS.md`、对应提交及实际测试为准；后续用户讨论尚未回填仓库的规则，应先与项目负责人确认，不能从演示页面推定已经批准。

## 1. 从哪里获取项目

- **GitHub 仓库（公开，可直接阅读/克隆）**：https://github.com/Serena-Lyric/TalentMind
- **正式开发基线**：`master`。请从这里新建自己的功能分支，不要在 `master` 上直接修改、推送。
- **前端目录**：`frontend/`；主要栈为 Vue 3、TypeScript、Vite、Element Plus、Pinia、ECharts；依赖管理使用 `pnpm`。
- **资料入口**：根目录 `AGENTS.md`、`AGENT_START_HERE.md`、`frontend/README.md`、`docs/PRODUCT_DECISIONS.md`、`docs/README.md`；按页面需要阅读其余模块文档。
- **图谱候选仅供对照**：PR #33 https://github.com/Serena-Lyric/TalentMind/pull/33（截至本文编写，P2.2 最新已知提交 `a373427`，Draft、未合并）；P2.3 三维相机正在另一独立开发流程中，不得把未合并改动当作 `master` 已有能力。

公开仓库不意味着其中所有历史文档均为最新产品规则，也不意味着未纳入 Git 的本地私有材料可自由转发。

### 本地接入（Windows / 终端示例）

```powershell
git clone https://github.com/Serena-Lyric/TalentMind.git
cd TalentMind
git switch master
git pull --ff-only origin master
git switch -c feat/frontend-<your-page>
cd frontend
pnpm install --frozen-lockfile
pnpm run dev
```

请用实际的功能短名替换 `<your-page>`。前端开发服务器默认端口是 `18080`；`/api` 默认代理至 `http://127.0.0.1:18000`，可通过 `VITE_PROXY_TARGET` 指向隔离的开发后端。前后端未联通时应展示真实的错误/空态，不要静默以假数据伪装成功。可用 GitHub Desktop 进行 Clone、创建分支和提交；使用终端不是唯一方式。

### 向仓库提交代码

- **已有写入权限**：独立分支推送到原仓库，创建面向 `master` 的 Draft PR。
- **没有写入权限**：Fork 到个人仓库，克隆个人 Fork；将 `Serena-Lyric/TalentMind` 设为上游来源，提交到个人分支，发起指向原仓库 `master` 的 PR。
- 由仓库负责人决定是否邀请为协作者。**不要分享主账号、访问令牌、Cookie、SSH 私钥或本地项目目录的私有文件**。
- PR 必须经过代码审查、测试和用户授权后才能合并；个人开发者与 Codex 均不得自行合并或启用自动合并。

## 2. 允许修改与需要协调的边界

本次优先开发 **非 `/graph` 页面**（如采集模块管理、JD 岗位管理、能力动态更新、简历分析、技能学习路径）。具体认领页面和业务需求应先由项目负责人确认；未确认的视觉重做不等于产品决策。

| 类型 | 建议 |
| --- | --- |
| 本人认领的 `frontend/src/views/` 页面及其专属局部组件、样式、测试 | 可以在独立分支开发 |
| `frontend/src/components/GraphPanorama.vue`、`LegacyGraph.vue`、`frontend/src/graph/`、图谱路由与视觉依赖 | **暂不修改**，由专门 M3/M5 开发线维护 |
| `frontend/src/App.vue`、`frontend/src/styles.css`、路由、`frontend/src/api/` 共享契约、Pinia 共享状态 | 跨页冲突高；修改前与负责人协调，优先改局部样式/局部组件 |
| `frontend/package.json`、`frontend/pnpm-lock.yaml`、`frontend/vite.config.ts` | 新依赖和构建配置必须说明必要性，并协调后再修改 |
| `backend/`、`exchange/`、数据库脚本、冻结 DDL、真实数据 | 本次前端任务不修改；需要变更先单独评审授权 |

**特别注意**：图谱专用的“隐藏全局顶栏”只适用于 `/graph`，不应让其他业务页的导航、登录/注销和状态布局受到影响。左侧全局导航卡片与图谱内部的控制菜单是不同组件，勿混用 CSS 选择器。

## 3. 页面设计与数据要求

1. 保持现有 TalentMind 基础视觉语言、导航、响应式行为和鉴权；优先用已有 Element Plus / ECharts / Vue 工具，不重复引入 UI 框架。
2. 先检查现有业务 API 与 `frontend/src/api/` 契约。请求沿用统一 `/api` 与 `{code, message, data}` 格式（由请求层处理）。不为了截图效果伪造数据、统计指标或实际后端功能。
3. 页面至少有加载、空数据、失败、正常四种状态；表单具备基本校验。适配 1600×900 常用演示分辨率，并检查窄屏、长内容、滚动条与弹层遮挡。
4. 不将 M2 的离线新分析体系、B3 尚未发布的 19 项正式岗位目录、M3 候选社区算法或 M4 的演示分说成已经正式上线的可信数据。保留旧功能，不因样式调整改变业务事实。
5. 不自动开始真实采集、不更改生产数据库、不迁移旧数据；如需账号登录或联网调试，使用批准的测试环境和权限。

## 4. 避免与图谱 PR 冲突

- `master` 当前不是完整新银河版本。#33 和之后的 P2.3 属于独立、未合并候选。
- 开发前、提 PR 前都查看 `git status` 和 diff；不要用 `git add -A` 夹带构建产物或未确认文件。
- 尽量把改动限制在本人页面；需要通用外壳/路由/API 变更时，在 PR 中列出冲突文件、影响的其他页面和解决方案。
- 图谱候选合并到主干后，由负责人统一协调更新；不得为了赶进度直接覆盖 P2.3 或无差别合并两个工作树。
- 涉及其他成员模块的功能：先共同确认接口与分工，再分别实现。

## 5. 最小交付标准与材料入口

每个任务提交一个独立 PR，描述：认领页面、需求来源、改动文件、主要界面前后截图、启动方式、实际测试/构建结果、已知问题以及是否修改公共接口。

至少运行：
```powershell
cd frontend
pnpm run build
```

有对应测试时运行定向测试；此外在真实浏览器检查导航、交互、输入、长内容滚动、窄屏和错误状态。测试没有执行就明确写未执行，不得编造通过记录。

给成员提供材料时，优先发**已审查的 GitHub 文档链接、确定提交或 PR 链接**；本地私有材料只通过负责人批准的渠道提供脱敏导出件。不要将 `.env`、API 密钥、真实简历、Cookie、数据库文件、`input/`、`output/` 或未入库原始资料提交公开仓库。
