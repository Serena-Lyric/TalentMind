## 2. 机器预测与人工真值分离

保留三层独立信息：

1. **机器预测**：冻结报告中的 B1、B2、B2.2、B3 结果、规则版本和 `machine_sha256`，只读。
2. **人工逐项真值**：B1 范围、B2 每条技能陈述的人工状态、B3 每个大类候选的人工判断，以及依据。
3. **审核事件**：审核人、时间、总决定、事件 SHA-256 和追加历史。

人工字段未填写时必须保持空值，不能根据机器结果自动复制。人工事件不能覆盖原报告或把候选升级为正式需求/岗位。

## 3. B1 范围审核

逐条查看原始 JD、身份状态和 B1 技术活动证据，填写：

- `in_scope`：核心工作属于当前软件相关技术范围；
- `out_of_scope`：核心工作不属于该范围；
- `needs_review`：证据不足、职责混合或边界未定；
- `not_applicable`：输入内容无效或无可用正文。

注意：

- 标题、公司背景、学历、年限、泛化“参与”或工具列表不能单独证明技术职责。
- 产品经理等复合岗位必须看主要交付责任，不以标题词或职责条数自动决定。
- 人工范围结论只约束本条 JD，不自动传播到重复正文的另一身份。

## 4. B2 技能陈述与要求状态

对每条机器技能陈述逐项核对：

1. 引文是否能从显示字段按 `[start,end)` 精确回源；
2. 它是否是技能/能力陈述，是否把工具、学历、年限、行业经验或职责动作误当技能；
3. “必须/优先/仅提及/不要求/待判断”的局部作用域、否定、条件和组合关系；
4. `all_of`、`any_of` 或未解析替代项是否被错误拆成单个必备要求。

人工状态使用：

- `required`、`preferred`、`mentioned`、`not_required`、`uncertain`：与五态对应；
- `not_skill`：人工认为该陈述根本不是技能事实，不作为五态之一。

人工状态是逐陈述真值。即使组合中的多个成员均为 `required`，也不得把组合拆成任一项单独必备；替代关系仍以组合上下文为准。未进入 B2.2 规范化的陈述仍保留 `skill_ids=[]` 并可审核，不能因为它没有 M3 Skill 边而跳过。重复 JD 必须分别审核。

## 5. B3 大类候选

逐个职业大类候选判断：

- `accepted`：职责证据支持该大类候选；
- `rejected`：证据不支持；
- `needs_followup`：责任主次、证据或大类边界不足。

允许保留多个竞争候选；没有明确主次时不得强行从中挑一个主类。机器没有给出、但人类从职责证据识别的已登记大类可在“补充机器漏判候选”中记录。大类候选仍不是标准岗位发布。

## 6. 页面操作

1. 打开正式 Vue `/m2`，选择表中精确 run，不创建替代输入、不启动重放。
2. 按队列 `page` 和 `ordinal` 找到 JD；核对 `machine_sha256`。
3. 在“冻结原文”和 B1/B2/B2.2/B3 页签查看机器结果与原文位置。
4. 填写 B1、逐条 B2、逐个 B3 人工标签和依据。
5. 填写自述审核人和总审核决定，提交追加事件；导出 JSON 复核。

页面登录只是本机演示入口，审核人字段也是自述，不是身份认证。Codex、Agent 或其他大模型不得代填、推荐为真值或冒用审核人身份。

## 7. 统计边界

- 未填人工标签的条目：未审核，不是负例。
- B2 统计单位是条目·技能陈述；B3 统计单位是条目·大类候选；两者不能与 JD 数相加为“总准确率”。
- 零分母时 P/R 未定义；不得用机器正例数、节点数、连线数或候选数推断真实 precision/recall。
- 只有真实审核人完成的交集样本可计算对应维度指标，并须同时报告覆盖数、分母、版本和导出哈希。
