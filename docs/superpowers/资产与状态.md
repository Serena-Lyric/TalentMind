## 重要限制与安全门禁

- M1 的岗位身份 `verified / pending / unknown` 与正文内容资格分开，`pending` 只能形成受限制的观察/候选，不能冒充确认招聘需求。正式 MySQL 三身份列迁移仍需兼容设计与单独授权。
- M2、M3 的机器候选不等于人工真值；Gate 3 曾验证工程闭环，但当时人工真值数量为零。正式分析表与 Neo4j 不能仅因前端显示候选而更新。
- 默认 `pytest -m integration` 的历史执行曾存在生产数据改写风险；只在明确验证的隔离实例运行。[安全陷阱](traps/2026-10-22-full-pytest-integration-default-import.md)
- Windows 宿主端口 MySQL 使用 `23306`（容器内仍是 `3306`）；连接配置和 Compose 以当前文件为准。[端口问题](traps/2026-10-17-mysql-excluded-port.md)
- 历史图、V1 导入 SQL 与当前正式数据不可混用；当前实时表记录数须重新只读查询，不能套用过往报告数字。
- 竞赛正式成品集中在仓库外私有目录，原则上不在公开仓库存放、不将私有提交资料当作通用 docs 类别。
