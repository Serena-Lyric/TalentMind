## 1. P0：三种业务星体主体视觉

- Job、Skill、历史 `Industry`/`scenarios` 投影分别对应**一种可长期辨识的主体星体设计**，主体由业务 `node.kind` 决定；不能再用 `stable ID % 4` 的随机红巨星/白矮星等作为一级主类型。
- 外形、球面质感、相对核心/光晕比例和基础色一起建立区分；优先沿用蓝/绿/紫类型辨识方向，但确切值通过 P2.4 同条件对照决定。
- P2.4 四种恒星外观保留为旧证据和明确回退能力；如果保留次级细节变化，不得改变业务类型辨识或暗示岗位需求、市场热度、质量、社区类别。
- 减少大面积高饱和红橙点阵。保留明暗与类型差异，避免近景仅剩饱和光盘。不能用完全统一的纯色圆点代替星体。
- 优先利用现有 `stellarAppearance.ts`、`stellarMaterial.ts`、`knowledge.ts` 和批量 GPU shader；避免全量高分段网格和无必要的新依赖。

## 2. P0：局部密度控制与银河融合

- 根据**屏幕空间投影密度**让拥挤区域的普通知识星体减小 halo/视觉覆盖，必要时控制点径/透明度；不改变真实图谱节点的身份、业务数据、布局坐标、查询可见性与拾取。
- 选中、悬停、搜索命中、真实关联对象仍易识别与命中；正常 LOD 可以保留，但不允许因为“不是当前关联”或密集而悄悄剔除它们。画面/计数应仍可追溯。
- 参数随 zoom/roll/orbit 平滑变化，无明显闪烁和突变；实现需避免每帧对 7845 个节点 O(N²) 邻域计算，必要时采用投影网格/桶或缓存与脏更新。
- 保留银河主体色彩、原旋臂和布局版本。允许以小规模细尘/过渡 shader/色彩微调缓解星尘与星体视觉脱节，不得挪动业务坐标或改变 Jaccard/Leiden 布局成果。新增细尘必须独立于知识统计。
- 用户特别反馈的场景：大面积旋臂及其尾部、不自然的彩色点阵、近景高密团块、侧面旋转观察，需要有专项实拍对照。

## 3. P0：关系端点渐变

- 默认未选择时历史关系提交为 0；选择后保留该节点全部**类型可见的真实直接边**，不删原边，不把派生相似混入历史事实。
- 对每条可见曲线，使用源端主视觉色 `source` → 目标端主视觉色 `target` 的空间插值渐变，保证线段沿原始真实方向、不同透视和滚转下仍对应各自星体。线仍需轻薄、清楚，不覆盖星核。
- 不再用历史 `REQUIRES`/`APPLIES_TO`/`RELATED_TO` 的实线/虚线样式作为**常态菜单线型图例**；删除相应旧图例。业务关系的类型、端点、`sourceIndex` 和来源原文须继续在右侧详情/hover/逐边高亮中准确展示。
- 派生层仍须用户显式开启，若开启绘制，也应采用端点颜色渐变，且独立标识为候选推断，不靠变成与历史一样的线来伪装。
- P2.4 原边 222/222 的 `sourceIndex` 高亮与高连接定位完全保留；默认隐藏与类型过滤都不能误报为数据缺失。
