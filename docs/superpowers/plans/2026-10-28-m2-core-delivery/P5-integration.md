# P5 — 独立入口、持久化恢复与下游消费闭环

> 状态：[ ] 未开始。直接依赖：P1～P4 实际接口与版本。早期各段已需有必要的保存/读取能力，本段验证跨能力集成与故障恢复，不把所有可靠性推迟到最后才处理。

**目标：** 使用者通过实际入口完成单条/小批分析、解释、候选与演化读取，停止/失败后不丢历史，下游能依据稳定契约消费结果。

## 必须交付的结果

1. 显式输入与依赖下的独立运行入口，不需要 M3、前端或完整正式目录才能分析；现有产品入口如接入，真实到达新实现而非只显示新字段。
2. 单条结果、岗位解释、候选及其当前/历史版本可读取，绑定同一输入及实际运行；旧结果不被当前 heads 或另一 run 偷换。
3. 同输入同依赖可正确复用；知识/标准/分析变化按受影响范围重评，范围不明时保守处理，不能复用不足事实或冒充精准失效。
4. 停止、模型超时/截断、进程中断、持久化和发布失败可恢复，已提交结果不丢失、未提交判断不冒充完成，不重复应用候选更新或关键确认。
5. 对外契约能表达部分/未知/失败与候选/正式性质，替换内部处理器后消费者仍可用；不兼容变化必须版本化，旧字段投影不默默丢失新语义。
6. 保留本地原文访问边界及缓存控制；适配现有 UI/API 的必要部分即可，不要求全新页面或正式 Neo4j/匹配模块改造。

## 必须实际检查的行为

- [ ] 一个真实入口走完整链路，消费者读取的版本和内容与本次运行一致。
- [ ] 模拟中断/提交后发布失败/停止恢复/重复启动，能核对持久结果、候选版本及更新次数。
- [ ] 输入内容变化、仅观察时间变化、标准变化、分析能力变化分别有正确复用或重评行为。
- [ ] 如有 UI，迟到响应不能覆盖新选择的 run；无 UI 时用实际 API/消费者验证同样的运行绑定性质。
- [ ] 部分结果不会因一个能力失败被抹去，也不会把整条 JD 提升为完整结果或正式知识。
- [ ] 集成测试使用实际核实的隔离连接和唯一夹具；finally 精确清理，残留为 0 且原有数据未受损，有查询证据。
