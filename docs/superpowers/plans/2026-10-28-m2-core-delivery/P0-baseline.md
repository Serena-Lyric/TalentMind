## 必须交付的结果

1. 一份可定位的私有评价清单：成员身份/内容摘要、来源、用途、版本、授权、标注/复核状态；选少量代表性真实中文 JD，数量由覆盖决定，实际数量如实记录。
2. 覆盖职责、要求逻辑、关系三态、岗位解释、候选配对与分批演化的参照案例；可先用合成案例验证读取，但真实语义指标必须对应真实人工参照。
3. 开发/留出用途划分及泄漏检查；人类标注可增加机器漏项。标注缺失/争议的项目显式待定，不用 Agent 或同模型未经审核输出填充人类真值。
4. 按审核标准冻结指标、分母、目标/定性通过条件及确认来源；未取得确认的指标保持未冻结，不声称本段语义条件已完备。
5. 最小语义契约：合法输入、职责/要求/关系及证据、部分/未知/失败、岗位解释、候选/正式性质和版本关联。具体编码/字段可由实施者提出，但必须可校验、可供 P1/P2 使用，并记录契约版本。
6. 说明后续可用模型/运行方式、真实数据可发送范围和成本边界；没有外部发送授权时准备离线材料即可，不调用真实文本服务。不得把候选技术选择写成永久产品规则。

## 结果检查与 ChatGPT 审核重点

- [ ] 另一执行者能按清单取得同一输入及知识版本；私有路径失效有明确诊断，不静默换数据。
- [ ] 基准包含短 JD、未知词、开放任选、否定/优先作用域、同技能不同责任、同责任不同栈、目录缺口及反证序列。
- [ ] 人工参照来源与工程自检分开，未标注内容不会进入真实准确率分母。
- [ ] 指标不能靠全未知通过；原文确实模糊时有合法未知预期。
- [ ] 契约支持独立单条分析与部分结果，不要求先有标准岗位名、M3 或完整职业目录。
