# P2 — 可更新知识与可复核的岗位归属解释

> 状态及提交记录仅维护在 [总进度表](../2026-10-28-m2-core-delivery-plan.md#3-分段地图与当前进度)。直接依赖：P1 分析结果、P0 岗位参照与评价口径。本段不建设完整职业体系或发布正式目录。

**目标：** 同义表达可可靠对齐，未知表达不会丢失；岗位判断能说明责任覆盖、缺口、冲突与限制，标准更新后可重新解释。

## 最小阅读与输入

- [总计划](../2026-10-28-m2-core-delivery-plan.md)、[审核标准](../../specs/2026-10-28-m2-delivery-review-standard.md)、P1 已审接口与 P0 标准版本、[设计 §5、§7](../../specs/2026-10-28-m2-analysis-candidate-design.md)。
- 参考 `backend/app/skills/normalizer.py`、`job_analysis/governance/`、`role_classification/`、`canonical_catalog/` 和正式契约。历史候选文件的存在不代表其中岗位定义已获批准。
- 实际比较从 P0 交接的少量岗位参照开始，读取其来源、版本和测试/候选/正式状态并带入结果。缺少可用参照时如实报告岗位比较证据不足，不能把空目录或未覆盖当作新岗位独立性的证明。

## 必须交付的结果

1. 独立可版本化的知识读取/对齐能力，原词、定义来源及确认状态保留；明确同义可映射，歧义/上下位/相关技术不强合并。
2. 未知技能和候选岗位定义可保留与研究，不自动进入正式知识。国内招聘表达及国内规范是业务依据；国外资源可作参考但不替代本地评价。
3. 岗位比较返回考虑该岗位的理由、相符职责、未覆盖责任、明确冲突及未知原因，引用新 JD 与所比较定义/历史 JD 的实际版本；大类、标准岗位、技术方向、级别分别给有依据的值或未决，不凭宽泛标题补齐。
4. 岗位定义和历史 JD 分担边界与变体证据；历史没出现/定义未覆盖不等于排除，目录为空也仍可返回单条分析和未决解释。
5. 检索覆盖范围与后续判断分别可检查；检查了有限候选不能宣称排除整个目录。具体检索算法与数量策略由实现者按效果选择。
6. 更新别名或岗位标准后，在事实充分时复用单条分析重新对齐/比较；旧解释仍能按旧版本读取，不把标准变化报成企业招聘变化。
7. 按实际岗位关联提供可重建的岗位能力画像，标明成员、范围、版本、覆盖和知识状态。单条 JD 的必备要求不推广为所有同类岗位必备，原冲突与不确定性不被画像改写；候选画像不冒充正式统计，不扩展市场需求率课题。

## 必须实际检查的行为

- [ ] 相同标题/技能但交付责任不同，结论可区分；同责任不同技术栈不会仅按工具拆成不同岗位。
- [ ] 候选/正式标准不混用；含宽泛标题、主辅不清、混合职责和多招聘目标时不强制归类或制造独立职位数。
- [ ] 目录缺口、分析不足、边界冲突有不同理由，未归类不自动生成“新岗位已发现”的结论。
- [ ] 未知技能不丢失，不通过相似度或模型常识自动发布别名/技能。
- [ ] 标准版本变更的同输入对照与历史读取可以复核。
- [ ] 相同单条事实可重建对应画像，成员/标准变化能追溯；画像不会反写单条要求或把一条必备扩成全体必备。

## ChatGPT 审核与交接

审核“为什么能/不能归入”的原文和定义依据；检索召回与给定候选后的错误分别报告。未经确认的岗位定义不能借通过此工程审查变成正式名单；P0 的本段评价条件须满足。

交接给 P3/P5：知识/岗位比较及画像读取接口、实际标准版本与状态、画像成员、解释结构和候选召回范围、未知与冲突的读取语义。知识格式、模型/检索实现及代码组织可变；产品语义和外部契约保持明确兼容。提交独立 PR 及真实证据。
