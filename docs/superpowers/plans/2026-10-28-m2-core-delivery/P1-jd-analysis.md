# P1 — 单条中文 JD 的职责、要求与证据理解

> 状态及提交记录仅维护在 [总进度表](../2026-10-28-m2-core-delivery-plan.md#3-分段地图与当前进度)。直接依赖：P0 的可用契约、样本与评价口径；对话结束交付本段结果，不扩展候选管理或前端重构。

**目标：** 一条真实中文 JD 可以独立得到有证据的结构化工作内容与要求；无法理解或执行异常时保留其真实状态，不丢掉其他有效结果。

## 已确认的 P1 执行方向（2026-10-29）

本节记录负责人在 P0 限定范围通过之后的最新选择，**约束交付目标、权限和验证，不固定 Codex 内部实现方法**。阶段状态和 PR 仍只在总进度表维护。

- **结果优先**：Codex 可选择、比较和替换模型、解析技术、函数/文件结构、请求次数、上下文组织与存储方式；下述“结构化语义理解 + 知识归一化 + 确定性验证”是优先研究的参考方案，**不是强制流水线**。旧 B1/B2/B2.2/B3 不得默认被包装为新 P1 分析器。
- **云端 API 优先**：P1 应能部署在不要求 GPU/模型权重的轻量服务器；模型服务商、实际模型版本与参数应可配置、可追溯，不将历史配置中的服务地址/价格视作当前批准或可靠可用。**本地生成模型状态是“暂未尝试”**，可以预留替换能力，不要求本阶段安装、运行或验证本地模型。
- **一次完整中文理解为主**：完整 JD 的职责、目标、对象与要求在足够上下文下理解；发现长文本、截断、关键遗漏风险或具体作用域歧义时，允许有针对性的补充分析。是否采用分段、二次模型或纯程序补救取决于效果，不无条件每条多轮调用。
- **职责事实优先、M2 独立**：不依赖岗位分类成功，不以目录/模型常识回填雇主未陈述的事实；P1 输出维持 `m2-semantic-0.2` 的来源、证据、版本、未知和部分结果语义。P2/P3、B/C 总体选择及旧正式 MySQL/Neo4j 接口不在 P1 施工范围。
- **规模作为设计参考**：历史曾提出约 3,000 条 JD/12 小时；它是选型和批处理规划参考，**不是已取得的实测能力或未经批准的硬性验收门槛**。评估实际延迟、吞吐、Token、重试、费用和轻量服务器资源依赖，避免只为少数例子无限增加模型调用。

### 云端真实 DEV 数据的本次权限与停止条件

负责人已明确**允许** P1 为真实中文语义验证向第三方云端模型 API 发送真实 JD；此项解决了 P0 时“不得外发”的 P1 前提，**不等于批准任意服务商、真实简历、全库/历史 ZIP、HOLD、无限重试或付费额度**。

1. **先限定 P1 已审核 DEV-01～09**，从当前私有冻结 manifest、签审凭据及 `p0-case-map-3-approved` 读取；不打开、发送或用于提示词调参的 HOLD-01～04，不外发原始历史 ZIP 的其他 JD 或未经必要确认的其他个人数据。不得将原文、模型完整回包、API Key、提示词中的私有样本写入 GitHub、PR diff、CI 或公开报告。
2. 在首次真实请求前，Codex 记录**实际供应商、账户/区域、端点、模型 ID 与服务商宣告的实际底层版本（若有）、调用所用输入字段、服务条款与数据保留/训练政策核对日期**；同名模型可能被供应商重定向。供应商可替换，但新供应商须重复权限/政策核对并确认外发范围仍被覆盖。不得因为“OpenAI 兼容”而把私有数据无意发送至旧默认代理网关。
3. 外发仅含分析所需 JD 文本与有限上下文，不附带人工标签、签审凭据、历史完整数据库、私人联系方式等无关信息。若必要脱敏会改变字符位置，外发文本与本地冻结原文的 offset 映射应明确可审查；不能把脱敏文本的偏移直接冒充原文偏移。中文条件、否定和章节上下文不能为了脱敏被无意删掉。
4. **付费仍未获金额授权**：不得主动充值、开通有额外账单的付费资源或无额度上限跑批。真实收费推理前须由负责人明确批准供应商/模型、预算上限和超限停止方式；免费额度只有在可证实不会产生额外费用的前提下才可用于本次授权的 DEV 试验。否则先完成离线工程、合成验证与真实请求计划，并将费用/访问阻塞如实登记，不以模拟结果声称 P1 语义通过。
5. 调用使用本地受控密钥，禁止提交或打印；输出原始响应和真实请求明细仅进合规私有目录。实际请求次数、Token、供应商账单/估算、失败重试、数据外发范围可供负责人及 ChatGPT 在授权方式下审阅。版本、超时和中止后不得让迟到响应覆盖新 run。
6. **供应商选择参考（不是指定模型）**：官方条款/数据政策与价格以调用当日再次核实为准，可比较 [DeepSeek API](https://api-docs.deepseek.com/quick_start/pricing)、[DeepSeek 开放平台条款](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html)、[阿里云百炼数据保留政策](https://www.alibabacloud.com/help/en/model-studio/data-retention-policy) 与 [阿里云百炼价格](https://www.alibabacloud.com/help/en/model-studio/model-pricing)。注意 DeepSeek 官方 2026-09 公告指出旧 `deepseek-v4-pro` 曾临时路由到 Flash，不能只凭两个 API 名称当作独立模型对照。

### Codex 开发及验收交接（方法开放、结果必须真实）

- **开发前**：核对 Git 状态与当前 `master`、P0 受控输入/契约/批准条件存在性；确认 P1 影响范围与无效权限门槛。代码在临时分支，文档小修可按负责人长期授权直接提交 master；不得自动迁移或写正式数据库。
- **先实现可独立运行的单条入口**：真实输入→分析→证据/版本校验→可追溯结果读取。模型输出可采用内部轻量草稿，再由程序完成证据定位；具体方案由 Codex 选，但模型不能自认人工审核或由 JSON 合法推导语义正确。
- **语义效果必须与批准 DEV 对齐**：逐例核对核心目标/职责/要求、任选、程度否定、条件/优先、开放集合、能力与职责关系、短文/背景污染及漏提/误提；遵守 P0 方案 A 的 A/B/C/D、全体适用单位及有理由的等价拆并。若不能调用真实模型，只可报告工程完成或条件性阻塞，不能声称真实中文语义验收通过。HOLD 留给 P6。
- **错误与覆盖必须真实**：区分没有识别结果、未提及、关系未知、能力未执行、部分完成、请求超时、空响应、坏结构、截断和失败；**禁止旧 `llm.py` 的截断补括号策略将不完整响应冒充完成**。保留可核查的有效部分及原文证据，`classification` 未执行时不应伪装整体分析 `complete`。
- **质量优先也要报告成本**：逐条记录完整请求次数、总时长、Token 和费用；若采用定向补充，说明触发条件、额外资源开销、实际修复的缺项和新增误判。模型自报分数不当人工真值；无需预设统一百分比门槛或刚性模型调用次数。
- **PR 和报告**：提交含源码/测试/合成夹具的独立 PR，私有 DEV 原文/预测明细留本地；在 `docs/review/` 提供脱敏可审报告：实现选择、实际入口、运行环境及命令/退出码、DEV逐例A/B/C/D与漏误提（可公开安全摘要）、真实调用/费用、异常/恢复、未验证范围及 P2 依赖；维护全仓最多五份阶段报告规则。ChatGPT 按 PR **固定 head** 与实际证据审核，修复后重新提审；Codex 不自行合并。
- **触发下一步**：负责人只需告知“Codex 已完成”，ChatGPT 自行读取远端 PR、提交和报告进行审查。若成本授权或私有样本缺失，应明确报告阻塞而非静默换样、重做 P0 或将模拟效果当真实评价。

## 必须交付的结果

1. 可独立调用的实际分析入口，接受 P0 契约输入，输出工作目标/对象/职责、能力与任职条件、证据引用及覆盖状态，不以岗位归类成功为前置。
2. 五态、程度、条件、否定、任选/全部满足、能力/经验对象按上下文保存；技术技能、专业能力、工程实践、软技能及行业/任职条件分别管理，允许类别未知。未知词/未解析表达保留原文，工作职责与公司背景分开。
3. 能力—职责明确关系有直接依据；有限推测标识且可说明上下文理由；只有共现时不强建关系，不生成全配对矩阵。
4. 严格校验输入身份、原文位置和结构；引文存在与语义正确分开。多处引用的歧义、Unicode/换行、字段副本重复可解释处理。
5. 超时、空回包、截断、坏结构、无识别结果、部分完成和未知分别输出；不能通过补 JSON 括号把截断结果冒充完整分析。有效部分可追溯保存。
6. 处理器与配置可替换并纳入版本。若采用模型，模型、提示及实际依赖记录可查；实现方式由中文效果决定。
