# P1 — 单条中文 JD 的职责、要求与证据理解

> 状态及提交记录仅维护在 [总进度表](../2026-10-28-m2-core-delivery-plan.md#3-分段地图与当前进度)。直接依赖：P0 的可用契约、样本与评价口径；对话结束交付本段结果，不扩展候选管理或前端重构。

**目标：** 一条真实中文 JD 可以独立得到有证据的结构化工作内容与要求；无法理解或执行异常时保留其真实状态，不丢掉其他有效结果。

- 参考 `foundation/inputs.py`、`foundation/models.py`、`semantics/validation.py`、`llm.py` 和 `docs/superpowers/traps/2026-10-22-m2-real-evidence-scope.md`；旧 FactClaim/B2 校验不能被默认当成新语义结果结构。

## 必须交付的结果

1. 可独立调用的实际分析入口，接受 P0 契约输入，输出工作目标/对象/职责、能力与任职条件、证据引用及覆盖状态，不以岗位归类成功为前置。
2. 五态、程度、条件、否定、任选/全部满足、能力/经验对象按上下文保存；技术技能、专业能力、工程实践、软技能及行业/任职条件分别管理，允许类别未知。未知词/未解析表达保留原文，工作职责与公司背景分开。
3. 能力—职责明确关系有直接依据；有限推测标识且可说明上下文理由；只有共现时不强建关系，不生成全配对矩阵。
4. 严格校验输入身份、原文位置和结构；引文存在与语义正确分开。多处引用的歧义、Unicode/换行、字段副本重复可解释处理。
5. 超时、空回包、截断、坏结构、无识别结果、部分完成和未知分别输出；不能通过补 JSON 括号把截断结果冒充完整分析。有效部分可追溯保存。
6. 处理器与配置可替换并纳入版本。若采用模型，模型、提示及实际依赖记录可查；实现方式由中文效果决定。

## 必须实际检查的行为

- [ ] “Python 或 Java 至少一种”不变成两项各自必备；含“等”或词典外选项时保留开放性/未决，不删掉替代项。
- [ ] “不要求精通但需了解”不变成整体不要求；“项目经验优先”不被改写为技能熟练优先。
- [ ] 使用 Redis 完成某职责不自动产生必备、熟练或不可替代结论；摄影等共现能力不被关联到智能体开发。
- [ ] 短 JD、章节/字段作用域、公司背景、重复职责和证据偏移有明确预期及实际结果。
- [ ] 至少一个实际入口跑通完整读入—分析—校验—结果读取；模拟能证明的工程性质和真实中文语义效果分开。

## ChatGPT 审核与交接

审查实际执行路径、P0 对本段的覆盖/漏误提及关键语义结果；测试数量、合法 JSON 或模型自报完整不能单独证明通过。没有真实模型/人工参照条件时，报告工程结果及缺失，不宣称真实效果通过。

交接给 P2/P3：真实入口、契约与分析版本、证据定位语义、有效部分读取方式、已知覆盖、实际用例/失败与成本信息。文件拆分、处理器数量和调用方式可自主选择，保留最小实现与必要回归。按总计划提交独立 PR、证据及审核结果。
