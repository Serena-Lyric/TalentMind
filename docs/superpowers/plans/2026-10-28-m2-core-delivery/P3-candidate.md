## 2026-11-06 限定执行范围与实施计划

**Spec / 授权：** [Issue #65](https://github.com/Serena-Lyric/TalentMind/issues/65)。其最新执行范围替代本页对完整 P2 的前置依赖：从 master `70a6f07` 独立开发，仅使用已合并 P1/P2-1，P2-2 #63 搁置、#64 未合并且业务未通过。不自动开始 P4/P5、合并或正式发布。技术选型由 Codex 自主完成，不等待技术方案审批。

**Goal：** 可跨进程研究、追踪、纠正工作组合候选，语义不足明确待核验。

**Architecture / Tech Stack：** 复用 P1 严格验证和 P2-1 对齐；标准库 SQLite 事务、只追加批次快照和内容寻址的原始分析/知识，不接生产存储。候选 ID 由显式稳定 ID 标识，描述只作机器解释；检索只读取有来源的工作陈述，返回有限研究线索，不确认同职业。与复用旧技能候选 registry 相比，独立轻量存储能避免技能准入语义泄漏；与接入未合并 P2-2 相比，可保持已发布依赖和真实验收边界。

**Global Constraints：** 原 P1 事实/机器未审状态不变；人工身份与语义认证不由哈希代替；未知来源独立性/职位数为 null；同批固定基线；关键结构和正式身份操作不开放；原始数据不出本地；报告直接写 Issue，不新增阶段报告。

**Review Focus：** 重跑/转载不能增加独立强度；候选链条无传递；部分/失败输入不生成身份；过时基线/并发写入整体拒绝；纠错/描述/知识变化保留旧事实和版本且不报告市场变化。

## 必须交付的结果

1. 候选有稳定身份、临时工作描述、成员分析引用、当前责任假设、相近岗位/候选及未解问题；无需正式职业名，不复制原分析事实。
2. 仅在有具体责任组合、依据和研究问题时建立观察假设；输入异常/单次分类失败不自动产生新岗位，创建前检查相近候选。
3. 新 JD 依据工作目标、对象与核心责任比较；有依据的机器关联可保存并撤销，明显不确定的保留疑点，部分职责支持记录其范围。
4. 同批比较固定候选版本，关联说明可以回到 JD、标准与候选版本；身份持续跨运行，不靠当前描述文本哈希制造新候选。
5. 检查相邻组合与代表性原成员，不把 A 相似 B、B 相似 C 当作 A/B/C 自动同组；可能重复的候选只提出合并建议，不自动变更身份结构。
6. 重复发布、身份待审、多候选关联与独立职位计数分别处理；候选数和关联数不冒充招聘量或需求率。

## 必须实际检查的行为

- [ ] 两批输入之后能读到同一候选身份、版本与新增证据，重放不会重复制造成员或候选。
- [ ] 责任相同/工具不同可以关联；工具相同/目标不同不被强关联；证据不足可检索但保持未决。
- [ ] 相似链条、同 JD 的局部交集与真正多职位材料不被错误合并或制造多个 vacancy。
- [ ] 多个相近候选的选择及不确定性有解释，不能只拿最高相似度分数当事实。
- [ ] 关联纠正能保留旧依据，不改写单条事实或借纠正操作自动合并/拆分候选。

## ChatGPT 审核与交接

审核可复现的跨批序列与 P0 候选配对评价，包括误关联、漏关联和重复候选，不只看成员数增加。人工真值不充分时说明参照范围，不声称新职业发现准确率。

交接给 P4：候选/成员实际接口、版本与身份语义、批次基准、未解与反对证据、机器关联修正和合并/拆分建议的边界。实现者可选最轻量持久化与比较方法；无需任务本体或完整关系矩阵。提交独立 PR 与阶段证据。
