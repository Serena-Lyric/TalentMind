# P6 — 中文真实效果与完整链路最终验收

> 状态及提交记录仅维护在 [总进度表](../2026-10-28-m2-core-delivery-plan.md#3-分段地图与当前进度)。直接依赖：P0 冻结口径、P1～P5 实际已审版本及已记录限制。本段是评价与必要定向修复，不扩展为全行业职业研究或新功能阶段。

**目标：** 用可复核的中文证据说明 M2 当前真正做到什么、效果如何、哪些仍不可靠，并让 ChatGPT 对完整交付给出明确结论。

## 最小阅读与输入

- [总计划](../2026-10-28-m2-core-delivery-plan.md)、[审核标准全文](../../specs/2026-10-28-m2-delivery-review-standard.md)、P0 基准清单及 P1～P5 审核结论/实际 master SHA。
- 使用原冻结中文评价口径及未被反复调参污染的留出检查；真实模型、标注、隐私和预算条件须实际具备，历史通过数不作为本轮结果。

## 必须交付的结果

1. 从最终真实入口执行单条/小批链路与连续候选演化，结果能回到实际输入、知识、分析、候选版本及人类参照。
2. 按 P0 冻结口径分别报告职责/技能漏误提、要求关系、岗位解释、候选关联与自动演化；分清检索漏召回、比较误判和运行失败，保留全部适用分母。
3. 有合理参照证明所选方法的价值，例如既有规则、标题/技能相似或其他可说明的基线；不强制采用哪种基线算法，比较须使用可比输入与参照条件。
4. 覆盖新 JD 支持/反驳、标准更新、描述自动生效、原成员解释、同批基准、误合并防护、身份结构确认和恢复后的连续读取。
5. 效果、覆盖、未知/部分/失败及成本并列，不能用全部未知、少量演示、合法 JSON 或单一综合分数证明目标成立。
6. 长期运行说明、已知限制、可用范围和契约写回现有正式文档；总计划更新实际完成/未完成状态，临时阶段报告按最近 5 份上限处理。

## ChatGPT 最终审核的通过条件

- [ ] P0 的适用评价条件达到，且有独立中文人工参照；缺失的能力明确未通过，不借其他段通过覆盖。
- [ ] 固定关键语义反例已修复或对应能力被明确限制；限制范围不得被宣传为完整目标已达成。
- [ ] 完整链路与真实语义两类证据都具备，回归、恢复和下游语义没有未解释的退化。
- [ ] 机器描述自动生效与人工/正式状态可区分，正式知识关键操作未越权，原文及历史未被覆盖。
- [ ] 留出用途、标注来源、版本、输入、成本、隐私及未运行项可查，没有结果泄漏或改口径美化。
- [ ] 正式文档、有效导航、资产状态和实际代码一致；最终准确 head 与后续可复现入口明确。

## 未通过时与最终交接

效果不足就按错误类型做定向修复，再用相同口径复评并保留旧结果；若已用留出结果调参，应明确它已成为开发证据并取得新的独立检查。不能用无限追加规则或改目标掩盖局限。

向 ChatGPT 交最终 PR、各段已审提交、完整结果与错误分析、私有证据引用、实际运行说明及遗留列表。最终结论只能来自真实审核；用户授权后由 ChatGPT 合并。B/C 名称、具体模型品牌或某个内部 DB 不是验收成果，产品目的与可验证效果才是。
