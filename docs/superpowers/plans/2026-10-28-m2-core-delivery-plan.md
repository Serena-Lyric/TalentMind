# M2 新底座分段交付计划（结果导向）

> **For agentic workers:** 执行时使用 `executing-plans` 或当时由用户指定的执行方式；每个新工作对话只执行一个获授权阶段，用 `- [ ]` 跟踪结果。此对话仅编制计划，不启动实施。

**Goal:** 让真实中文 JD 能被独立分析、归一化并得到可复核的岗位解释；有价值的工作组合能够持续积累证据、自动演化，并在重大知识结构变化时交人工确认。

**Architecture:** 遵守单条分析、岗位/工作组合比较、候选持续维护三项逻辑职责，保留证据与版本。具体处理器、检索、算法、内部存储和文件划分由实施者按效果选择；此前“结构化语义处理器 + 知识对齐 + 程序验证”是可替换的起点。

**Tech Stack:** 当前基线有 Python、FastAPI、Pydantic、httpx、SQLite 及 Vue 工作台，可评估复用；本计划不强制具体模型、调用顺序、向量库或数据库方案。

**Spec:** [当前产品决策 §3.11](../../PRODUCT_DECISIONS.md#311-新底座最小职责组织与候选管理2026-10-28)、[最小架构设计](../specs/2026-10-28-m2-analysis-candidate-design.md)、[架构设计输入](../specs/2026-10-27-m2-core-foundation-design.md)。

## 1. 本轮授权、计划状态与执行约定

- 2026-10-28 用户要求完整计划写入工作区并提交 master，按对话分段，结果优先，后续由 ChatGPT 审核。本次仅提交文档；P0～P6 均未实施，不将计划提交当作业务能力完成。
- 后续执行者先核对当前 Git、产品决策、实际代码及本表，再读取当前分段与其直接依赖；不依赖旧对话记忆，不因计划存在就自动执行全部阶段。
- 一段包含形成独立结果所需的最少实现、必要验证、文档与提交；不单独为安装依赖、建目录或空接口开一个阶段。段内可持续修复，不重复申请已经授予的常规开发权限。
- 每段经 ChatGPT 审核后更新交接。未通过的关键依赖不能被后段假定完成；非依赖工作可记录为部分结果，不以等待个别事实标注阻塞所有离线工程工作。
- 后续常规开发按 AGENTS 在临时分支提交、创建面向 master 的 PR，ChatGPT 审查并由用户授权合并。本次直接提交 master 的文档授权不扩展为后续代码自行合并授权。

## 2. Global Constraints — 全阶段约束

1. 使用实际输入与版本，保留原始 JD、旧分析和判断依据；输入变化、知识变化、分析器变化、候选演化分别说明。
2. M2 可独立运行，接口语义稳定且版本化；部分结果、未知、未提及、未执行和失败分别表达，下游不能隐式依赖内部表结构。
3. 技能要求五态、程度、任选/全部满足、条件、否定、能力与经验对象分开；技能类别、行业场景和任职条件不混同。未提及不等于不要求，技术使用不自动变成必备或熟练要求。
4. 明确关系、有限推测和未知分开；推测不能通过反复使用或摘要改写升级为招聘事实，不构建完整能力—职责配对矩阵。
5. 工作组合以目标、对象与核心责任为主要依据；候选稳定身份不等于正式岗位或独立招聘职位。
6. 日常关联、证据积累、共同职责、描述、解释及未决原因可自动更新。有证据且仍能解释原组合与成员时自动生效，语义变化本身不触发人工审批。
7. 同批关联使用一致候选版本；修订不反过来自证本批关联，不通过泛化强容纳新 JD。关键合并、拆分、正式归属、新岗位定义确认及正式发布仍需人工确认。
8. 中文真实 JD 是主要语义依据；国内职业标准为参考，国外分类/成绩不能直接充当中国业务标准。B 倾向保留，B/C 未选定；不建设完整职业本体或复杂审批体系。
9. 当前正式后端仅 `backend/app/`，前端仅 `frontend/`；原始数据、人工标注、模型原文回包等私有产物只保存在合规私有位置，不提交真实全文、凭据、数据库或简历。
10. 计划不额外授权外部/付费模型发送真实文本、正式 DB/Neo4j 写入、迁移、真实采集或数据清理；具体权限在需要的阶段核对，不能套用历史授权。
11. 集成测试仅用已核实连接的隔离实例；夹具唯一标记、finally 清理并确认残留为 0，不按 source 等宽泛删除。纯文档任务不运行应用、DB、模型或采集。

## 4. Review Focus — 五类必须落到阶段验证的风险

| 输入/条件 | 合理预期与验证归属 |
|---|---|
| 中文开放任选、程度否定、跨栏目作用域、重复正文、短 JD | 不误升技能、不丢选项和上下文、不重复制造事实；P1 的具体用例与 P6 留出检查 |
| 同标题/同技能但责任不同，或同责任但技术栈不同 | 不按名称/工具错误归类；检索漏召回与比较错误分开；P2、P3 |
| 目录为空、定义未覆盖、候选标准未确认 | 有效事实仍可用；缺口不等于排除，不伪造正式岗位；P2 |
| 相似链条、次序变化、反证、同批摘要更新、描述逐步泛化 | 不靠传递相似强合并；自动修订保持证据与原成员解释，不能自证；P3、P4 |
| 模型截断/超时、停止、进程退出、标准变更、迟到响应或恢复 | 区分未完成/失败，保留已提交结果和真实版本，不覆盖历史或显示错 run；P1、P5 |

## 5. 验收以结果为准，方法可以替换

- 实施者可更换算法、调用次数、模块内部组织与持久化实现；在阶段报告中说明选择、比较依据、效果、成本与局限。合理替代方案不因偏离此前技术建议而被否决。
- B/C 名称仍未定，不阻塞已确认共同能力的分段交付；遇到真正改变产品的选择，再提交具体问题，不为抽象方案命名停工或擅自替用户定案。
- 对外语义、证据边界、受控正式知识状态等产品约束必须保持。若要不兼容变更契约、变更产品范围或扩大真实数据权限，先说明影响并取得相应决定，不偷换目标。
- 每段开始先界定实际输入、预期行为和失败案例，再实现或复用最少内容，并验证实际执行路径。对业务行为应有有意义的回归；不为纯文档/空壳写镜像测试，不强制某一种测试框架或内部函数签名。
- P0 必须冻结各指标的定义、适用样本、分母、目标/判定方式和确认来源；不能看完 P6 结果再降低门槛。当前没有获确认的统一百分比，本计划不捏造精度阈值。
- 语义覆盖/漏提和误判都要评价；全部返回未知不能靠“没有确定性误判”通过效果验收。确实模糊的原文应允许未知，不能为了覆盖率伪造确定性。
- 具体审核和证据要求统一见 [分段交付审核标准](../specs/2026-10-28-m2-delivery-review-standard.md)，不在各阶段复制整套规范。

## 6. 新对话的最小阅读包与交接

每段只需：本计划 §1～§6、当前分段文件、审核标准的相关项、该段直接依赖的已审结果与产品决策相关节。再按实际改动读取代码和对应陷阱，不要求重读整个仓库或所有旧报告。

阶段开始交接应具备：

- 当前分支/基线 SHA、当前获授权段，以及总进度表中的前段 PR、已审 head、审核出处、实际合并 master SHA 和阻塞项。
- 实际契约版本、输入/知识/标注清单引用和摘要、所需权限；私有文件不存在时如实说明，不以另一份文件偷偷替代。
- 需复用的已实现入口与已知失败；当前段尚未完成什么。

阶段结束交接应具备：

- 实际提交/PR、入口、测试命令/环境/退出码与结果；明确模拟、合成、真实、人类参照及未运行部分。
- 本段目标逐项证据，失败/未决分母、必要错误案例和私有产物引用；不能只写“测试全绿”。
- 与原方案不同的实现选择及理由；影响后段的真实接口、版本和风险。
- ChatGPT 审查待办或结论，下一段是否具备依赖；只在总进度表更新状态、PR、提审/已审 head、审核出处、合并 master SHA 与阻塞项，并同步资产摘要，不在分段页复制运行状态，不自动启动下一段。

供后续新工作对话使用的指令：

> 执行 M2 分段计划 Pn。本轮只完成该段，先读总计划、Pn 和审核标准，核对已审依赖与授权。以可验证结果为准，内部方法可调整，勿扩大产品/数据边界。完成后提交独立 PR、提供真实验证证据和交接，供 ChatGPT 审查，不自行合并或自动启动下一段。

## 7. 审查记录与报告数量

开发时在 `docs/review/` 维护当前阶段临时报告，提交到该阶段 PR；全仓阶段报告最多 5 份。新报告需要淘汰旧报告时，先将长期规则/使用说明/陷阱写回正式文档，保留 PR/commit 审查证据，再移除过期报告及其独有公开附件，并修正活跃链接；不转存 archive 规避上限。

该规则不授权清理私有 JD、标注、历史分析或数据库。私有可复核证据的保留与可访问性单独记录，公开报告删除后仍应能由审查引用定位。当前计划编制不新增验收报告、不删除既有报告。

## 8. 范围与参考实现入口

参考现有 `backend/app/job_analysis/`、`backend/app/skills/`、`backend/app/routers/m2.py` 与 `frontend/src/api/m2.ts`。当前基础层的输入、版本、恢复可评估复用；旧 FactClaim/B2 规则结构和固定编排不能直接当作新语义契约。

各段列的是需要调查的现有文件和应交付的职责，不是强制新增文件清单。真正落地时在当前段报告记录实际文件/接口及必要验证，防止为了遵守计划制造重复源码或空层。

本计划与旧 [M1→M3 真实验证计划](2026-10-20-staged-m1-m3-real-validation.md) 分别服务不同范围；旧文件中的采集次数、旧 B1/B2 技术限定或历史授权不作为本次重新授权。M1 采集、正式图谱发布、M4 匹配改造和全新 UI 不在本计划核心交付中。

计划编制自检：P0～P6 已覆盖单条语义、知识、岗位、持续候选、自动演化、受控正式变化、独立运行、版本恢复和中文效果；上述五类风险都有负责阶段。此自检不是实施验收。
