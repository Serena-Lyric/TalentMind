# 模块外发-回发协作闭环（Roundtrip）方案

- **日期**：2026-08-14
- **负责人**：A（唯一集成者）
- **背景**：5 人 5 机，M2/M3/M4/M5 由四位开发者在自己电脑上开发、打包发送到 A 机；A 负责打通模块连接、统一集成。本方案解决：打通后如何把修改回发、队员如何继续二次开发、如何防止版本覆盖与依赖缺失。
- **配套**：`docs/superpowers/plans/2026-08-14-remediation-plan.md`（系统修正 v2：裁决/契约/缺陷看板/中英文统一）；`笔记.md` 第八/九/十节。

## 一、协作模型与核心风险

```
队员本地开发 → 打包回包 → A 导入集成/打通连接 → A 回发修改版+问题+要求 → 队员二次开发 → 再次回包 → A 验收
```

三大风险（本方案逐一设防）：

| 风险 | 表现 | 对策 |
|---|---|---|
| 版本覆盖 | 队员基于旧版本继续开发，回包覆盖 A 的修改（如 skill_dict 约束、canonical 化） | A 修改文件清单 + 版本号 + 验收 diff 门禁 |
| 依赖缺失 | 队员看不到真实数据，只能 mock，联调返工 | 随包附「依赖数据快照」（A 集成库权威数据） |
| 契约漂移 | 队员按旧契约/旧设计开发，回包又产生偏差 | 契约包（ddl.sql/schema/接口文档/中英文规则）+ schema 校验器 |

## 二、五步闭环（一个迭代周期）

### Step 1：A 打通连接（本地，可立即开始）

- 数据流打通：M1 jd_pool → M2 产出 → M3 graph.json → Neo4j → 20 API → M5 六页（已基本完成）。
- 本轮打通增量（修正方案 P0/B1–B7）：
  1. `validate_exchange.py` + schema（B3）：交接文件机读校验，成为回包验收第一关；
  2. 中英文统一字段（L1–L8）：job_definition 加 `job_name_zh`、job_skill 英文 key、API/图谱中文展示；
  3. change_type 扩容（B2，通知后执行）；
  4. import 白名单化（B3），修复后的模块代码即「回发基线」。
- 产出：可运行全链路 + 每模块「A 修改版代码」+ 联调证据（导入日志/API 返回）。

### Step 2：A 回发（每模块一个包）

```
回发包/<模块>-v<版本>/
├── 模块代码/          # A 修改后的该模块（可独立运行：代码+依赖+run 说明）
├── 依赖数据快照/      # A 集成库权威数据（M2 产出、skill_dict、graph.json、API 返回样例）
├── 契约/              # ddl.sql、交接 schema、接口文档、中英文统一规则（本模块相关）
├── 问题清单.md        # 本次发现的该模块问题（严重度 + 证据）
├── 要求清单.md        # 二次开发任务（优先级 + 验收标准 + 截止时间）
├── 联调证据/          # A 验证结果（导入日志、API 返回、截图）
└── README.md          # 版本基线、A 修改文件清单、回包要求、本地运行方式
```

回发要点：
- **A 修改文件清单**写入 README（如 M2 `stage3_extract.py` 加了 skill_dict 约束、M4 `matcher.py` 加了 canonical 化），队员不得回滚；有疑问先问 A。
- **依赖数据快照**必须发：M3/M4/M5 队员本地没有真实数据，用快照联调，不再 mock 空转。
- **A 的集成层（import_exchange/validate_exchange/routers）不属于任何模块，不发**；只发契约与 schema。

### Step 3：队员二次开发

- 只改自己模块；以「A 修改版」为基线，不另起炉灶；
- 用快照数据本地联调；遵守契约与中英文规则；
- 完成任务按要求清单自测（含新交接产出的 schema 校验）。

### Step 4：队员回包

```
回包/<模块>-v<版本+1>/
├── 模块代码/          # 修改后代码
├── 交接产出/          # 新 json（M2/M3 必交；M4/M5 按约定），带版本头
├── 变更说明.md        # 自上次回包改了什么、为什么、涉及哪些文件
├── 测试结果.md        # 本地单测/集成结果
└── 问题反馈.md        # 需要 A 或其他模块支持的事项
```

### Step 5：A 验收集成（门禁 4 关）

1. **schema 校验**（validate_exchange）：字段/类型/枚举/关联/版本头；
2. **diff 检查**：A 修改过的文件未被回滚（被回滚 → 打回并附 diff 证据）；
3. **模块单测 + 集成测试**（含非空样例）；
4. **导入 + 前端冒烟**（真实数据）。
验收通过 → 更新资产状态，进入下一里程碑；不通过 → 新问题清单随下一轮回发。
