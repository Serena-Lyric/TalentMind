> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `backend` 容器在 Ubuntu 24.04 上通过 Microsoft Edge for Linux + Xvfb + noVNC 运行现有 CDP 采集引擎，并用 Linux 进程组/`/proc` 证据替代 Windows Job Object，保持失败关闭。

**Architecture:** 继续使用 `backend/app/collect/browser.py` 与 `runtime/` 单一引擎，不引入 Playwright。Linux 进程发现用 `/proc` + `/proc/net/tcp*`；worker 以独立 session（pgid=pid）归属整棵树；镜像内置 Edge/Xvfb/x11vnc/noVNC，noVNC 只发布到宿主机回环。采集仍只按模块入口和频率门禁执行。

**Spec:** `docs/superpowers/specs/2026-11-17-issue81-ubuntu-deployment-design.md` §6；交接 `data/local/issue81-handoff-20261118.md` 阶段 1。

**Base:** `codex/issue81-p1-deploy` @ `d74496c`。分支 `codex/issue81-p2-m1-linux`。PR 基分支为 P1 分支（stacked），不合并。

## Global Constraints

- 只在 Linux 分支新增行为；Windows Job Object 路径不得退化（现有 `test_collection_worker_process.py`、`test_collection_runtime_*` 继续通过）。
- 无法核实进程/监听/进程组时 fail closed：抛错或拒绝复用，不按 PID 猜测。
- 只接受回环 CDP 监听；动态端口与 `DevToolsActivePort` 逻辑保留。
- noVNC 只允许 `127.0.0.1:6080:6080`；MySQL/backend/其他服务不新增公网端口。
- 容器烟测不访问真实招聘站，只用 `about:blank`/本地页；不触发采集、不连接正式库。
- 不迁移 Windows Edge 档案/Cookie；服务器登录态由负责人人工建立。
- 单函数不超过 200 行；Bash `set -euo pipefail`。
- 测试输出重定向到临时文件，只读尾部；不把 `data/`、密钥、Cookie 加入 Git。

## Review Focus

1. **PID 复用误杀**：Linux 恢复 worker 必须同时校验 `/proc/<pid>/stat` 的 starttime；不匹配即视为已退出，不向复用 PID 发信号。
2. **进程树逃逸**：worker 以 `start_new_session=True` 启动，pgid=pid；停止时先 SIGTERM 进程组，超时 SIGKILL，仍无法确认则 `collection_worker_termination_unknown`，lease 不释放。
3. **进程发现降级**：`/proc` 或 `/proc/net/tcp` 不可读时 `_edge_sessions` 抛 `CdpError`，不得返回空会话冒充“没有 Edge”。
4. **日常档案误用**：Linux 拒绝 `~/.config/microsoft-edge`、`~/.config/google-chrome`、`~/.config/chromium` 及其子目录。
5. **noVNC 暴露面**：compose 仅 `127.0.0.1:6080`；P1 的“backend 不发布端口”断言更新为“唯一发布为回环 6080”。

**Interfaces:**

- `parse_proc_net_tcp(text: str) -> dict[int, tuple[str, int]]`：只保留 `st == '0A'` 的行，返回 inode → (address, port)。IPv4 小端十六进制；IPv6 按 32 位小端还原为 `ipaddress.IPv6Address`。
- `linux_edge_sessions(proc_root: Path | str = '/proc') -> list[dict]`：遍历 `proc_root/<pid>`，读 `cmdline`；要求同时有 `--remote-debugging-port=`、`--user-data-dir=`，且无 `--type=`；用 fd 的 `socket:[inode]` 与监听表匹配；返回 `{pid, profile, port, listeners:[{port,address}]}`。`cmdline` 为空/不可读的条目跳过；监听表不可读抛 `CdpError`。
- `edge_launch_argv(executable: Path, profile: Path, initial_url='about:blank', *, linux: bool) -> list[str]`：公共参数 `--remote-debugging-port=0 --remote-debugging-address=127.0.0.1 --user-data-dir=<profile> --no-first-run --no-default-browser-check --disable-extensions --new-window <url>`；`linux=True` 追加 `--no-sandbox --disable-dev-shm-usage`。
- `_edge_sessions()`：`sys.platform.startswith('linux')` → `linux_edge_sessions()`；Windows 原 PowerShell 分支不变；其他平台抛 `CdpError('当前自动启动仅支持 Windows/Linux Edge')`。
- `_launch_edge`：Windows 候选不变；Linux 候选 `/usr/bin/microsoft-edge`、`/usr/bin/microsoft-edge-stable`、`/opt/microsoft/msedge/msedge`，再 `shutil.which('microsoft-edge'|'microsoft-edge-stable'|'msedge')`；Linux 不传 `creationflags`，不新建 session（保持 worker 进程组）。

## Task 2: Linux 进程组与 `/proc` 归属

**Files:**
- Modify: `backend/app/collect/worker_process.py`
- Modify: `backend/app/collect/runtime/scheduler.py`
- Modify: `backend/app/collect/runtime/lease.py`
- Create: `backend/tests/test_m1_linux_process.py`

**Interfaces:**
- `worker_process.group_alive(pgid: int) -> bool`：`os.killpg(pgid, 0)`；`ProcessLookupError` → False；`PermissionError` → True；其他 OSError 原样抛（fail closed）。
- `worker_process.stop_process_group(process, timeout=10, *, killpg=os.killpg, clock=time.monotonic, sleeper=time.sleep)`：SIGTERM 组 → 等 leader → 轮询 `group_alive` → 超时 SIGKILL → 仍存活抛 `TimeoutError('采集子进程树停止超时')`。
- `spawn`（POSIX）：`start_new_session=True`，设置 `process._collection_pgid = process.pid`。
- `stop`（POSIX）：调用 `stop_process_group`；`close` 无操作。
- `scheduler.parse_proc_stat(text) -> tuple[str, int] | None`：以最后一个 `)` 分界，取 state 与第 22 字段 starttime（`fields[19]`）。
- `scheduler._process_creation_time`：Linux 返回 starttime；其他非 Windows 返回 None；Windows 不变。
- `scheduler._pid_alive(pid, created_at)`：Linux 读 `/proc/<pid>/stat`；缺失/`Z`/`X`/starttime 不匹配 → False；Windows 原路径；其他 POSIX 回退 `os.kill(pid, 0)`。
- `_PidProcess(pid, created_at, job=None, pgid=None)`：`poll` 在 POSIX 下 leader 已退出但 `worker_process.group_alive(pgid)` 为真时仍返回 None；`terminate`/`kill` 在 POSIX 调用 `worker_process.stop`。
- `_pid_process(..., pgid=None)`、`_restore_processes`、`_process_payload`、`_PROCESS_META`、`_bind_worker_lease` 读写 `pgid`；Linux 默认 `pgid = pid`（`start_new_session` 的构造保证）。
- `lease._payload`/`rebind` 增加 `pgid`；`_owner_tree_alive`：worker owner 的 leader 死亡后，POSIX 用 `pgid` + `group_alive`；pgid 缺失/非法 → None（fail closed），非 worker owner → False。
- `_stop_process` POSIX：`worker_process.stop` 后若 `group_alive(pgid)` 仍真 → `collection_worker_termination_unknown`。

**Steps:**
- [ ] 先写测试：带空格/括号的 comm；starttime 匹配/不匹配/僵尸/缺失；`group_alive` 三种异常；`stop_process_group` 成功、SIGKILL 后仍存活抛错；lease payload 含 pgid、worker owner 树存活矩阵、pgid 缺失 fail closed。
- [ ] 运行新测试确认失败。
- [ ] 实现，保持 Windows 分支逐字不动。
- [ ] 跑 `tests/test_m1_linux_process.py tests/test_collection_worker_process.py tests/test_collection_runtime_scheduler.py tests/test_collection_runtime_lease.py tests/test_collection_runtime_browser.py`，全绿后提交 `feat(collect): own Linux worker process groups`。
