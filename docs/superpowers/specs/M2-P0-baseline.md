## 1. 输入、成员与材料边界

私有根目录为主仓 `data/local/m2-p0-20261028/`，不在临时工作树中。`manifest.json` 为唯一成员索引，`files` 绑定所有列入清单的私有产物原字节 SHA-256。输入身份、原始来源 URL、SQL 存档行定位、文件摘要、内容版本、观察时间、选题理由与历史暴露记录逐样本保存。完整快照在 `snapshots/`；原始历史文件不移动、不修改。找不到指定路径或版本时失败，不静默改读数据库或新文件。

| 集合 | 数量/用途 | 来源与限制 |
|---|---|---|
| `DEV-01`～`DEV-08` | 8 条开发、标注说明与后续错误定位 | 从中文历史 ZIP 中明确定位原 SQL 观察；均与历史 120/60 有身份和正文重合，重新选题，不继承旧预测或旧标签 |
| `HOLD-01`～`HOLD-04` | 4 条本轮预留检查 | 与开发集及历史 120/60 无已检测身份/规范化正文重合；仅检查身份、来源及字节，不用其预测调优 |
| 合成案例 | 公开、工程边界回归 | 不进入真实语义分母；不宣称市场代表性或人工真值 |

历史 ZIP `chinese-jd-archive.zip` 的字节摘要为 `068935e3fbafbeb4218510cfdfab586c45075761f836e679ff6bff1ce25c4a8d`，包含 3,573 种字段内容表示，不能解释成独立职位数。选择的来源是其中 `sources.jsonl` 的历史 SQL 文件，而非列表卡或分析回包；每条保留全部已知历史出现位置。原文存在不证明来源身份已经认证，未附身份签审的记录保持 `not_attested_in_this_snapshot`。可用于中文文本理解参照，不用于确认独立招聘需求或市场规模。2026-10-28 用户授权本轮离线复用；第三方全文公开再分发未获授权。

泄漏检查使用分析契约的 namespace+jd_id（来源另存），以及正文 NFKC、空白、大小写归一；已知“职位描述”前元信息和“公司简介”尾部不参加正文匹配。重复/同职位各版本作为同组处理，不能跨集合。该检查不能发现所有近义改写、跨平台同职位或历史模型暴露；`leakage-audit.json` 明示限制。4 条留出仅称“本轮预留”，不声称此前从未被看过。成员/分组调整必须另存新版本及理由；查看留出预测并据此改算法、提示或知识后标为已暴露，不再作为独立留出。

## 2. 人工参照及 ChatGPT 复核

本轮用户答复“由我本人负责”，指定负责人本人承担实际复核；未提供实名，用该自述身份记录。另答复“允许”，允许必要中文摘录及标签通过本聊天提供给 ChatGPT。该许可不允许公开 GitHub 上传 JD 全文，也不扩展到第三方模型或付费调用。

每条 `annotations/<sample>.json` 的 `human_labels`、`human_added_omissions`、`disputes`、`review_events` 独立于 `drafts/`。待审时实际审核人、审核时间、确认来源留空；分配复核人不等于已签审。Agent 可在 `drafts/` 写候选解释和问题，不能复制进人类标签。

复核顺序：

1. 核对样本 ID、输入摘要和完整冻结原文，先独立通读并补齐全部职责、目标、对象和要求，允许新增机器完全漏掉的单位。
2. 每个标签记录 `unit_id`、维度、结论、原字段及 `[start,end)`/引文、理由、适用范围；多种合理答案列为可接受集合，真正模糊处允许未知。不得把工程失败标为语义未知。
3. 对照 Agent 草案补记接受、修改、拒绝及遗漏；争议保留双方依据。只审某几个陈述时设 `partial` 和具体 scope，不声称完整召回。
4. 完成后追加实际复核事件：审核人、ISO 时间、确认消息/材料位置、所见输入版本、修改和争议处理。修改产生新文件/清单版本，保留旧版；不得覆盖冻结包。人类事件是可核查自述，不是身份认证。
5. ChatGPT 先读固定 PR head 和公共合成例，再通过获准聊天材料查看对应原文、逐标签和错误对照。摘录不足以判断否定、条件或遗漏时补足上下文；不能查看完整原文时只评价摘录范围。

当前实际人工标签为零；已指派但未执行。哈希、私有路径、Agent 自检或 ChatGPT 代码审查均不能替代逐项人工参照。岗位定义的正式准入与 JD 标签审核另行记录。

## 3. 评价口径（定义可复用，业务通过条件待确认）

评价单位绑定样本/输入版本、知识定义版本、人工标注版本和预测分析版本。人工 `unit_id` 为对齐依据；先由人或可审查的匹配表确定预测与参照的一对一匹配，不用模型自评、宽松同义字符串或重复预测充当 TP。可接受改写/拆分/合并需记录配对理由。重复陈述合成一个语义单位，跨字段副本不增加真值；有不同条件/程度/对象的要求不能合并。错误可多标签归因，不把各错误数量相加成统一准确率。

| 指标 | 对象、分母及计算 | 未知、未完成与失败 |
|---|---|---|
| 职责/技能提取 P/R | 分开统计：P=正确匹配的预测单位/全部输出单位；R=匹配的人工单位/全部人工参照单位；另列 FP 误提、FN 漏提 | 完整 R 仅用独立通读的完整人工标注；未审核项目列未决，不当负例。不确定匹配列区间下界/上界及待定数；零分母为 null |
| 要求语义错误率 | 在已匹配且人工已判定的要求单位中，五态、对象、程度/否定、条件、组合/开放集合分别列错误数/各维度已判定单位数 | 人工允许未知单列为“合理未知”；机器对明确答案给未知计漏答，不按正确；机器失败列执行失败，不编 uncertain |
| 证据位置/身份错误率 | 无法精确回源的引用数/全部输出引用数；按字段、代码点偏移、输入版本、身份分别归因 | 缺证据的事实另计缺失数/全部输出事实；引文匹配通过不证明语义正确 |
| 能力—职责关系 | 明确、推测、未知分别列混淆表；明确误报/全部明确预测；正确明确召回/人工明确关系；另列推测被升级的次数 | 未生成矩阵不产生负例；缺记录=未主张。只对人工明确评估的稀疏关系与遗漏计数；全未知不能达到明确关系召回要求 |
| 岗位判断及解释 | 判断错误/已审核比较项；支持职责、未覆盖职责、真实冲突、证据不足原因分别逐项核对；候选冒充正式单列计数 | 不完整目录的未覆盖不算排除；比较对象范围必须显式，不能从少量候选宣称全目录排除；允许人工认可的 unresolved |
| 候选检索召回 | 检索到的人工相关候选数/人工相关候选总数，绑定固定候选池/版本与检索上限 | 未运行检索不可报 0；人工相关集合不全则不能声称全库召回 |
| 给定候选后的关联 | 固定给定候选列表中误关联数/全部确认关联；漏关联数/人工应关联数；JD职责子集是作用范围 | 与检索漏召回分开，身份重复不增加独立支持证据；无人工配对不计算 |
| 跨批演化与稳定性 | 逐个已签审序列：原成员仍可解释、反证处理、是否过度泛化、同批版本、自证和变更理由；通过序列数/已审序列数 | 顺序一致性本身不证明正确。标准、输入、分析器变化分别归因；真实未审序列不可用合成结果补分母 |
| 可用性与覆盖 | N 为本次选中全部输入；完成/部分/未执行/失败互斥计数，相加=N；各能力另列覆盖，明确应答/人工可判定单位 | failed、不完整、没有识别结果、语义未知分别计数。语义已判定样本的分析失败仍产生 FN/漏答，不从总分母删除；同时报告成功子集供诊断 |
| 延迟与费用 | 实际执行的次数、总耗时、每条延迟（样本很少时逐条列，不做稳定分位数推断）、真实账单/用量 | 未调用模型时为 not_run，不能把离线校验耗时或旧配置价格冒充模型成本/能力 |

共同规则：未审核材料不进入真实准确率分母，但必须报告样本覆盖、未审单位、排除原因、部分标注范围、争议和执行失败。只做部分审阅时可以评价该部分，不能扩大到整份 JD。人工数量为零时语义指标不可计算，不记作 0 或 100%。后续评价工具须把未知/失败/未审分开；本段不实现 P1/P2 分析器或完整评分引擎。

### 3.1 待负责人选择的通过方式

- **建议 A：少量样本逐例签审。** 对每个已审案例冻结“必须识别的单位、允许未知的范围、可接受解释和禁止错误”，所有必检案例达到其明确条件，且无审核标准 §4 的未处理反例。对当前小规模、长尾且真值仍为零的材料，比未经校准的统一百分比更容易解释。不能只验证“没误报”，还须逐例检查应提取事实与关系的漏项。
- **备选 B：补足各维度独立人工参照后制定数值门槛。** 先展示每类正例、负例、歧义和失败的实际分母，再由负责人/业务评价者批准各项精度与召回目标。当前不提出没有样本依据的 90%/95% 等门槛，也不从模型分数推概率。

两种方式均尚未获通过条件签审；用户指派复核人与允许材料查看不等于认可 A 或 B。定义修订、成员变化、人工修订和通过标准确认分别留版本与确认来源。P6 观察效果后不得悄改本口径；改变时保留旧口径结果、理由、新批准及新的独立评价材料。

## 4. 最小契约及实际入口

[Pydantic 模型](../../../backend/app/job_analysis/baseline/contract.py)为可执行表达；[公开合成实例](../../../backend/app/job_analysis/baseline/examples/analysis.json)演示开放任选和 Redis 使用关系，不含真实 JD。[包说明](../../../backend/app/job_analysis/baseline/README.md)给出命令。`Analysis.model_json_schema()` 可导出结构描述，无须增加 Schema 依赖或数据库。

| 类别 | 最小表达与读取语义 |
|---|---|
| 输入/来源/证据 | `namespace + jd_id` 与 `input_version/input_sha256`，完整 `input_row` 保留来源及已提供字段；复用 InputRecord 完整指纹，不把观察时间算内容变化。证据须精确匹配同身份/指纹/字段的 Python Unicode 代码点半开区间，JS 使用者必须转换 UTF-16 偏移 |
| 目标、对象、责任、要求 | `Claim.kind` 分开，`core=null` 表示未知核心性；核心性解释在 reason，不按标题/篇幅猜测。每条 claim 有原文；缺某类结果结合 coverage 判断，不能把空列表当失败或不要求 |
| 五态及逻辑 | `Requirement.state` 沿用五态；target/category 分开任职条件和技能；members 保留原词。`single/any_of/all_of/unresolved`、`open_set`、degree/degree_polarity、condition 与 scope_evidence 分离。状态作用于该陈述/组合，不自动分派成员独立必备；独立要求另建 claim；复杂嵌套无法可靠表达时保留原文及 uncertain/unresolved，不强建逻辑树 |
| 规范化 | `alignments` 绑定原成员；unknown 保留原词且不能伪造 canonical ID；已知映射绑定知识版本及 test/candidate/formal 性质。知识条目是否属于该版本仍须下游读取实际知识校验，摘要不能认证语义/准入 |
| 能力—职责联系 | 稀疏 Relation 的 explicit/inferred/unknown、局部端点、上下文和理由；不生成完整矩阵。推测不可凭复用升级；结构验证只检查引用，不能判自然语言关联正确 |
| 质量/失败 | 六维 coverage 必填 complete/partial/not_run/failed，outcome 与其一致。部分结果保留可用 claims；机器结果 semantic_review 固定 machine_unreviewed。真实人工事件存在单独标注文件，不允许分析器自述已人审 |
| 岗位解释 | role_judgments 带具体参照版本、知识性质、已覆盖/未覆盖职责 ID、冲突及理由；结论 supported/unresolved/not_supported。空参照目录合法，未比较不伪造目录排除。推测不可单独作正式归属依据 |
| 版本/候选性质 | analyzer、model、prompt、configuration 及实际 knowledge 显式 ID/revision/SHA-256；无知识时 knowledge=[]。工作组合候选身份不是岗位知识准入；本段不建候选服务，跨批版本约束由后续阶段实现 |

本契约为新底座的新增边界，不改变旧 `FactClaim`、DDL、旧 API、前端或交接文件。P1/P2 后续可直接验证输出；接入旧存储/接口时须显式适配并标明损失，不能静默压成必备/加分二态。当前只验证结构、引用和部分一致性，不证明算法/中文语义正确，不建立正式知识审批流程。其工程字段/版本随本 PR 提审，未冒充负责人对具体正式契约的最终签审。

## 5. P2 最小岗位参照与知识使用

[两条来源支持的候选参照](../../../backend/app/job_analysis/baseline/role-references.v1.json)描述程序设计工作与信息通信网络运行工作，均 `candidate`、`approval_source=null`。含目标、核心责任、适用范围、未定边界、来源 URL/PDF 页码、下载字节摘要与本地定义版本；可用于覆盖、缺口与边界测试，不能发布为正式职业目录。

程序设计参照来源为上海市软件行业协会发布、上海市职业技能鉴定中心指导编写的三级认定指导手册；网络运行参照来源为人社部/工信部国家职业技能标准的官方 PDF。实际下载字节保存在私有包 `public-sources/` 供复核，不提交整本文件。不假设页面发布日期就是文档独立版号，也不宣称所选固定版本是当前最新法规/职业边界。职业标准用于参考，企业 JD 事实仍以本条原文为准，来源国家职业编码不强制对应某个市场岗位。

现有 285 条技能词典可只读复用，已核对实际条目数及字节 SHA-256 `0e1af59aa1622c3c6b9d1ee67259a822ac2a615317916e30a10ebcf3f995e3ad`；本段不新增/修订正式词典。现有 B3 的 19 个候选定义与空正式目录保留原状态，不因本次有来源参照而自动正式化。国外分类或英文成绩不作为中文验收标准。
