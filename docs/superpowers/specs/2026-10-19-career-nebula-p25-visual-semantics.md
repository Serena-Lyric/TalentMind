## 一、用户已确认的产品规则

1. **业务类型优先于装饰恒星类型**：岗位（Job）、技能（Skill）、历史场景（旧 `Industry` / `scenarios` 投影）要分别拥有一套**稳定、直观可区分的节点主体视觉类型**。不能只给它们随机分配红巨星、白矮星等主体外观，再靠很小的外部标记表达岗位/技能/场景。旧场景标识是对历史输入的暂时展示，不表示 2,457 条记录已通过场景或行业语义审核。
2. **控制色彩与明暗主次**：P2.4 中高饱和、过亮的红橙色恒星形成一层独立点阵，压过蓝紫银河星尘；下一版需明显降低红橙点的视觉抢占，保证知识节点可辨认而不是另造一张显眼点阵。
3. **控制局部拥挤**：中近景局部节点密集时出现大量重叠光盘，需降低高密区的视觉占用与光晕相互覆盖，使节点仍可定位、选择和查看，不能以删改知识事实解决。
4. **星体融入银河**：现有星尘过渡未完全解决知识星体与旋臂视觉脱节、尾部漂移的观感。要在色彩、辉光、细尘/过渡层及空间观看体验中协调两层；保留原银河主体、相机与确定性知识布局，不靠伪造语义关系或任意移动业务节点来使构图好看。
5. **关系线统一采用端点颜色渐变**：默认仍隐藏；选中节点后呈现真实直接边。可见关系线由**一端节点的主视觉颜色渐变到另一端的主视觉颜色**，去掉常态菜单里旧的实线/虚线/多线段类型图例。关系的实际类型（岗位—技能、岗位—历史场景、历史 RELATED_TO 等）、方向、原边和来源索引仍在详情和交互中明确表达；新渐变只是视觉表达，不能模糊知识关系的事实身份。
6. **保留已确认的交互和数据边界**：未选中时无历史连线；选中/取消/改选不使其他本来可见的星体消失；真实关系完整保留并可逐边检查；镜头环绕、WASD、Q/E 滚转、主动“定位全部关联”、相机完整返回和旧版回退继续有效。

上述确认来自用户对 P2.4 真实截图的直接反馈和后续“先把决策写入仓库”的授权。**不是**用户已逐项批准以下工程实现建议、具体数值、配色表或任何算法质量结论。

## 二、P2.5 可自主验证的实施建议（非固定产品裁决）

- **三类主体视觉**：在现有蓝/绿/紫知识色彩约定基础上建立三个各具主体外观的恒星 archetype（例如岗位更稳定、技能更紧凑、历史场景更柔和），实际色值、光圈、纹理、尺寸由同条件截图验收；保留色盲/低亮度下的形态辨识。高饱和红橙可以降饱和或仅用于少量次级装饰，不作为大量节点的默认主类型。
- **原四种恒星原型**：P2.4 蓝白、红巨星、白矮星、脉冲星留为历史视觉证据或可选次级表面细节；**稳定 ID 随机分配不再决定节点的一级主视觉类型**。是否保留特定天体名称或少量特写效果由效果决定。
- **屏幕空间密度感知**：考虑分辨率、相机距离、可见节点邻域的投影密度，对非选中节点逐步压低 halo/点径/叠加透明度；选中、悬停、搜索命中对象保留识别与拾取优先级。用连续函数，避免缩放跳变与闪烁；正常 LOD 的可见数变化须可解释。
- **节点-背景协调**：可以微调局部过渡星尘的亮度/颜色/密度或 shader 参数以减少冲突；不擅自修改 `exchange/m3/graph.json`、P2.1 布局文件、社区结果或知识坐标，不重做大型全景旋臂。
- **关系渐变**：真实边保留独立 `sourceIndex`，顶点颜色沿线插值；端点用对应**业务类型**主色，保持实际 `source/target` 次序，选择与 hover 高亮可以提升亮度/透明度；原边样式与语义分离。默认隐藏历史边、候选派生层默认关闭。删除常态旧线段图例，但保留可读的文字关系类型与完整来源。

实现方法不是用户逐项授权的算法参数；只要遵守产品目标与数据约束，可选择更适合的 ShaderMaterial、批量 Points、cache 或 GPU 方案。不得把性能优化当作修改知识事实的理由。
