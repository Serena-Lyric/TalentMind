## 1. 核心目标与范围

输入一条合法的真实中文 JD，理解其工作内容、能力与任职要求，给出有依据的岗位归属判断；无法归入时，解释原因、保留有效分析结果及有研究价值的工作组合候选。之后能利用新证据重新判断，并解释结论为什么改变。

继承 [2026-10-27 设计输入](2026-10-27-m2-core-foundation-design.md) 的结构化、模块化、可替换、独立运行、稳定且版本化的对外契约，以及知识、标准和分析能力均可更新的约束。单条分析不以岗位命名成功为前提，也不以 M3、前端或完整正式目录为前提。

初版以现有中文招聘信息和当前小规模增量为背景。职责、技能与学历年限等对象分开；五态、程度、任选、否定、条件和冲突继续按产品规则表达。保留原始输入与实际使用版本，聚合或人工判断不覆盖原文及旧分析。

本设计不建设完整职业/任务本体、全球任务编号、技能与职责的全量配对网络、每日全量重聚类或复杂审批权限系统。真实需求率、独立职位统计和完整市场演化分析不由候选数量推导。

## 2. 已确认边界与建议的地位

- 已确认产品要求集中维护在产品决策 §3.11，既有事实、证据、隐私及正式准入规则继续有效。
- 共同职责可依据新证据自动修订并成为后续比较基准，无须人工接受；这是本轮已确认原则。本文的具体检索与比较流程、记录组织、版本实现方式和评价设计仍是 Agent 的候选技术方案，供负责人整体审阅。
- 模型、算法、阈值、正式 API/JSON Schema、表结构与迁移均未由本次对话定案。旧阶段的模型优先、确定性规则优先、SQLite 和四阶段编排不自动成为新底座的长期唯一选择。
- 对话确认职责组织适合当前体量，不代表真实准确性已获验证、具体岗位条目已获批准或已有运行系统已被替换。

## 3. 最小职责组织

三个逻辑职责共享输入、知识版本和质量约束；不要求三个服务、三个模型或严格串行的调用链。

| 职责 | 输入与职责 | 产生的结果 |
|---|---|---|
| 单条 JD 分析 | 基于实际输入理解工作目标、对象/交付物、职责、能力及任职要求；已知概念归一化，未知表达保留；按需提取有依据的明确关联 | 可部分完成的版本化分析记录，包含原始陈述、证据引用、覆盖与不确定性 |
| 岗位与工作组合比较 | 对照可用岗位标准、历史 JD 和工作组合候选，比较核心责任及未覆盖原因；必要时使用有上下文理由的有限推断 | 可复核的归属/关联判断、相邻候选比较、共同职责重新归纳，以及归类解释和未决原因更新 |
| 候选持续维护 | 保存稳定候选身份、分析记录关联、当前假设及简短判断历史；自动应用有依据且仍能合理解释原工作组合的职责修订，处理人工确认的关键结构变化 | 关联与比较基准更新、候选重要变化历史、合并/拆分关系，以及归入岗位或结束观察的记录 |

输入校验、知识读取、证据验证、持久化和发布是共享边界，可以复用基础设施，不另建复杂的关系推理领域模块。内部知识标准与处理器解耦。

### 3.1 最少保留的内容

1. **输入身份与快照引用**：实际提供的完整文本、来源和内容版本。身份、内容、真实观察时间分别表达，不以文本相同自动合并职位。
2. **单条分析记录**：职责和要求陈述、原文位置、归一化结果、必要的明确关系、覆盖与错误信息。它是机器分析结果，不自动具有人工真值地位。
3. **知识标准版本**：技能概念/别名、岗位定义、确认状态及来源。正式目录可以为空；候选定义可供受限比较，但不得伪装成已确认标准。
4. **工作组合候选及判断记录**：稳定身份、关联的分析版本、共同职责版本、当前比较依据、未解问题与重要判断变化。候选引用事实，不复制整份 JD 分析。

这些是最少信息类别，不是四张表或冻结字段。岗位画像是可重建结果，保留成员、范围和依据，不另造一套可反写单条事实的权威来源。

### 3.2 对外语义边界

独立入口接受显式 JD 输入及可用知识标准；输入适配不读取未声明的外部依赖。缺乏岗位标准时，仍能分析职责和能力，岗位判断如实保留未决原因。

对外至少分别提供：输入/证据身份、职责与要求及其关键关系、岗位判断与解释、候选/正式性质、各能力的覆盖和执行结果、实际知识及分析版本。无识别结果、未提及、关系未知、未执行、部分完成和失败不能用同一个空字段代替。

候选内的内部 ID、归纳方式和检索器可替换；下游不必读取候选存储表才能消费单条分析或岗位画像。旧必备/加分字段不足以表达的新语义不得静默压缩；兼容投影若丢失含义，需显式标示限制，不能写回冻结契约。

## 4. 能力与职责的有限关联

| 关系状态 | 依据与用途 | 不能推导的结论 |
|---|---|---|
| 明确关联 | 原文直接表达某能力用于某项工作，引用对应原文；可支持岗位与组合比较 | 不自动证明该技能必备、某种熟练程度、不可替代，或已获人工复核 |
| 推测关联 | 有可指出的上下文理由；按实际比较需要生成，可辅助检索、提示及后续验证 | 不能单独确认组合相同、排除已有岗位或支持独立新岗位；不能通过累加或摘要改写升级为明确事实 |
| 关系未知 | 缺少足够联系依据；职责与能力分别保留 | 不等于不存在关系，也不等于执行失败或尚未分析 |

例如“使用 Redis 实现任务状态存储与恢复”可支持技术与工作的使用联系，不能据此补写“必须熟练掌握 Redis”。要求五态、程度和关系依据分别判断。

没有明确关系时不生成职责 × 技能矩阵。只有对具体配对作过判断，才需要表达该关系未知及原因；没有关系记录的读取语义是未提供关系主张，而非明确无关系。推测可以临时存在；实际进入候选解释、检索选择或职责修订时，保留足以理解该次判断的理由、输入及版本引用。

程序验证引用身份、原文和位置等确定性条件；“引文存在”“语义判断正确”“经人复核”“已正式收录”是不同层次。其他岗位、候选摘要或模型常识不能替代当前 JD 的直接证据。

## 5. 岗位归类的解释基础

岗位定义描述当前版本认可的核心责任、交付目标和范围；历史 JD 描述真实招聘中的变体。历史没有出现某项职责，不能证明该职责被岗位排除；定义没有覆盖，也不等于存在明确边界冲突。

建议比较结果分别解释：为什么考虑该岗位、能覆盖哪些责任、哪些尚未解释、是否有明确边界冲突、证据与目录是否充分。可归入、暂不能确定、有依据不宜归入作为概念结论；具体枚举留给契约设计，不扩充成大量最终状态。

目录不完整、原文不完整、召回不足和分析能力不足是原因，不能冒充“新岗位”。只比较少量候选时，结论范围必须限于已检查对象，不能宣称排除整个职业目录。

正式目录尚未成熟时，可以从真实 JD 与国内职业规范形成候选岗位定义，逐步确认核心职责与范围。候选标准参与比较的结果必须带出其待确认性质，不能用机器新生成的定义自证正式归属。

岗位知识及评价立足国内真实招聘表达；国内职业标准作为重要参考，市场岗位不强制与国家职业分类一一对应。国外分类、方法和实验成绩不能直接充当中文业务标准或 TalentMind 的效果结论。

## 6. 工作组合候选的关联与稳定性

### 6.1 比较依据

共同工作目标和核心责任是主要依据；原文明示的能力—职责关系提供支持；标题、技能共现和推测关系帮助检索。职责相同而技术栈不同，仍可能支持同一组合；技能相同而责任不同，不因此合并。

职责表示保留工作目标、工作对象/成果、具体责任、能力联系及上下文证据，允许其中一部分未知；不把所有职责强制标准化成任务实体。核心性也应有证据及不确定性，不按条目顺序、词频、篇幅或技能数量猜测工作占比。

### 6.2 建议的比较过程

1. 取得明确版本的单条分析，先区分理解充分、局部可用与执行异常。复杂或多招聘目标材料不因出现多组职责就自动拆成多个职位。
2. 利用职责、对象、已知概念和辅助线索检索相近岗位与组合。标题和技能检索可以补充召回，不能作为唯一入口；已能关联某个岗位的 JD，也可能包含值得研究的未覆盖责任。
3. 对每个候选，以当前职责假设、代表性原成员及相邻组合为参照，解释支持、差异、冲突与未知。核心证据不足时保留待判断，不能把“没有发现矛盾”当成已经证明相同。
4. 保存可撤销的机器关联或待确认建议，引用本次使用的 JD 分析、候选及标准版本。局部相符时记录实际支持的职责范围，不让一项相符扩张成整份 JD 的全部职责都属于候选。
5. 关联判断完成后，再根据新证据重新归纳共同职责；证据充分且仍能合理解释候选原有工作组合与成员时，自动修订并使新版本用于后续比较。不能合理融入的证据保留关联疑点，必要时提出拆分或新候选建议，不为容纳新 JD 不断泛化描述。新摘要不在同次判断中反过来证明新成员正确。

一批新 JD 先对照同一候选基准版本评价，再自动修订并用于后续批次；候选基准已变化时，旧版本生成的修订须重新核对当前依据，不能直接覆盖新版本。初版可用串行执行与版本检查处理，具体并发机制属于工程设计。这些是判断正确性约束，不增加人工审批环节。

相似关系不具有自动传递资格：A 与 B 共享工具调用、B 与 C 共享失败恢复，并不足以把 A/B/C 合成一个组合。需要检查整体责任假设与边界案例，而非只连接相似邻居。

### 6.3 创建、修订与身份

候选是可以持续验证或被推翻的工作组合假设，不要求正式名称。“WC-001”仅为示意，不规定 ID 格式。单次分类失败或输入异常不足以自动创建候选；至少应能提出具体职责组合、原文支持和待研究的归属问题，并检查是否已有相近候选。

创建候选只建立待验证的观察假设，不声明市场规模或岗位独立性；不设固定 JD 数量自动生成新岗位的规则。证据不足以描述有意义组合时，保留单条未决分析即可。

普通关联可以自动积累；明显不确定的留待确认。重复发布和身份待审记录的关联，不自动增加已确认独立证据或职位数量。

系统可根据新证据自动重新归纳共同职责、修订候选描述、更新岗位归类解释与未决原因，并使修订版本成为后续比较基准，无须人工接受。共同职责的语义变化本身不触发强制人工审核；自动修订应有足够证据，仍能合理解释候选原本代表的工作组合与原有成员，不能为了容纳新 JD 持续泛化。

新证据不能合理融入时，保留关联疑点，必要时提出拆分或新候选建议，不强行扩张原候选。保留实际用于比较的职责版本、重要变化依据和历史判断，但不为每次文字调整生成繁琐审核记录。候选描述自动生效不表示获得人工确认，也不表示成为正式岗位定义。

同一假设在原证据脉络上获得更准确描述或纠正个别关联时，保留稳定 ID 并追加版本。若判断实际包含不同组合，提出拆分；若两个候选重复，提出合并。合并、拆分均由人工确认，保存前后身份关系及依据，不能覆盖原历史或重写源 JD。具体保留哪个合并 ID、拆分 ID 格式等可由工程设计确定，但旧 ID 必须能追溯最终去向。

允许一份 JD 的不同职责支持多个候选；是否同一独立招聘职位另行判断，不从候选关联数推导 vacancy。

### 6.4 自然结局与改变理由

- 现有岗位或其方向足以解释：提出归属建议，经人工确认结束独立观察，保留候选历史。
- 仍未确定：继续积累，保留明确的未解原因。
- 有依据支持独立性：提出新岗位定义建议，经进一步人工确认和既有准入流程处理，不自动发布。
- 原组合假设被推翻：记录反证与结束理由，保留旧判断及关联纠正历史。

重要判断变化保存简短差异：触发输入或标准/分析变化、旧判断、新支持/削弱/反对证据、新判断和剩余疑点。保留实际比较所用版本，不为每次文字调整增加审批记录，也不为没有新增有效信息的每日运行重复制造判断版本。

## 7. 知识、标准与分析的更新

新增别名或确认技能时，若旧职责与原词事实充分，可重新归一化；岗位定义改变时，可复用单条事实重新比较及构建画像；分析能力原先漏掉职责、条件或否定时，则重新分析相关 JD。

输入变化、知识/标准变化、分析器变化、候选成员或画像重构分别记录，不把重新解释当成真实招聘变化。同一次历史判断绑定实际输入和依赖版本；重放旧结论不套用当前标准，重新评价产生新记录。

受影响范围可定位时只处理相关对象；无法证明影响范围或复用充分性时保守扩大重评范围，不能声称已实现精准失效。无需每日全量重聚类，也不能因检索漏召回就认定不存在受影响对象。

## 8. 自动化、审核与发布

仅区分两类职责边界，不要求两套工作流或复杂状态机：

- **日常自动演化**：JD 分析、新 JD 关联、证据积累、共同职责重新归纳、候选描述修订、岗位归类解释与未决原因更新，由系统自动处理。满足证据和候选稳定性约束的职责修订自动生效，无须人工接受；异常和明显不确定的关联保留疑点及待复核原因，不阻塞其他可独立完成的分析。
- **关键知识结构决策**：候选合并、拆分、正式归入岗位、新岗位定义的确认与正式发布，第一版由系统给出依据、人工确认。日常职责的语义变化不因此升级为关键决策，不要求人工逐条审核 JD 或每次职责修订。

同批次基准一致、合理解释原成员和重要变化可追溯，是自动判断的正确性要求，不转化为额外人工审批。未来自动化范围按真实准确性问题和处理量调整，不提前建设复杂权限、审批体系或固定数量门槛。

日常单条岗位判断可以自动产生带机器性质的建议，不等于某条 JD 已正式确认归属。候选共同职责自动成为比较基准，也不等于人工确认或正式岗位定义批准。工作组合候选、候选岗位定义、人工判断与正式岗位知识状态分别表达，不能借同名“候选”自动互相升级。未知技能的正式准入仍受既有产品规则约束，本次候选管理不扩大其自动准入范围。

发布保留部分结果、证据限制和正式/候选性质；下游读取候选，不授予正式统计或知识准入。仅在必要语义和版本约束通过后发布相应可用结果；某一能力失败不抹去其他已保存的有效内容，也不把整条 JD 宣布为完整分析。

需要人工确认的关键决策应绑定所见版本，过期建议重新比较；模型自述、程序校验或自动化审阅不能冒充真实人工确认。原有 [人工审核规范](M2-M3-human-review-protocol.md) 的机器/人工分离原则继续有效，其现有 API 不因此自动覆盖新候选机制，也不成为日常自动演化的审批前置条件。

## 9. 候选技术路线与工程自主范围

| 路线 | 当前适用性与限制 |
|---|---|
| 持续扩充字面规则 | 可用于明确边界、证据检查和回归，但不作为开放中文语义和新表达发现的唯一长期路径 |
| 整份文本一次生成最终岗位 | 便于快速输出，但难独立评价事实、归一化和比较，错误与知识状态容易混合 |
| 结构化语义处理器 + 知识检索/对齐 + 确定性验证 | **Agent 优先建议**：对应三项最小职责，允许替换实现及分别评价；成本和真实效果仍需中文样本证明 |

推荐路线不是规定固定模型调用顺序或混合比例。处理器负责开放表达理解，知识标准提供可版本化参考，程序验证确定性条件；规则、模型和检索可按评价结果调整职责分工。

未来实现者可在获开发授权后自主决定内部函数/类划分、索引、记录编码、内部持久化方案与可替换处理器接口，优先现有依赖和最小实现；须保持本文证据与语义边界。当前 Python 后端、已有版本/恢复机制和词典可评估复用，但不能仅因存在就宣称满足新语义或强制新方案沿用旧流水线。

具体模型、部署方式、费用、向外部服务发送真实 JD 的范围及最终契约属于后续明确选择；本次不授权付费/外部模型调用、真实数据操作、正式接口替换或数据库迁移。

## 10. 评价设计与可接受证据

首轮使用少量、合法来源且经人工标注的中文 JD 与相互比较案例，覆盖当前技术岗位范围中的代表性职责；不规定每类等量，不宣称覆盖整个中国招聘市场。候选岗位定义的来源与确认状态随样本记录；人工应能补充机器漏掉的职责或技能，不能只审核机器已抽取项后声称获得完整召回率。

至少包含：

- 职责相同但标题或技术栈不同；技能相同但工作责任不同。
- 明确关系、可解释的推测、只有共现和缺少上下文的未知关系。
- 任选、含“等”的开放枚举、程度、优先/否定的作用范围、能力与经验对象区别。
- 标题正文冲突、多个核心责任、真正多招聘目标与证据不足的短 JD。
- 未知技能、歧义别名、目录缺口及职责未覆盖但不存在排除证据的案例。
- 分批追加、输入顺序改变、相似链条、重复发布、误关联纠正和推翻旧假设。
- 岗位标准改变、候选描述修订、分析器纠错分别导致的判断变化。

分别评价职责与技能提取、要求语义、证据定位、关系误判、岗位解释和候选误合并/漏关联；检索召回与给定候选后的判断质量分开，候选稳定性检查需有人工参照，不能只看不同顺序结果相同。

标题/技能相似与整份 JD 文本相似可作参照路线，比较结构化职责判断的额外价值。样本来源、标注者、定义版本、分母、未决、失败和未覆盖范围单独报告；不以同模型未经审核的生成内容作真值，零分母不记为零分，不把未校准模型分数当概率。

正式样本、标注细则、模型选择和验收阈值尚未确定。本文只描述需要取得的证据，**本轮未抽取真实数据、未生成真实人工真值，也未运行上述评价**。

## 11. B/C 的剩余取舍与下一步边界

两种方案均可复用本文已确认的三项职责，并提供简单的对外岗位结果。持续候选管理已是明确能力；不能以采用 C 为由把候选退化为一次失败日志，也不能以倾向 B 为由引入完整任务本体。

仍需在具体候选架构中比较：工作组合在长期知识组织中承担什么地位、哪些能力需对外公开，以及持久化和维护成本。若两种方案在约束下已经趋同，应直接说明，不为维护 B/C 名称人为增加模块。
