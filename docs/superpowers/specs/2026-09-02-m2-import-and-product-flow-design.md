# TalentMind 2026-09-02 M2 完整导入与产品流程修复设计

## 背景

用户确认采用 `input/岗位数据-新一代与现有/` 作为 M2 权威回包，完整导入新一代岗位 344 条和现有岗位 375 条，共 719 条岗位；同时修复采集历史日志、智联/猎聘控制、简历自动匹配/学习路径及图谱节点/详情展示。

## 方案

### 1. M2 导入

- 新增交接包解包层，兼容旧数组根节点和本次 `{items, schema_version, ...}` 包装格式。
- 合并新一代/现有定义与技能文件；以 `job_id` 为稳定关联键，允许同一岗位出现多条技能记录并在导入前合并。
- 为 `job_definition` 增加 `m2_job_id/name_en/job_name_zh/category/category_review/source_jd_count`；为 `job_skill` 增加 `m2_job_id`；为 `job_change_log` 增加 `m2_job_id/object_type/source_jd_time`。不删除、不改变冻结字段。
- 通过数据库当前列检查执行幂等增量迁移；导入在单事务中全量重建岗位定义、岗位技能、能力变化日志。未知变化日志保留为 `job_id=NULL` 并记录原始 `m2_job_id`，禁止静默丢弃。
- `validate_exchange` 支持包装格式、拆分文件和关联检查；导入审计报告写入 `data/local/m2-import/`。

### 2. 采集控制

- 任务状态统一包含 `platform`、`log_path`、`log_summary`、`raw_log_tail`。
- 历史任务优先读取状态文件，兼容旧任务记录；根据任务 ID、平台和日志文件名/内容匹配日志。
- 日志解析兼容 BOSS 现有格式，并支持智联/猎聘通用的轮次与完成统计；未知格式显示部分可识别而不是空数据。
- 控制 API 增加 `platform` 查询和平台状态；采集器入口只复用现有 `fetch_cn_jobs`，不重写抓取器，不实现验证码绕过。

### 3. 自动匹配与学习路径

- 上传简历后自动遍历完整岗位目录，返回真实排序结果。
- 前端固定展示至少 3 张推荐卡片；每张卡片分数至少展示 90%。当真实分数低于 90% 时，响应同时返回 `raw_score` 和 `display_score`，卡片标注“展示保底分”，不伪造真实计算结果。
- 移除旧目标岗位下拉选择器和旧单岗位匹配卡片；推荐卡片的岗位 ID 是学习路径唯一目标。
- 学习路径从 query `job_id` 或推荐卡片跳转生成；若无 query，不自动偷偷选择第一个岗位，而是提示从简历页选择推荐岗位。

### 4. 图谱

- 图谱加载支持 M2 包装文件，并使用稳定 `job_id`、canonical 技能 ID 和 slug 行业 ID。
- 岗位/技能/行业节点统一输出 display/name_en/name_zh/category/source 等属性；保留未进入 skill_dict 的 M2 技能并用稳定 fallback ID，不删除原始证据。
- 图谱详情栏设置视口内最大高度和独立滚动；长标题、职责、标签可换行，不撑破页面。

## 验收

1. M2 校验通过，导入后 MySQL `job_definition=719`、能力日志为 243 条，技能记录按 job_id 合并且无未知岗位技能。
2. 图谱重建与 Neo4j 导入后，岗位节点数为 719，节点类型和边的 source/target 均可解析。
3. 采集历史 API 能返回历史任务和日志状态，BOSS/智联/猎聘平台字段正确。
4. 简历上传响应至少 3 条推荐岗位，`display_score >= 90`；低于 90 的结果带 `raw_score` 和明确标记。
5. 学习路径只能由推荐岗位 ID 驱动；图谱详情在小屏幕和长内容下可滚动。
6. 后端全量 pytest、前端 `pnpm run build`、关键 API 冒烟和 D37 数据清理核查通过。
