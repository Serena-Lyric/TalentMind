# M2 分段交付审核标准

> 日期：2026-10-28。本文规定后续 ChatGPT 如何审核交付完成情况，不是已完成的审核报告，不冻结内部实施方法。
> 适用计划：[M2 新底座分段交付](../plans/2026-10-28-m2-core-delivery-plan.md)。产品语义以 [当前产品决策](../../PRODUCT_DECISIONS.md) 及 [最小架构设计](2026-10-28-m2-analysis-candidate-design.md) 为依据。

## 1. 审核对象与职责

ChatGPT 直接检查该阶段 GitHub PR 的实际 diff、固定 head SHA、实际执行路径、验证证据及交接。Codex 自检、工具成功和另一个 Agent 的意见不能代替这次审查。后续修复换 head 时，明确复审的是新版本，不以旧审查结论自动覆盖。

ChatGPT 的交付审查不自动成为真实人类 JD 标注，也不批准具体正式岗位。业务真值须记录真实标注/复核来源；用户允许的合成或模型断言可检查工程机制，但不能据此宣称市场语义准确性。

审核根据阶段结果，不要求遵守某个模型、算法、调用序列或文件布局。改变方法但效果满足要求可通过；改变产品含义、隐私边界或冻结契约须有对应确认。

## 2. 每段必交证据

| 项目 | 必须能够核对的内容 |
|---|---|
| 版本与范围 | base/head SHA、PR、阶段编号；实际改动、既有修改保护和未覆盖范围 |
| 可执行入口 | 实际命令/API/页面入口、环境前提和版本；调用链确实到达本段实现，不能只验帮助或字段存在 |
| 输入与知识 | 冻结输入/知识/模型配置与提示修订引用、内容摘要、来源及确认状态；P0 最小岗位参照带来源/版本及测试/候选/正式性质，私有全文不上传 |
| 行为证据 | 本段完成标准逐项结果、原文到结论的引用、失败及未决原因；必要时给可公开合成复现 |
| 测试与质量 | 实际命令、退出码、计数与未运行项；规则/合成测试、真实模型运行和人类参照分别报告 |
| 量化口径 | 输入总数、完成/部分/失败/未决及各指标分母；漏提、误提、误关联与覆盖单列 |
| 安全与恢复 | 与本段有关的权限、实际隔离连接、夹具清理与残留查询；无需真实 DB 的阶段不为了报告运行 DB |
| 交接 | 实际文件/接口及契约版本、产物位置、已知限制、后段依赖是否具备；临时报告与正式文档链接 |

证据记录实际发生的内容，不能预填通过数、运行时间、价格、签审人或测试输出。没有人工真值时明确相应指标不可计算，不记作 0 或 100%。

关键证据无法受控复核时，结论为证据不足，不能只凭文件哈希或执行者自述放行。可提供经授权的必要摘录、合成复现及真实标注/复核记录，但合成材料不替代真实语义证据，也不能为方便 GitHub 审查公开上传私有全文。

P0 须落实实际人工复核人和 ChatGPT 可查看材料：样本/输入版本、足够作用域的必要摘录、逐项人工标签与理由、实际复核及争议记录和错误对照。负责人确认材料范围与提供方式；只能查看部分上下文时审核仅覆盖该部分，缺少关键原文或标注就报告相关语义证据不足。模型服务/真实文本发送范围及费用许可也须有实际确认来源，凭据或旧配置不能替代授权。

## 3. P0 必须冻结的评价口径

每项指标至少记录：评价对象、人工参照来源、样本选择与排除规则、输入/标准版本、分母、计算方法、目标或定性通过条件、确认来源、未知和失败如何计入。至少覆盖：

- 职责/技能漏误提；中文要求五态、程度、组合、条件、否定与对象错误。
- 原文位置/身份正确性与语义正确性分别评价。
- 岗位解释的支持、缺口、冲突和待判断；正式/候选标准混用错误。
- 候选检索召回、给定候选后的关联、误合并与漏关联分别评价。
- 自动演化前后的原成员解释、反证处理、描述泛化与变更理由。
- 完成、部分、未知、失败、延迟/成本等可用性；成本与模型能力以实际配置和调用为准。

当前不设未经确认的统一精度数字。P0 提出的数值目标须由负责人/获授权的业务评价者确认，或以明确签审的逐例通过条件替代；在 P6 观察结果后改标准，要保留旧结果和修改依据，并重新取得独立评价证据。

开发样本和留出检查的成员/用途先冻结；不能用留出结果反复改提示、知识或算法后继续称其独立留出。人工能补标机器漏项，不能只审已有预测后计算完整召回率。样本不足或口径未确认时可交工程结果，但相关语义验收为证据不足。

## 4. 全阶段的必要行为约束

1. 明确原文中的任选/否定/作用域不能被改成确定错误要求；不能将使用技术改写为必备、将未提及改写为不要求。
2. 推测、未知、未完成和执行失败分开，且有适用范围；不能靠全部返回未知规避 P0 的覆盖与召回要求。
3. 输出引用真实存在的输入与版本；程序引文校验通过不能充当语义真值，摘要不能替代源证据。
4. 归类未覆盖不等于明确排除；目录缺口不证明新岗位；未经确认条目不自动正式准入。
5. 候选身份和工作责任可追溯，不按标题/技能简单相似强合并，关联数量不冒充独立职位数。
6. 共同职责允许自动修订生效；同批比较基准一致，新版本不能反向自证本批关联，不能靠泛化容纳冲突。
7. 合并、拆分、正式归属、新岗位定义确认和正式发布无人工确认时只保留建议；已生效机器描述仍非人工确认或正式岗位定义。
8. 输入、分析、知识与候选版本变化保留原因，重放不混用新依赖；部分结果和旧历史不被失败或新结论抹除。
9. 正式 DB/Neo4j、采集、外部真实文本发送、隐私及测试清理遵守实际授权。模型/服务提供的异常不得把凭据泄漏到可公开产物。

有可复现且未处理的上述反例时，相关能力不应判为通过；可以修复后复审，或明确缩小本次可用范围，但缩小范围不能冒充原阶段的全部目标已完成。自然语言本来存在歧义时应依人工参照允许待判断，不强求伪确定答案。

## 5. 审查结论与后续处理

- **阶段通过**：本段目标有足够证据，适用硬约束满足，P0 对该能力的评价要求达到，遗留不影响该段声明范围；记录准确 head 与后段可用接口。
- **需定向修复**：列明具体输入、预期/实际、影响和代码/证据位置；Codex 在本段修复并更新证据，ChatGPT 复审新 head。
- **证据不足**：指出缺失的执行、标注、版本或评价条件；工程和语义结论分别保留，不把条件未具备描述成通过。

结论直接写入 PR 审查记录，并只在总计划当前阶段行统一维护状态、PR、提审/审核 head SHA、结论出处、合并后 master SHA 及阻塞项；各分段页不复制运行状态。新 head 需复审，原结论不自动继承。审查通过不自动授权 Codex 合并；后续按 AGENTS 由用户授权 ChatGPT 合并。未合并时保留未合并标记，后段不假定已交付；合并后记录实际 master SHA，后段不要继续依赖废弃工作树路径。

## 6. 提交给 ChatGPT 的审核信息模板

以下字段由执行者在实际交付后填写，不在计划编制阶段伪造：

- 阶段、PR、base/head SHA、审核结论出处、合并后的 master SHA（未合并则明示）及阻塞项、对应计划与适用产品规则。
- 本段目标逐项对应的实现路径、结果和证据引用。
- 实际验证命令/环境/退出码；真实/合成/模拟、人类参照、未运行部分。
- 输入/知识/契约版本和私有产物清单引用；错误、未决、失败与各指标分母。
- 实现选择及与建议路线的差异，已知限制，后段依赖和未获授权事项。

审核请求：请直接审查该 head 的代码和证据，以本段结果目标和本标准判定。先报告实质问题，再给阶段通过、需定向修复或证据不足；不因未采用建议算法扣分，不用测试数或界面演示替代真实语义证据。

## 7. 审查证据与报告生命周期

`docs/review/` 阶段报告受全仓最近 5 份上限约束。长期规范、用法和陷阱写回正式文档；PR/commit 保留审查证据，淘汰报告时同步修正活跃链接，不新建 archive 报告。公开只放安全摘要及合成案例，私有原文/标注/回包保持私有且可受控复核；报告淘汰不授权删除私有证据。
