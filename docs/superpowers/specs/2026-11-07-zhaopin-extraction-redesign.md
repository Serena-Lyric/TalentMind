# 智联采集与分类证据链重设计

状态：2026-11-07 代码核查后的技术方案，未实现、未完成实站验证。负责人授权本对话大范围修改，目标与性能优先；明确问题同时涉及字段/正文分栏和岗位/技能分类。具体失败岗位及正确分类参照待补充。本文件不取代已确认产品规则。

## 1. 已确认的问题与尚未确认的原因

2026-11-07 最新本地任务的事件复核：1 条列表候选、1 条详情取得、正文合格、0 条入库，拒绝原因为 `missing_list_title`。详情有非空标题，列表标题为空。`control.get_results()` 只以列表标题初始化 `job_title`，处理详情事件时未暴露详情标题，造成界面标题仍为空。用户所举“处理结果＝拒绝”属于采集准入状态，并非职业类别；M2 分类错误仍无具体反例。真实日志留在私有目录，不复制入本文件。

优先实现：结果返回独立的列表标题、详情标题与显示标题来源；详情标题可以显示，但不能作为独立列表身份证据。对拒绝原因提供中文解释。列表提取失败仍需通过当前可见页面结构定位，不以详情回填掩盖失败。

表述纠正：用户明确指出现有文本就是 JD 标题，浏览器复核亦确认。应将事实表述为“JD 标题已取得；历史事件缺少列表侧标题记录、关联校验未通过”，不能据此推断整个 JD 标题获取失败或当前网站缺标题。控制台已经按此区分展示。

- `fetchers/job_sites.py` 的智联地点、经验、学历选择器均包含 `.jobinfo__other-info`，同一段混合文本可能被写入多个字段；是否命中当前网站需真实样本确认。
- `normalize_job()` 给所有正文添加“职位描述”标题；`cleaner.py` 又把该标题解释为职责。通用描述与明确职责没有分开，存在将混合正文误标职责的路径。
- `source_sections()` 每种类型只保留第一段；重复标题、职责/要求交错时存在遗漏。采集台优先展示已存 duties，展示层重新分段并不能修正旧字段。
- `RawJD` 和 `jd_pool` 没有独立公司、薪资、学历等结构化字段，适配器将部分字段拼入文本。网页取得、标准化保留、落库、API 展示四层必须分别验证，不能把页面显示为空直接判为采集失败。
- 岗位目录 API 读取 `job_definition.category`；采集原始池与目录不是同一数据源。某条智联 JD 的语义误判原因尚未确认，需绑定源 JD、分析版本和页面入口，不能直接改目录分类或词典掩盖问题。

## 2. 方案选择

1. 继续给通用选择器加回退：修改少，但字段来源和面板绑定仍混在一起，难以说明错字段来自何处。
2. **采用智联独立适配器、带来源的字段提取及独立正文分段**：复用控制器、频率门禁和保存流程，将网站结构变化限制在适配器；可离线回放，便于测量性能。技术选择由 Agent 提出。
3. 全部交给模型从网页文本抽取：额外网络、费用和不确定性，不适合作为每次页面轮询的默认路径。模型只在已授权的下游语义阶段使用。

## 3. 数据流与职责

目标页面 → 有界等待和身份绑定 → 一次详情快照 → 纯函数字段解析 → 原文分段 → 证据及状态校验 → 逐条保存 → 版本化分析 → 展示与复核。

### 3.1 详情快照

- 建立智联专用模块，列表和详情采用不同字段选择器，明确主面板、元信息区、正文区、公司区；禁止全页文本回退。
- 卡片点击前重新核对观察标识与展示摘要。列表变动或虚拟滚动造成索引失效时停止当前条，不能点击新的同下标卡片后继续使用旧身份。
- 轮询只检查目标及必要稳定信号；到达稳定态后一次取得所有字段，避免字段分别取样混入两条岗位。
- 完整快照带目标、URL、观察时间、适配器版本和内容摘要，最终快照再次检查绑定。保留现行 DOM-only pending 规则；不因字段齐全升级 verified。
- 可选字段延迟用有界等待；超时返回明确缺失状态，不无限等待。未取得当前 DOM 样本前不凭空指定新选择器。

### 3.2 字段结果

每个字段包含值、原始片段、来源区域/选择器和状态。状态至少区分已取得、页面未提供、未匹配、冲突、访问受限；“页面未提供”只有在识别到受支持页面结构且确认对应区域后才成立。

- 地点、经验、学历不能复制同一个混合容器。先读专属元素；混合元信息只能按可验证的标签/格式提取，无法确定的部分保留为未归属文本。
- 列表与详情冲突分别保存证据，不静默覆盖；招聘中介与客户公司保持来源角色，不强行合成同一个公司。
- 页面技能标签是来源标签，不直接当作 canonical 技能或岗位类别。
- 公司、薪资、地址、经验、学历等字段逐一跟踪“取得→转换→保存→返回→展示”，防止误把输出遗漏当作网站不提供。

### 3.3 正文与分类

- 原始正文保留换行、标题和顺序；系统包装标题不得作为原文职责证据。
- 输出段落列表：原文区间、原始标题、段落类型、判定依据；多段同类内容全部保留。类型为职责、要求、福利、公司、通用描述或未确定。
- “职位描述”先作为通用容器；只有明确的职责标题/证据才生成职责，不能将全部内容默认归为职责。不按缺少双栏目拒绝短 JD。
- 原始字段分段是 M1 事实组织；职业、技术方向、级别、技能规范化仍由 M2 承担。下游每项结果关联源 JD、输入摘要、分析版本、证据区间与不确定状态。
- 修复实际分类前建立用户指出的反例和预期参照；区分标题误导、职责语义、词典归一化、旧分析版本及页面展示错误。未确认标签不能写成正确答案。

### 3.4 存储与展示

- 新的结构化快照先进入私有、版本化本地产物，显式关联源记录和观察标识；写入需原子化，失败可见，禁止私有正文进 Git。
- 以 run_id、observation_key 和内容摘要共同定位不可变快照；同一运行的事件记录保存相对引用，API 通过受控服务解析，禁止客户端传任意文件路径。先原子保存快照，再写业务记录，最后记录包含数据库 ID 的提交回执；快照失败时不写业务记录。业务写入或回执失败必须显示部分完成状态，恢复先按已保存的来源身份核对数据库，不能盲目重复 INSERT。历史缺回执记录不得补造关联；M2 只接受显式导出的冻结输入。
- 保留当前存储兼容接口；新数据库字段/表设计在实现前核对契约，执行迁移须另获许可。旧数据不自动覆盖或重新分类。
- 采集台展示来源字段、缺失/冲突原因、原文与分段；下游页区分原始事实、机器推断、历史结果、待复核结果。
- 不用一个质量分替代字段覆盖率、正文完整性、身份可信度和分类准确率。

## 4. 性能与安全约束

- 保持页面动作 15–30 秒、组合切换 360–720 秒及验证即停；优化重复 DOM 遍历、重复解析和跨进程通信，不缩短安全间隔。
- 字段提取单次扫描有界区域，正文分段一次顺序扫描；可复用已构造脚本和已编译规则。不得为缓存命中复用另一岗位的详情。
- 测量 DOM 调用数、解析耗时、面板等待耗时、保存耗时及 p50/p95，分别报告固定等待与计算耗时；没有基线前不宣称提升百分比。
- 每条合格结果在下一次访问前保存；停止、超时、浏览器关闭和数据库异常不丢失此前已提交结果。
- 不导出凭据，不绕过验证，不自动启动真实批量采集，不自动重算正式分析库。

## 5. 实施顺序与验收

1. 用具体失败岗位确定页面入口、源记录及分析版本；获取获授权的最小可见页面样本，私有保存，公开测试仅用脱敏合成结构。
2. 先写失败回放：混合元信息、同名不同岗、列表重排、隐藏推荐、慢字段、重复分段、无标题、短正文、截断和验证状态。
3. 独立适配器及纯函数字段解析；先离线检查所有字段来源与缺失原因，再接入真实控制链路。
4. 修复原文分段与前后端展示；已存旧字段显式标为历史结果，不批量覆盖。
5. 基于已确定的分类反例，沿实际 M2 执行路径定向修复；保留版本和证据，未审语义不进入正式目录。
6. 非集成回归、隔离存储测试、前端测试/构建、独立审查；测试夹具按身份精确清理并验证。
7. 获得具体试采范围后，以最小实站样本逐字段比对网页→快照→库→页面，并测量耗时。离线通过不能替代这一步。

列表标题缺失和详情标题未展示已有本地事件证据，可先建立离线回归并实现展示证据修复。新列表适配器需核对当前 DOM；实际语义分类修复需额外的错误实例及预期，但不阻塞已确认采集问题的开发。不要求提供凭据。
