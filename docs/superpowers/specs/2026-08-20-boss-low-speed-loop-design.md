# BOSS 低速持续采集设计（2026-08-20）

## 1. 背景与目标

BOSS 正式 CDP 采集链路已经完成，当前 `jd_pool` 中 `source=boss` 为 470 条。用户要求在保持人工登录和合规边界的前提下，直接进入持续采集：降低页面刷新密度，改变关键词/城市切换间隔，长期以小批量、低速方式运行。

本方案只做访问节奏控制，不实现验证码绕过、登录绕过、指纹伪装、代理池或其他反爬规避。

## 2. 设计原则

1. **独立循环**：不修改通用 `collect_loop.py` 的 signal/HN 采集职责，BOSS 使用独立入口。
2. **单目标小批量**：每轮只处理一个关键词 + 一个城市，最多 1 页、12 个岗位、8 个详情。
3. **长间隔切换**：每轮结束后等待 6–12 分钟，再切换下一个关键词/城市组合。
4. **节奏有界抖动**：列表/详情页面间等待 15–30 秒，页面加载稳定等待 5–10 秒；范围固定、可审计，不用于规避验证。
5. **异常即停**：检测到登录页或验证页时停止循环，不继续重试造成额外访问；普通单轮异常记录日志后继续低速运行。
6. **幂等入库**：继续复用 `fetch_boss_jobs.run_fetch` 和现有 pipeline，按 `source_detail` 去重，不重复写入同一岗位。
7. **可观测**：每轮记录目标、节奏参数、列表数、详情数、新增数和异常；日志写入 `data/local/logs/`。

默认关键词为 Python、Java、数据分析、后端工程师、数据工程师、AI工程师、机器学习、产品经理；默认城市为北京、上海、深圳。可通过 CLI 覆盖。

## 4. 运行边界

- 依赖用户在独立 Edge 中人工登录 BOSS 求职端；不接收、保存或提交密码、验证码、Cookie。
- CDP 仅连接用户已启动的浏览器；当前正式端口为 `9333`。
- 进程不会自动注销 BOSS。采集结束时，必须由用户在同一 Edge 窗口手动退出登录。
- 如果页面需要登录或出现验证，循环停止并等待人工处理；处理完成后由用户重新启动。
- 默认无限运行；使用 `--once` 或 `--rounds N` 可进行连通性验证和受控运行。

## 5. 选择该节奏的原因

与“每 6 小时整批翻页”的批量模式相比，单目标、1 页、小详情上限和 6–12 分钟切换间隔会显著降低单位时间访问量；随机化仅用于避免固定节拍造成的集中访问，同时保持参数透明、可复盘。该方案不承诺绕过平台风控，只承诺在平台允许的登录态和公开页面范围内降低访问压力。

## 6. 验收标准

- 新增循环专项测试通过；
- BOSS 专项和后端全量测试通过；
- 启动后可观察到首轮日志；
- 首轮完成后数据库中不出现占位 URL、空 `source_detail` 或重复来源 URL；
- 如触发登录/验证，进程日志明确记录并停止。
