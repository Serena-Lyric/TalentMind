# 前端与图谱模块结合验收设计（2026-08-27）

## 目标

在不覆盖 `input/` 原始包、不破坏 A 侧现有 API 和 M1 未提交改动的前提下，验证并修复前端与图谱模块的真实结合，让正式 `frontend/` 能通过当前后端 `/api` 读取正式 Neo4j 图谱并展示可交互页面。

## 方案

1. `input/岗位能力图谱前端系统/` 与 `input/图谱模块/` 只作为只读对照，不直接替换正式目录。
2. 以正式 `frontend/` 的真实 API、`code=0` 响应、`vue-tsc` 构建约束为基线，选择性吸收输入前端的视觉布局和图谱交互能力。
3. 图谱数据继续来自正式 `exchange/m3/graph.json`/Neo4j；输入包的 812 节点旧快照不直接导入生产图谱。
4. 只接入当前后端已经存在的接口；无后端支持的输入包页面不使用 mock 冒充真实功能。
5. 启动 FastAPI 与 Vite，使用页面、网络请求和控制台错误进行验收；必要时只修复阻塞真实联调的最小问题。

## 验收标准

- `frontend` 的 `pnpm run build` 通过；
- Dashboard、Jobs、Graph、Resume 页面请求命中当前 `/api`，无 404/422/运行时错误；
- Graph 页面显示真实 Neo4j 节点和边，节点类型与边类型正确；
- Graph 页面能完成至少一次筛选/布局或节点交互；
- Learning 在 M4 pathfinder 尚未实现时显示诚实空态，不显示伪造学习数据；
- 不修改或删除两个 `input/` 目录；
- 不覆盖当前 M1 工作树改动；
- 修复 bug 时同步写入陷阱记录和资产状态。

## 不在范围内

- 不迁移 `input/` 整包；
- 不直接导入输入包 812 节点图谱；
- 不实现尚未回包的 M2 岗位分析和 M4 pathfinder；
- 不创建 Git commit，除非用户另行要求。
