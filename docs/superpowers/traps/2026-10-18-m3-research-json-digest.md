# M3 研究结果 JSON 往返后摘要不可复算

日期：2026-10-18。

## 症状

完整实验两次内存结果/落盘正文一致，但交付前从 results.json 独立重算 deterministic_sha256，结果不符。此前摘要仅证明内存运行一致，不能当作产物自验证证据。

## 根因

structural_summary 的度分布使用整数作为字典键。`json.dumps(sort_keys=True)` 在内存按整数顺序排序；JSON 读回后键成为字符串，再算时以字典序排序，例如 1、2、10 与 "1"、"10"、"2" 顺序不同。数学计数相同，序列化字节和摘要不同。

## 修复

新增最小用例要求度分布为文本键，断言 JSON 往返前后结构及 digest 相同：先观察 `{1:1} != {"1":1}` 失败，再改两个 histogram 在生成时即使用 str 键。空图真实 CLI 测试也回读核对正文/组/分区摘要。随后重新运行完整快照矩阵、两次独立进程比较，并从最终落盘 JSON 重算所有摘要。

旧 run 文件仍保存在忽略的本地实验目录，阶段报告标明旧摘要由修复版本取代，不修改正式图或旧证据。结果数值与推荐的结构结论没有因本次修复改变。

## 教训

“同种子两次相同”与“提交的 JSON 自身可验”是两项独立门禁。证据产物必须只含 JSON 原生结构，在落盘读回后重新计算摘要，不能只信生成时返回的哈希字符串。
