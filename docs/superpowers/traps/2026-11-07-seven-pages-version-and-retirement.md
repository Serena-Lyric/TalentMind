# 七页接通：版本冻结、任务退役与会话边界

## 症状 → 根因 → 修复

- 连续冻结A/B任务，先完成A后B永远不能恢复 → 两者冻结同一候选基线 → 同一新账本只允许一个未完成可执行任务；先恢复或显式放弃。放弃只追加状态且保留结果，不能通过stop/start复活。
- 候选已提交、结果尚未提交时崩溃，重试报请求不一致 → 重试按已更新候选库重新推导create操作 → 第一次提交前持久化`candidate_batch`，恢复使用完全相同批次。
- worker租约失败但网页先显示已开始 → 后台线程失败没有同步握手 → 启动获取租约的结果同步回传409，`finally`释放本机活动状态。
- 图谱点击时校验通过、随后artifact混版本 → 每个请求重新读取正在变化的run → 单次读取冻结bundle，按manifest SHA持久化；URL和每个artifact携带相同snapshot，缺失明确失败，部分结果同样可固定。
- 旧历史接口读取时意外初始化/改状态，或导出503 → 旧Workflow构造器含恢复写入、拆分漏掉`now`依赖 → `History`使用SQLite `mode=ro`，不建目录、不修复任务；保存原输入/报告摘要校验，导出单独回归。
- 加分项改名变必备，推荐旧分数搭配新要求 → 合并标签失去类型/版本 → 按技能身份保留类型（历史双重成员保持both，改名也写回两组），要求摘要随推荐/选择/学习传递；版本冲突409，用户明确重算。
- 退出或卸载后旧重算恢复目标 → await列表请求后仅检查是否已有简历 → 同时校验存活、会话代次、请求代次与当前目标，旧结果不得导航或写入。
- 演化的日志序号被展示为版本，演示趋势冒充市场事实 → 计数与来源身份混用 → 无持久版本返回null；原文/解释/档案编辑分别比较；32条已核实演示只按完整内容指纹标识，其余无法核实记录保持未知。

- 无变化保存也产生演化记录、连续版本摘要断链 → 请求与数据库值的空日期/布尔类型不同 → 同事务写后重读持久值，以同一规范生成前后快照；无变化不记日志，连续编辑版本链回归。

## 教训与回归

读取历史不触发新引擎或当前head解释；退役的是执行能力，不是原始数据。删除旧接口时同步删除其专属测试，但保留共享生命周期、安全门禁与实际消费者。集成验证只能使用隔离实例。
