# 2026-09-02 整体系统修复与回归门禁

## 症状

- 前端重新整合后首次 `pnpm run build` 暴露图谱节点详情字段缺少类型声明、学习路径存在未使用导入；构建虽能继续，响应式样式还出现 `}.@media` 语法警告。
- 后端服务未重启时，新增平台统计、采集和学习路径接口分别表现为 422/404，容易误判为路由实现缺失。
- M2 旧测试仍按“中文翻译文件一一对应、job_skill.job_name 中文、质量低分 reject”断言，与当前稳定英文关联 key、中文展示字段独立和质量分仅作权重的契约冲突。

## 根因

1. 前端 API 类型没有同步岗位节点新增的真实详情字段。
2. 本地联调服务是旧进程，工作树新增路由尚未加载；同时 FastAPI 参数路由会抢先匹配静态路径时会产生 422。
3. 回包测试保留了旧中英文语义，未跟随已确认的 `job_name` 稳定关联 key、`job_name_zh` 展示字段和 canonical 技能约束更新。

## 修复

- 补齐 `GraphNode` 的岗位详情字段，删除无用图标导入，修复 `LearningRoadmap` 的媒体查询分隔，并重新通过 `vue-tsc --noEmit && vite build`。
- 重启后端 18000 进程后回归 `/api/jobs/platform-stats`、`/api/learning/*`、`/api/collection/*` 等接口；采集管理页进入时自动准备独立 Edge，已登录才单轮尝试，未登录只提示人工登录。
- 在 M2 stage3 中按正式 skill_dict 归一 alias，词表外技能进入 `unknown_skills`；翻译层保留 `job_name` 和 canonical 技能名，中文标题写入 `job_name_zh`；恢复 `translate_change_logs`，避免过度裁剪模块 API。
- 将旧测试改为验证当前契约，而不是放宽生产数据边界。

## 教训

- 本地服务重启和路由顺序必须作为接口回归的固定前置条件。
- 中英文展示字段与关联 key 必须分离；技能名不能为了界面翻译而破坏 canonical 对齐。
- 修改模块文件时要保留同文件其他公共函数，完成后用全量测试和 `git diff --check` 双重门禁。
