# 批次停止、异常释放与单项日志生命周期

## 症状

串行批次在组合间等待时，单项已经结束，旧停止入口只看单项会遗漏批次；持久文件持续写失败后可能遗留控制器占用；滚动历史仅100项，旧批次的日志文件尚在却不能从历史列表找到；批次改变浏览器页面后旧单项准备凭据可能仍可启动。

## 根因

批次和单项具有不同生命周期，不能仅靠单项active状态判断。异常路径把保存批次文件放在释放reservation之前，保存抛错会跳过释放。前端以滚动历史列表充当精确日志索引；准备资格没有考虑跨模式浏览器变更。

## 修复

统一停止入口先结束批次（含等待），确认归档后再停止应用进程；停止失败则保留服务。控制器持有串行reservation，确认实际子项退出/归档后，即使批次落盘失败也在finally释放内存占用。按批次/条目/run_id精确读取真实日志，不依赖100项历史保留；日志端点沿用本地原文门禁，过滤事件全文、限制受控路径。批次开始时撤销旧单项准备资格。

## 教训

计划创建、批次运行和单项执行分别表达，未启动不能自动准备或采集；已处理数量不是成功数量。停批次需要覆盖正在准备、运行和等待阶段；文件写入异常不能留下永久占用，也不能在仍有活子进程时提前释放。长久保留的批次引用不能依赖短滚动历史列表。
