# 频率许可 SQLite 连接与 Windows 清理

- **症状**：分支整合后，Windows 全仓非集成回归出现 24 个 SQLite 文件占用清理错误；历史控制器链路另因零秒配置被新门禁拒绝。
- **根因**：`with sqlite3.connect(...)` 只管理事务，不关闭连接。许可发行、消费和一个账本损坏夹具将句柄释放依赖于垃圾回收；旧子进程夹具未同步新的间隔校验和账本隔离要求。
- **修复**：使用标准库 `closing` 包住连接，同时保留连接的事务上下文，确保提交/回滚后关闭；子进程夹具使用独立临时账本、合成时钟和合法间隔，在 finally 精确删除其账本并断言不存在。
- **验证**：58 项定向回归通过，覆盖许可重放、过期、共享限流、Windows 文件释放和真实子进程中的合成链路。未执行真实网站采集或生产数据写入。
- **教训**：事务退出与资源释放须分别验证；新增持久化门禁时，同步审查旧子进程测试的路径与时间隔离，不能通过关闭门禁使测试通过。
