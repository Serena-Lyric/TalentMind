# M3 候选适配的类型强转与关系汇聚

## 症状

独立审阅发现 `type: ["job"]` 被接受，计数为岗位但岗位筛选为空。真实快照中 python 的 222 条关系同时高亮时，汇聚点过亮；均在本轮独立候选中发现，未上线。

## 根因

`Object.hasOwn(kinds, value)` 会把数组强转为属性键；白名单本身不保证输入为字符串。原合成演示的固定曲线透明度不适合高连接度真实节点。

## 修复

先检查 `typeof kind === 'string'` 再匹配白名单，数组/对象/null/数字反例与筛选测试 RED→GREEN。关系仍完整批处理，仅按选中关系数量降低线条透明度，222 条仍全部保留；相关测试 RED→GREEN。

## 教训

校验须覆盖输入实际类型，不能依赖隐式属性键转换。合成演示接真实数据后须验证高连接度与空筛选；视觉减亮不能删除关系或改变正式统计。
