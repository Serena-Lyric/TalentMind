# 岗位语义：独立源工作表征与职责检查范围

## 症状

两次模型回答及合法引用仍可能把普通系统性能优化归为网络优化，把规范、测试集或知识处理
归为本人软件开发。每角色很小的 pair 预算还会被同一职责的多个参照占满，未查职责被忽略。

## 根因

目标参照的用途可能反向填入源责任；相同词面和同模型重复回答并不独立验证动作、对象或主体。
按 pair 排序没有职责广度保证。另一方面，简单取最近动词会遗漏“开发和维护”共用对象的前一个动作，
粗粒度 software 对象又会把接口、算法和 Skills 等不同方面混成同类。

## 修复

新增目标独立、版本化的有界源表征并由岗位对照与跨批研究复用；保留动作、功能对象、具体对象、
原始片段和作用域。不同方面不自动当反证，通用系统不能自动当具体功能对象。
角色检查先给不同职责机会，再检查同职责其他参照；预算外与比较未决、运行失败分账。
delivery 实际调用离线研究解释入口，使用其冻结知识，并保留四轴未决、未覆盖工作及来源版本。

## 教训

减少支持数不能单独证明改进。固定 pair 必须包含历史错配、边界、正例和已知未查职责；
对正例的误伤也要检查。通用语法修复可恢复共同对象上的动作，不能按 DEV 身份硬编码。
本轮中间实验以私有源码快照保存；fresh、历史回包重校验、有界离线测试和 Agent 诊断分别报告。
有限词义适配不是完整职业知识，局部研究不自动发布整岗身份，独立人审分母缺失时不报准确率。
