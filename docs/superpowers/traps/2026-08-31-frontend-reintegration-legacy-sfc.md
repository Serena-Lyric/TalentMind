# 前端完整重整时误把原版 SFC 当作正式源码

- 日期：2026-08-31

## 症状

将 `input/岗位能力图谱前端系统/src` 的页面直接拷贝到正式 `frontend/` 后，`vue-tsc` 暴露出原版页面的 JavaScript SFC、旧 API 模块、未使用导入和遗留静态数据依赖，构建无法稳定通过；图谱默认边全部显示时还出现严重的线条噪声，与设计图的星云节点视觉不一致。

## 根因

`input/` 是开发者原版返回包，不是当前正式工程。其页面带有独立的依赖、旧类型和测试/Mock 体系，不能作为可覆盖的完整实现。图谱原版适合展示功能，但没有按当前 588 节点/3998 条关系的真实规模设计默认渲染密度。

## 修复

以 `frontend/` 为唯一正式目录，逐页重建而不是整目录覆盖：

- 重写 App 壳层、路由和全局设计 token；
- 用 TypeScript 重新实现 Career Nebula 图谱画布，只在节点聚焦时绘制完整关联边，默认显示节点空间；
- 删除未被正式路由使用的旧测试组件、数据加载器和静态可视化依赖；
- 为原版 Collection/Evolution 页面重新编写正式 API 和类型；
- 保留现有真实 API、简历上传校验、空态和构建门禁。

## 教训

`input/` 返回包只能逐项提取视觉和交互意图；重新整合前必须先建立正式目录的路由、API、依赖和数据边界，禁止通过复制覆盖制造第二套正式实现。真实图谱数据规模变化时，默认可视化策略必须以可读性为验收标准，而不是简单绘制全部关系。
