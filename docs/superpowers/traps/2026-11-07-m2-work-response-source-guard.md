# 工作响应接收必须执行已识别的引用事实限制

## 症状

PR #75 第二轮 F1：原文“编写软件采购合同及代码”、短引“编写软件”（同名接口对象亦可复现），
源解释已给出空 frames、`uncited_action_or_object` 和 `context_restricts_quote=True`，但 work v4
接收两份合成肯定响应后仍保存 `machine_supported` 及工作候选，序列化读回也通过。

## 根因

接收门禁只识别 `unrecognized_complete_object`；源帧为空时，软件对象门禁允许普通未知词汇
交给模型比较。这条回退同时放行了已经明确识别的“引文没有包含动作或对象”，把事实限制误当
普通未知措辞。仅检查 source_work 返回值不足以证明实际响应接收安全。

## 修复

新默认 work v5 在接收与读回共同使用的状态判定中拒绝无源帧的 `uncited_action_or_object`；
两份肯定响应不能覆盖它。保留普通未知表述的比较能力、完整代码正例及包含代码的局部方面支持。
测试经过真实 `add_work_response → save_result → read_attribution → model_validate`，同时拒绝
伪造支持状态，并检查 P1 原记录未变。所有响应为合成，未调用真实模型或数据库。

新默认还恢复原有条件保护：复用既有条件词和动作判断，把无工作动作的独立条件行作为控制头；
普通条件职责句不提升为标题。不能直接对旧版整句 scope 取交集，否则“不承担课程教学，仅开发软件”
中的明确肯定方面会被误拒。完整/短引用条件、他责、历史和局部肯定均用真实接收及读回控制。

新版本同时消费普通/括号辅助标题恢复。历史 work v4 保留冒号恢复、semantics-2 和旧门禁，
work v3 保留冻结解释；新执行入口统一 v5。旧误支持属于已知历史局限，读取时不静默重算。
新规则重解释是独立产物，不能覆盖旧结果或只替换版本号。

## 教训

来源事实已被程序判定为缺失，与词汇未识别是不同状态；模型回包不能推翻前者。
版本隔离要覆盖源解释、输入摘要、提示词、状态、候选重要性及摘要方法标识。
既要测新执行拒绝，也要在修改前记录历史输入摘要，并核对既存私有结果的原字节读回。
