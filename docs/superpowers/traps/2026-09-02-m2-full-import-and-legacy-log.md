# 2026-09-02 M2 完整回包导入与历史日志识别失效

## 症状

- 最新 M2 回包使用 `{items: [...]}` 包装格式，旧导入器按数组读取，无法识别完整回包。
- 导入后岗位定义、技能和变更日志可能被按来源过滤，英文岗位不会进入主库。
- 采集模块历史任务只读取控制状态，不扫描既有 UTF-8/GBK 日志，页面显示 `No Data` 或“无法识别日志”。
- 图谱原实现以岗位显示名作为节点键，无法稳定关联重复标题，且 Neo4j 不能直接存嵌套 evolution Map。

## 根因

1. M2 回包演进为拆分文件 + `items` 版本包装，但交接层没有统一解包。
2. A 侧遗留的中文来源白名单与英文归档决策覆盖了用户后来明确要求的完整导入。
3. 历史日志缺少 `log_path/raw_log_tail/log_status`，且旧日志编码和当前任务状态未统一。
4. 图谱把显示文本误当稳定主键，并把嵌套 JSON 直接写为 Neo4j 属性。

## 修复

- 新增 M2 包加载/校验层，兼容数组和 `items` 包装格式。
- 以 M2 `job_id` 作为稳定关联键，新增应用字段保存英文名、中文名、分类和来源 JD 数；完整导入 719 个岗位、719 条合并技能记录、243 条变更日志。
- 无法关联的 3 条岗位变更仍保留，`job_id=NULL`、原始引用存入 `m2_job_id`。
- 图谱使用稳定 `job:<m2_job_id>`、`skill:<canonical>`、`industry:<slug>` 节点键，并批量重建 Neo4j。
- 历史任务扫描 BOSS/智联/猎聘采集日志，兼容 UTF-8/GBK，提供解析摘要、原始日志尾部和日志状态。
- 简历页移除旧手动目标岗位机制，推荐卡片固定至少 3 张且展示分不低于 90，同时返回真实 `raw_score`；学习路径只接受点击推荐岗位 ID。
- 采集控制台增加平台选择，复用既有智联/猎聘可见 DOM 采集器，不读取凭据、不绕过验证码。

## 教训

- 回包格式和来源边界必须以用户最新确认与文件实测为准，不能让旧白名单静默过滤新数据。
- 稳定 ID 与展示标题必须分离；跨系统 JSON 进入 Neo4j 前要先扁平化/序列化嵌套值。
- 历史任务列表必须把状态、日志路径、日志解析结果作为同一条可审计记录，不能只显示当前进程状态。
- 产品明确要求的展示保底分必须同时返回真实计算分，并在页面标注，避免业务展示值掩盖计算事实。
