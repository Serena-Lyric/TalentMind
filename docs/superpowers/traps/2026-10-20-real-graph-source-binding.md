# 真实图谱陈述的来源绑定、冲突与偏移

日期：2026-10-20。修复范围为新的离线贯通和隔离预览；不改 M2 历史事实或生产图。

## 症状

- 一个 any_of 组包含的 Python 有同 JD 冲突，Go 没有冲突，但投影把 Go 也标成 conflict。
- 前端只核对引文存在，跨 JD 的引文/关系在重新计算产物摘要后仍可能通过；emoji 前缀使合法 Python 偏移在 JS 中失配。
- verify 只核对文件摘要时，重新计算摘要的非法派生边/布局不能被识别；被拒绝的原文也缺冻结输入对照。

## 根因

- 依据 statement/group ID 找冲突时漏了技能身份，组成员状态互相污染。
- 文件内容完整性不等于语义来源关联；Python 偏移为 Unicode 码点，JS slice 为 UTF-16 code unit。
- 产物自报摘要不能替代 M1/M2 关系和派生算法重算。

## 修复

- 冲突同时匹配原陈述成员证据/名称和 effective.skill，不跨成员传播。
- 前端绑定 namespace、jd_id、fingerprint、技能治理条目/陈述、关系端点及 source_record，按 Array.from 的码点切片校验。
- 冻结完整 input.json 与来源清单，核对 M1/B1/B22，重投影事实并重新计算相似、社区和完整布局。预览失败清空旧节点/三维几何，不以缓存或历史图冒充成功。
- 以上反例先失败后通过。真实长JD与上游空正文保留原状态，不用本次修复冒充开放域提取升级。私有预览另外拒绝跨Origin/Host/非loopback请求，普通build不复制原文。

## 教训

一条图边要同时回答“谁的哪个原始字段、哪条陈述、哪一个技能、在什么条件下”。保留五态并不能自动保证冲突和来源正确；文件hash、引用绑定、Unicode偏移和算法重算必须分别验证。
