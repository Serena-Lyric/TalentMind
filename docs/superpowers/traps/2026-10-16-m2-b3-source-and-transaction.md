# B3 直接输入与共库恢复边界

日期：2026-10-16；Issue #8 离线开发期发现，未涉及真实数据。

## 症状

初始 B3 Python 调用只核对 InputRecord 的字段与指纹，没有核对 InputBatch.raw_bytes 与 records 一致；可将 `[]` 的源文件字节与非空 records 组合后保存，来源审计与实际分析不一致。另发现复用 A 存储初始化会把 A 的 running 恢复为 interrupted，不符合 B3 打开不得修改旧运行的要求。

## 根因

把“通常由严格读取器构建”当作可信边界，忽略公共 Python 接口也能构造 dataclass；将锁/快照复用与旧任务恢复绑定在同一初始化入口。

## 修复

B3 解析冻结 raw_bytes 并与 records 完整比较，逐条复核 namespace/identity/payload/observation，拒绝重复或伪造输入；全轮保存放在一个事务中。A 增加默认兼容 recover=true，B3 显式关闭恢复。测试对照旧A/B1/B2/治理全部表的逐行数据，另验证打开前遗留 A running 不变；默认A恢复用现有完整回归验证。

源文件字节/记录不一致回归先失败再通过；整轮事务测试在结果写入/提交前异常均无残留，提交后发布失败可重放。真实子进程 os._exit 覆盖五个边界，不以抛异常替代硬退出验证。

## 教训

共用基础设施前先读初始化副作用；每个外部可调用入口都验证实际保存的完整来源，不只相信类型或上游约定。证据位置通过仍不等于分类语义正确。
