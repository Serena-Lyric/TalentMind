# 岗位详情跨表 ID 回退与原文旁路

## 症状

`GET /api/jobs/{job_id}` 在 `job_definition` 中没有对应岗位画像时，继续把同一个整数当作 `jd_pool.id` 查询三中文平台原始记录。命中后会返回原始正文、职责和要求，调用方也无法区分这是岗位画像还是原始 JD。

## 根因

两张表的主键数值类型相同，但各自属于不同身份空间。岗位画像详情把“数字相等”误解成“对象相等”，同时绕过了专用原文接口已有的 `TALENTMIND_LOCAL_RAW`、回环地址、Host、Origin 和跨站请求门禁。

## 修复

岗位画像详情只解析 `job_definition.id`。画像不存在时固定返回 `BizError(4041, "岗位不存在")`，不再查询或返回 `jd_pool`。原始正文继续只由 `/api/collection/raw/{raw_id}` 读取，门禁在数据读取之前执行。删除仅服务旧回退的原始池响应转换函数，并增加隔离回归证明不存在画像时只查询画像表，允许和禁止原文访问时专用接口行为保持分账。

## 教训

数据库主键只在所属表或明确对象命名空间内有效。接口路径词相同不表示身份相同，跨表转换必须由调用契约显式携带对象类型和目标表。包含原始正文的读取应统一经过原文门禁，不能从画像详情或其他便捷接口另开旁路。
