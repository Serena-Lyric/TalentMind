# B2 治理的名称与评测边界

日期：2026-10-16。以下修复仅作用于新增治理层，不修改旧词典、共享 normalizer 或旧 B2 文档。

## 症状

- 285 条词典有六个重复映射名，旧 build_alias_map 依赖行顺序覆盖；sass 可能变为 css，js/ts/k8s/oop/敏捷开发存在 canonical/alias 重叠。
- 既有 python3、es6、oauth2 等别名可能丢失具体版本或混淆关系。
- 新覆盖层首轮实现中 `Vue 3.x` 被缩成 `3`，裸领域词“金融”直接出现在 skills 中；非技能否定/条件需要明确复核状态。
- 评测若把原文可定位当成事实正确，或在零分母时输出 0/1，会给出虚假的质量结论；未经人类复核的 Codex 合成预期也不能变成真值。

## 根因

旧字典映射没有保留多目标、版本和关系语义；直接复用会把历史实现选择扩散到新治理。新增治理的窄版本解析和领域词处理仍需独立边界。引文校验、人工语义复核、程序预期是不同的验证来源。

## 修复

- 旧资产只读；新 Catalog 保留重复项/多目标/未审别名/版本别名审计。只采用显式审定的同义覆盖，其余原名与比对结果留待复核；关系不表示可替代。
- 新结果保存原词与具体版本身份；通配 `3.x` 和精确 `3` 不合并。领域词无明确事实语境时进入 review_mentions，非技能只保存词面片段、完整上下文和 constraint_state=needs_review，不断言无条件任职要求。
- 新增反例实测 RED 5 failed / 53 passed（含尚未实现的评测 CLI）；完成后治理/评测 58 passed。名称/分类反例及原 B2 兼容均在真实 SQLite 路径验证。
- 评测严格区分预测、参考与程序证据检查。零分母为 null + undefined_zero_denominator；缺标注拒绝，缺预测计遗漏，重复预测计误提。真实评测模式要求合法使用及人类复核声明；合成自检 quality_claim_allowed=false。
- 开发期间 SQL INSERT 占位数与新增八列表不匹配，被三项真实持久化/CLI 测试捕获；修正为八个占位符，首批 33 项全部通过。保持执行型测试，不能只测试内存抽取。

## 教训

规范化视图可以追加纠正名称，不能顺手改历史语义或替换全局词典。程序自检和人类标注应分别建证据；指标必须显示覆盖与分母，不能用“全部测试通过”代替真实效果。
