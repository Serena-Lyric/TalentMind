# P0 人工参照绑定与集合身份

症状：初版离线审计接受缺少 `input_sha256` 的“已人工复核”记录；同 namespace+id、不同 source 的输入还可跨开发/留出集合通过。两类合成反例由独立审查复现，真实12条材料仍全部待人工审核，未产生错误真实准确率或改写原始JD。

根因：用“若字段存在才校验”保护强制版本依赖；审计层临时使用 source+id，而实际 InputRecord/Analysis 使用 namespace+jd_id，导致集合隔离与后续消费者身份不一致。

修复：样本与人工标注都必须显式提供且匹配完整输入指纹；跨集合检查统一实际 namespace+jd_id。新增回归先观察3项失败，再修复通过。CLI另用固定安全错误码区分缺文件、摘要不符及泄漏，不回显可能含原文的Pydantic异常。私有审计说明升级v1.1，保留原清单和说明在私有history；成员、快照和人工状态不变。

教训：身份键必须来自实际消费者契约；强制依赖的缺失本身就是错误，不能仅检查已提供值。文件摘要匹配、人工自述、语义正确性和正式知识批准仍是不同证据层次。相关长期入口见 [P0规范](../specs/M2-P0-baseline.md)。

限定材料访问时，不能直接调用默认全包审计：它会打开清单中的所有文件。新增显式sample选择，只打开指定snapshot/annotation并在输出声明局部完整性范围；空/未知/重复选择不能回退全量。合成回归以读取守卫验证未选中材料不会打开，实际DEV转录另用Python审计hook确认未打开HOLD。人工标注文件摘要正确也不能证明其中引文正确，须再绑定输入指纹并核对字段、Unicode代码点区间和引文；不能用文件哈希替代逐条证据校验。
