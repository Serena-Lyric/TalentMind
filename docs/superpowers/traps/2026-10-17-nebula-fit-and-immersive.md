# 图谱全览基线与网页沉浸高度（2026-10-17）

## 症状

P0 页面外壳已对齐，但原 Canvas 无法完整全览；PR #23 experimental 的功能未进入 P0。P0.5 首轮真实浏览器还发现 Y 模式宽度已铺满、高度仍少 36px。

## 根因

- P0 与 PR #23 是不同基线：旧版 wheel 固定 0.45–2.7，reset 为 scale=1，无 fit；行业节点按 110 坐标间隔横排，约 27 万宽。不能误报为 P0 外壳回归。
- Vue scoped `.graph-page[data-v-*]` 的高度规则后加载，与全局沉浸选择器同优先级，覆盖了 100dvh。
- 应用 margin-left 动画会产生连续 resize；若当作全览窗口调整，会在模式往返中悄悄改变相机。

## 修复

经用户明确授权，选择性复用 PR #23 确定性关系坐标及视口/交互工具，保留 P0 外壳与原配色；fit 使用实际面板矩形和完整筛选节点。沉浸高度选择器增加外壳类限定，图谱路由禁用外壳 margin 动画；resize 区分模式切换与正常窗口变化。H 使用 v-show，Y 不卸载画布。

## 验证与教训

真实 Edge 首轮 1600×900 测试捕获高度 864 而非 900 的 RED，修复后两种桌面分辨率均精确铺满网页视口，Y/H 往返相机值不变。7,845 个坐标逐一与 PR #23 比对相等，逆序输入不变；搜索 Python 原始 222 条直连，隐藏岗位后可绘制为 0，不补造边。完整证据见 `docs/review/Career-Nebula-issue-26-P05.md`。

独立审查另外指出窄屏已选中详情会遮挡“返回原视角”。新增真实 390×844 操作先复现面板相交 RED，再将 <=1000px 的两面板错开并各自限高滚动；同时增加搜索面板高度变化的 SFC 回归（RED：遮挡标签仍为 1；GREEN：0），搜索 watcher 等 DOM 更新后再绘制。

以后先记录分支、提交、URL 参数和实际布局，再诊断视觉差异；模式切换必须测真实尺寸及相机状态，DOM 类名存在和 build 成功不足以证明网页全屏生效。P0.5 尚待 ChatGPT 复审与用户验收。
