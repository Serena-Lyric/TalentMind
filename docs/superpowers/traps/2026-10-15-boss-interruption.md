# BOSS 整轮缓冲导致浏览器中断时已采数据丢失

日期：2026-10-15。离线修复，不运行真实采集或操作正式数据库。

## 症状

BOSS 已读取一页有效卡片后，下一页或详情连接异常可导致整轮没有入库。详情中途失败时，之前成功读取的详情也要等整轮结束才保存。

## 根因

`fetch_boss_jobs.run_fetch()` 先缓冲所有列表，再读取全部详情，最后一次调用管道。原 URL 去重只能跳过既有记录，直接提前入库又会挡住同 URL 的后续详情补全。

## 修复

- 每页列表后调用原公共管道，清洗、有效性判定与评分仍共用；新增行逐条提交。
- 每条成功详情后立即走同一管道；写入器按 source/source_detail 查找并精确更新，不重复插入。
- 详情只能补本轮新增行，或既有数据中所有非空行都带已知元信息标签、且 duties 为空的纯列表行。未知历史文本和既有实质描述不自动覆盖；列表写入不能降级已有详情。
- UPDATE 同时匹配 id、平台、稳定 URL 和原 raw_text，避免覆盖读取之后已被修改的文本。保留原 crawled_at/status/cross_source；不改 DDL、不删除数据。
- 浏览器异常与写库异常分开；单条详情失败后有限地处理剩余条目，空/无效卡片不落库。写库失败 rollback 当前事务并上报，已提交记录保留。

## 验证与教训

新增 `backend/tests/test_boss_interruption.py` 的 11 项用例，使用合成卡片和临时 SQLite、真实 SQL 提交及独立连接查询。先复现列表未提交及详情补全阻塞，再验证下一页失败、详情失败、详情连接失败、跨轮纯列表补全、URL 去重/上限、历史保护、写库回滚、详情重定向身份和无效详情不污染。

fixture 在 finally 关闭引擎、删除精确的临时数据库文件并断言不存在，不访问正式 MySQL。局部 158 passed；非集成回归 340 passed / 23 deselected（第三方弃用警告）。

及时保存必须与后续补全一起设计。没有唯一键的现有契约不能保证并发采集幂等；仍要求同平台串行运行。智联/猎聘的 DOM 卡片依赖当前页面，本轮不改其缓冲顺序，保留中断丢失风险待专项处理。
