# 工程可靠性：请求归属、批量预校验与资源生命周期

## 症状

- 简历慢解析阻塞轻量接口；CSV 导出后无法可靠导回；导入后行坏字段可能已写入前行；创建岗位返回 ID 依赖提交后连接状态。
- 重复图谱请求关闭共享 Neo4j driver；详情、保存或时间线迟到时覆盖当前岗位/编辑；某面板请求失败导致其他成功数据也不显示。
- 关闭重开同一岗位后，前一会话的 PUT 尚未完成却能再次保存；逆序写入使旧修改覆盖新修改，而页面仍显示已保存。导入拒收虽然零写入，HTTP 文案却丢失记录序号和字段名。
- 旧文件版 parser 合并短行后重复输出，缺少可选依赖或 textract 处理失败时访问未初始化属性。

## 根因

- `async def` 内直接调用同步解析/数据库/匹配；创建 Session 与执行线程归属未划清。
- CSV 编码 BOM 与解码不匹配，技能使用不同分隔符，导入边读边提交；`LAST_INSERT_ID()` 在提交后可能换连接。
- 请求级 session 与应用级 driver 所有权混淆；页面仅用 loading 或当前对象变量，未同时绑定请求代次、弹窗会话和编辑版本。`Promise.all` 后集中提交把面板成败绑在一起。
- 弹窗重开重置了写入中的状态；响应守卫只能拦截 UI 回写，不能取消已发送的服务端写入。导入最外层固定错误文案吞掉校验上下文，中间件不会向客户端返回异常 cause。
- parser 状态只在某个成功/失败分支初始化，循环合并却没有消费下一行。

## 修复

- 上传只在事件循环读取文件，随后将解析、匹配和完整 Session 生命周期放入一个同步工作单元；不修改原匹配结果规则。
- CSV 用 UTF-8 BOM 兼容读取，数组导出 JSON，兼容旧分隔列表；全文件解析与字段校验成功后才调用既有逐行提交。插入时从执行结果取得 `lastrowid`，提交成功才返回。
- 预校验必须包含冻结 DDL 的存储边界：嵌套 JSON 禁止 NaN/Infinity、FLOAT 范围、TEXT 的 UTF-8 字节数及 DATETIME 年份/格式，不能只依赖 Pydantic 类型。无时区日期规范为 SQL 格式，不擅自解释带时区导入值。
- 图谱请求只关闭 session；共享 driver 延迟初始化，由应用退出时释放并重置，异常路径同样释放。
- 列表与统计独立请求；页面在每次 await 后验证当前请求/岗位/会话，编辑版本保护较新的草稿；看板/分析独立面板提交和错误重试，保留旧数据时明示刷新失败；卸载使迟到响应失效。
- Jobs 的在途写 Promise 按岗位 ID 保留到 finally，保存状态按当前岗位派生；重开详情先等待前写结束再 GET，核对完成前不能再次保存。草稿与新基线不一致仍按既有冲突提示处理，不静默合并。该约束限于同一已挂载页面，不是跨标签或其他客户端的后端版本锁。
- 导入保留安全的记录序号和模型顶层字段名；Pydantic 只取模型白名单字段，按字段核对 JSON 可编码性以准确定位。文件级编码、JSON/CSV 语法和表头错误使用固定安全说明，事务规则不变。
- `docx_module`、`has_antiword` 提前初始化，textract 处理失败后检查既有备用解析器；短行合并成功时消费下一行。优先级与合并判断不变。

## 教训与验证边界

- 详情迟到保护不能只“保留草稿”：若新详情包含旧列表没有的技能，保存时不可把它们静默当成用户删除；需识别冲突并保留草稿，显式处理后再保存。
- 写入顺序必须按岗位约束并跨弹窗保留；重新允许保存前须核对在途写结束后的基线，不能只对返回结果做会话检查。验证须包含可控持久状态及尝试逆序写入，而不只断言当前页面内容。
- 错误定位须在 HTTP 响应层验证：记录序号与受信字段名可用于定位，不能直接回显 Pydantic 错误、底层异常字符串或原始记录值。文件解析错误与记录字段错误分别表达。
- CSV 预校验不等于整批原子事务。已有逐行提交规则下，数据库中途故障仍可能保留之前成功行；本次未新增去重/覆盖/合并规则。
- 成功空、失败和仍在加载必须分别表达；Mock 图表生命周期测试不能证明真实浏览器绘制效果。
- 正常依赖缺失错误不能被 `AttributeError` 掩盖；大体积参数化测试需显式短 ID，避免夹具临时路径和日志无限膨胀。
- 本次仅合成数据、内存 SQLite 和 Mock。旧 `file_parser.py` 属文件版入口，网页上传的 PDF/DOCX/TXT 契约另行验证；不把旧 DOC 回退支持误写为网页支持。实际命令/最终 head/CI 见 [交付记录](../../review/PR71-engineering-2026-11-07.md)。


## 只读岗位浏览：分页边界与组件联动

- **症状**：概览与能力动态只请求前 100 个岗位，在此局部列表上搜索；概览换词后还停在旧页，匹配结果可能错误显示为空。局部列表长度被当作全部岗位数。
- **根因**：后端已提供分页与总数，两个页面仍在客户端二次截取；请求版本只覆盖整体刷新，没有独立保护搜索和翻页。
- **修复**：共享 `usePagedJobs`，按既有服务端筛选/排序请求单页；搜索先回首页并防抖，回车取消待发计时，新查询立即使旧请求失效。成功、加载、失败分开，同条件刷新失败保留旧数据，新查询失败不显示旧行。页数缩小只回查一次，继续变化则报错待显式重试；能力动态将选中岗位标题与时间线同时绑定。
- **组件陷阱**：翻页时不可把 `total` 临时清零。Element Plus 会因页数收缩发出 `current-change(1)`，使真正翻页被新请求取消。保留总数维持边界，清行与成功态并禁用加载中的分页器，成功后一起提交有效页码和新总数。回归除请求层外也模拟真实 Vue 下的分页器页数监听。
- **边界**：此处工程修复不定义趋势 `range`、匹配分或 M2 语义；本次回归为合成 API 与组件 setup/响应性测试，未挂真实浏览器或生产数据库。
