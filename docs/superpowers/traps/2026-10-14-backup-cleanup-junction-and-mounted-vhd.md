# 备份清理：junction 与已挂载 VHDX

## 症状

2026-10-14 第二轮，旧备份的批量/递归删除被自动审批拒绝；单独删除 `docker-cold-docker_data.vhdx` 又因文件被使用失败。不能把失败记录写成“已释放空间”。

## 根因

恢复测试目录中有一个指向原工作区 `node_modules` 的 junction，递归清理必须防止越界。冷 VHDX 副本被附加为 Windows PhysicalDrive1；当前会话不是管理员，无法完整卸载。审批只返回 `blocked by policy`，不能臆测更具体理由或改用另一个 shell 绕过。

## 处理

先核验精简替代包及两版 SQL、dump；以明确路径逐项清理允许执行的普通副本。为剩余项准备仅处理备份根的 UTF-8 BOM 管理员 PowerShell 7 脚本：核验 → 确认挂载盘位置属于备份 → 卸载备份盘 → 仅移除 junction 本身 → 清理旧副本 → 核验哨兵和保留文件。用户运行后，agent 独立核验 64 个旧项目均已移除，核心 9 文件约 0.967 GB、原工作区哨兵和原容器状态不变。

## 教训

授权范围与实际执行能力不同。删除前证明替代物可恢复，使用明确路径和原文件哨兵；遇到挂载/权限/审批阻断应记录真实状态，不能杀进程、停 Docker、换 shell 绕过或忽略失败。空间报告采用同口径实际分配字节，并扣除新备份占用。
