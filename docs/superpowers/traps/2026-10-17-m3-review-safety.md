# M3 待审实体关联与离线入口安全收尾

## 症状

canonical 主张已经进入 audit，REQUIRES 却可能 needs_review=false；新离线算法仍能通过旧 rebuild() 无参数写入正式文件并清空图数据库。

## 根因

待审名称集合与实体 ID 使用不同比较方式。明细带有效 bool 时其原名也被加入关系来源，原复审示例不会漏标；当 bool 缺失或为 null 时，名称大小写/空白差异会使字符串判断漏标。另一个问题是仅在文档禁止破坏性操作，实际旧入口仍然可达，未完成消费方和迁移适配也能运行。

## 修复

- 待审集合直接保存 `_skill_id(display)`，REQUIRES 按 sid 关联；不应用未经核实的 canonical 主张，不改变 legacy 状态。四组大小写/空白输入分别覆盖 True、null、缺失，并补等价 canonical 的不误标对照。
- 保留 rebuild() 名称作为明确报错入口，移除旧 DB 查询/覆盖文件/清图实现；直接调用与模块入口在任何服务导入、DB 连接及文件写入前报 offline disabled。没有开关可绕过，后续重新开放须单独设计及授权。
- 两条子进程反例拦截服务依赖导入、连接及 Path 写入并核对正式快照字节不变；修复前 8 项漏标与 2 项入口反例失败，修复后定向合计 51 passed。

## 教训

风险标记应按实体身份传播，不能依赖显示名称或可选字段恰好存在。离线边界必须在可执行路径失败关闭；文档告诫不代替安全门槛。该修复只约束此完整图入口，不宣称其他历史导入器已经安全化，也不解决前端布局和连线呈现。
