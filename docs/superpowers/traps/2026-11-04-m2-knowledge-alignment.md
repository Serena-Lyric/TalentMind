# M2 知识对齐：精确身份、模型更新与证据覆盖

日期：2026-11-04
范围：Issue #61 P2-1 离线知识对齐、候选治理、岗位比较与版本定位

## 症状

- 只按名称相似或共同出现，容易把 `JavaScript`/`TypeScript`、
  `Kubernetes`/`容器编排` 或同技能不同职责误合并。
- 对齐层若复制 P1 措辞后再重新构造，组合、程度、条件或原始证据可能被无意强化/丢失。
- 同一正文跨平台转载可能被误算为多条独立候选证据。
- 知识更新后直接覆盖旧结果，会把知识变化误报为 JD 或招聘市场变化。

## 根因

- 名称、概念关系、要求事实和工作责任是不同层；字符串相似不能证明同义或同岗。
- P1 的 nested Pydantic 对象若通过 `model_copy(update=...)` 注入普通 dict，可能留下未验证的
  混合对象，序列化时出现警告并削弱输出契约。
- 平台字段不是独立性；独立证据应以规范化正文等内容身份去重。
- 快照 SHA 变化不等于能精确推导受影响对象；缺少结构差异证据时必须保守扩大。

## 修复

- 知识快照只接受来源、许可/使用限制、字节摘要和逐字短证据齐全的 `test/candidate/formal` 条目；
  跨概念重复别名在加载时拒绝。
- 对齐仅做 NFKC、外侧空白和大小写归一；原始 member 顺序与全部 requirement 字段原样复制，
  并重新验证更新后的 Pydantic 对象。
- 岗位比较由职责锚点和显式边界决定；目录缺口只能是 `unresolved`，`not_supported` 必须同时
  保留职责证据与知识边界证据。
- 候选观察按 namespace/JD/claim/member 去重，独立证据按规范化正文摘要去重；版本只追加。
- 影响范围按概念/别名/关系/角色/来源变化定位，无法归类时返回全部受影响对象。

## 教训

“找到字符串”“引用能定位”“同一模型说相同”都不等于语义身份或人工事实。先保存确定性的原始引用，
再把知识关系、候选版本、岗位比较和画像作为独立可重建层；正式准入与关键身份变化继续人工确认。
## 2026-11-04 独立复审补充

- 关系影响不能要求两个端点都出现在旧对齐；新关系只要连接旧概念或旧邻居，就会改变其
  `related_concepts`，必须重评。计算影响前，所有历史对齐还必须绑定 `old_knowledge_sha256`。
- 职责关键词命中前要检查局部否定；P1 duties coverage 不完整或 duty core 未确认时不得输出
  `supported/not_supported`，也不能把该成员写入支持画像。
- 自动候选不能只记录观察：同一义项达到独立证据策略后生成独立 candidate projection；不同上下文
  必须隔离为 competing candidates 并保持未决，不能互相累计验证强度。修订必须绑定新增 P1 证据。
- 岗位目录为空是合法状态：技能知识仍可读取/对齐，岗位比较显式返回 `no_role_candidates`。
- 快照清单摘要只证明仓库 JSON 与清单一致；外部页面/PDF 的真实性与现行内容需要在受控私有
  证据中重新核对，不能由本地加载器自动声称。

## 2026-11-05 第二轮复审补充

- candidate projection 的消费必须同时匹配词面、`target`、`category` 和上下文；只在 registry 端分组、
  在 align 端只按词面读取，会把技能候选错误用于学历、证书或其他领域要求。
- “不同正文”不是独立证据。自动核验必须检查已知来源身份、同源改写和跨来源近似转载；来源不明时
  保持 observing，不能以另一固定正文数量阈值代替证据质量。
- 教学、开发等用途上下文不同，不自动证明概念身份冲突。可以隔离为不同 candidate context，
  只有当前要求匹配相应 context 时才能读取；显式 disputed 仍由反证或人工判断产生。
- 静态知识 SHA 相同不代表 candidate projection 相同。impact 必须比较新旧 projection SHA 与
  concept 集合，画像必须绑定一个 projection SHA 并拒绝混版。
