# BOSS 安全校验循环与错误目标状态

## 症状

点击采集搜索目标或显式准备浏览器后，BOSS 页面快速在搜索页和安全页之间切换，最终返回首页；控制台可能同时看到多个同域标签或错误的访问状态。

## 根因

BOSS 站点在搜索 URL 上追加递增的 `_security_check` 参数，并在 `/web/passport/zp/security.html` 与搜索页之间跳转，最终回到首页。准备阶段原先每 0.5 秒通过 CDP 读取页面状态，前端又定时查询 CDP；对照实验显示，完全不检查页面时不会出现每秒多次刷新，而会在较长等待后单次返回首页。搜索目标外链还会额外打开普通浏览器标签，放大重复访问。

状态查询原先可能检查同域下任意旧标签，而准备后已经绑定的目标页也可能被无关安全标签阻断。仅检查页面是否有职位卡会把带 `_security_check` 的中间页误当作可采集。

## 修复

- 带 `_security_check` 的页面立即归为自动安全校验，不再错误提示用户处理不存在的验证内容。
- 准备和状态查询按 `target_id` 只检查本次目标页；首页回退明确标记 `target_page_redirected`。
- 默认准备只检查一次，不再循环读取；前端 5 秒自动刷新只更新任务和数据库状态，不查询浏览器。
- 只有“准备 / 重新检查”和顶部“刷新状态”会显式触发一次浏览器检查。
- 搜索目标改为只读展示，避免从 TalentMind 再次打开普通浏览器标签。

## 教训

访问受限时，轮询本身也会成为额外访问。系统应停止自动访问并保留清楚的等待态；不能拦截跳转、锁定页面或自动处理验证。访问检查必须绑定当前目标标签，站点内容和同域旧标签不能互相冒充。

## 补充诊断（2026-10-21）

同一独立 profile、同一账号缓存和禁用扩展下，不启用远程调试直接打开搜索页时，等待24秒仍停留在正常搜索页；启用远程调试并从 `about:blank` 通过 `/json/new` 创建搜索页时会出现 `_security_check` 跳转。首次启动现已直接以目标搜索 URL 打开，不再先创建空页；默认只建立一次页面读取，之后停止自动CDP检查。一次调试连接仍可能被 BOSS 识别并返回首页，因此上述修改解决重复刷新和错误人工验证提示，但不能保证站内自动化访问始终可用。若需要稳定采集，应另行设计基于普通用户浏览器扩展的人工触发采集方案，不在本修复中伪装或绕过站点验证。
