# BOSS 安全校验循环与错误目标状态

## 症状

点击采集搜索目标或显式准备浏览器后，BOSS 页面快速在搜索页和安全页之间切换，最终返回首页；控制台可能同时看到多个同域标签或错误的访问状态。

## 根因

BOSS 站点自身在搜索 URL 上追加递增的 `_security_check` 参数，并在 `/web/passport/zp/security.html` 与搜索页之间连续跳转，次数耗尽后回到首页。TalentMind 的准备和定时状态查询不会调用页面刷新；搜索目标外链只是额外打开普通浏览器标签，会放大重复访问。

状态查询原先可能检查同域下任意旧标签，而准备后已经绑定的目标页也可能被无关安全标签阻断。仅检查页面是否有职位卡会把带 `_security_check` 的中间页误当作可采集。

## 修复

- 带 `_security_check` 的页面立即归为 `verification_required`，不进入采集。
- 准备和状态查询按 `target_id` 只检查本次目标页；首页回退明确标记 `target_page_redirected`。
- 安全验证期间前端暂停自动 CDP 检查，只保留显式“准备 / 重新检查”。
- 搜索目标改为只读展示，避免从 TalentMind 再次打开普通浏览器标签。

## 教训

站点要求人工验证时，系统应停止自动访问并保留清楚的等待态；不能拦截跳转、锁定页面或自动处理验证。访问检查必须绑定当前目标标签，站点内容和同域旧标签不能互相冒充。
