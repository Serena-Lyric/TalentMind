# B3-2 审核必须绑定具体候选结果与完整依赖

## 症状

离线候选内容变化但规则版本相同时，若审核只引用规则 manifest，则旧事件可能被用于新提案；仅改成正文摘要仍不足，规则变化但正文相同也能复用旧事件。

## 根因

规则版本、候选提交版本与具体结果版本是不同身份。review 只校验其中一项会漏掉其他变化。

## 修复

result_version 同时绑定 manifest version_id、完整 submission 摘要和结果正文摘要；record_review 同时核对 result_id、目标类型/ID 和该摘要，supersedes 只能指向同结果/目标/版本的旧事件。审核仍不触发正式准入。

先写失败回归：仅 rules 改版时复制旧审核，预期拒绝却未拒绝（1 failed / 1 passed）。修复后定向及完整阻网非集成回归通过。候选主张变化、规则变化、空白归因、外部引文、错位引文、撤回引用错误均有测试。旧报告始终不被新事件改写。

## 教训

审核的版本引用须覆盖实际被审核对象及其依赖，不能只引用共享规则或可相同的展示正文。通过审核与正式准入始终分开。
