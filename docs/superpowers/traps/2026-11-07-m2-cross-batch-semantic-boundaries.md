# 跨批研究：逐成员直接支持、来源语境与范围收窄

## 症状

字面二元字符检索会把同工具教学、否定、条件或辅助职责加入开发候选；A 的成员 B 包含另一项工作后，C 仅相似 B 的新增工作也进入 A。初版有界语义又曾因 `software/system` 粗对象标签产生错误关联。反过来，复杂 claim 中只支持一个方面时全部保留未知，会遗漏可研究的局部任务。

## 根因

- 检索命中被当作自动关联依据，没有逐个有效成员验证同一入批职责。
- P1 转述不能替代原始引文的责任主体、否定和条件；通用对象标签也不证明具体功能相同。
- 当前关系引用是完整 claim ID。局部方面有支持不等于完整 claim 都有支持，直接放宽会把剩余未支持范围带入后批。
- 给新增自动关系写比较状态时，若把它直接用于解释含义指纹，相同正文换身份会被误算为研究进步。

## 修复

- 字面结果保留为对照；自动研究使用共用有界语义接口的原始引文检查，同一职责须得到每个有效成员直接支持。共同解释还对选定成员任务两两检查，不取传递闭包。
- 条件、否定、他责、辅助/核心错位、未决反证阻止自动扩张；`core=null` 明示未知，不能称为已知核心。不同方面只表示无支持，不自动成为事实反证。
- 语义共同工作、逐成员差异、辅助与未覆盖职责分别保存；正式身份和整岗确认保持空/否。纠正/撤回保留旧关系、旧快照，后批仅消费收窄后的有效范围。
- 相同且明确承担的原文可保留精确重复局部观察，单列证据性质；未识别文本不假装已获语义解释。自动比较和显式机器观察不凭状态字符串制造有效研究版本变化。
- 固定旧 CLI 与新真实 delivery 连续回放分开留存；全量记录不代替人审。已知局部漏项列为来源绑定 Agent 诊断，不以拒绝数量或 synthetic 通过率宣称真实准确率。

## 教训

自动生效的是有范围和来源的研究假设。要支持复杂 claim 的部分方面，必须先把作用域细化为可持续消费的 span/aspect 引用，再扩大自动关联；不能只放松阈值。只读维护接口使用 SQLite `mode=ro`，避免 GET 为读取而争抢写锁。
