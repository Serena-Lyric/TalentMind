# 星云视觉合并：业务回退与窄屏顶栏

## 症状

PR #45 的 `App.vue` 与 `Collection.vue` 冲突。远端分支只有视觉提交，但基线早于新版 M2 和 M1 单轮/批次整合；若整体选择远端文件，会删除新版 M2 导航、批量任务、当前城市配置和真实计数流程，恢复旧持续采集入口。合并后的 CSS 还把静态侧栏写成“数据已连接”，390px 窄屏顶栏标题被用户区挤压成竖排。

## 根因

冲突文件同时包含业务结构和大段视觉结构，普通三方合并无法自动区分“保留主线行为”和“采纳分支外观”。后续全局视觉层改变了侧栏宽度与顶栏内容密度，但原响应式规则仍保留面包屑和完整用户标签。

## 修复

- 以当前 `master` 的 `App.vue` 路由和 `Collection.vue` 脚本/模板业务区为基线，只移植品牌、模块标识、插画、气泡和卡片视觉。
- 明确保留新版 M2 入口、单轮/批量互斥、批次创建与统一停止、主线城市接口、真实质量字段和持续采集禁用门禁。
- 将静态连接暗示改为“Career Nebula 视觉主题”“页面状态以实时结果为准”“演示模式”；实际连接状态只由接口返回值表达。
- 在 560px 以下隐藏面包屑、收起用户文字并让顶栏操作靠右，避免标题被压缩；390px 下复验采集、M2 和图谱。

## 教训

视觉分支冲突要先按 template、script、style 分别核对业务基线，不能整文件取任一侧。静态装饰不得充当连接或运行状态；响应式验收要包含真实窄屏截图，而不是只看桌面布局。
