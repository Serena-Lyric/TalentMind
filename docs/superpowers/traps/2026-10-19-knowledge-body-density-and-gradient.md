# 主体类型被随机恒星掩盖、密集光晕与单色关系

日期：2026-10-19；P2.5，基线 P2.4 `df1ca24`，实施从文档 HEAD `b7e6f65` 派生。

## 症状

P2.4 以稳定 ID 分配四类恒星，业务身份只在外部细标记上表达；大量红橙节点抢占画面，近景叠光；关系线按关系类别使用单色/虚线，不能表达用户要求的端点渐变。

## 根因

装饰外观成为主体类型，未依据 `node.kind` 建立主体；普通点缺少屏幕空间密度响应。关系 shader/geometry 将颜色和线型绑定关系类别，与原边语义、端点身份耦合。

## 修复

- 新主体按 Job/Skill/历史 Industry 投影映射蓝色球面、青绿紧凑星、紫色环状体；ID 仅控制静态表面纹理。
- 双线性网格投射/采样构成连续密度场，每点固定八次网格访问；仅缩小视觉占用、光晕及透明度，保留原拾取半径和布局/LOD/类型规则，保护选中、悬停、搜索和直接关联。
- 曲线每段顶点颜色按真实 source→target 主色插值，保留 `sourceIndex`；高亮只调整透明度。常态菜单移除旧线型图例，详情保留关系类型、方向、原文与索引。
- `graphStars=p24` 保留原材质与装饰强度，`p23` 及更早回退保留。P2.4 原证据和精确 Git 基线仍在。

## 教训

主体语义不能依赖微小外标；密度优化必须与可见/高亮/拾取集合分开。渐变几何、原边身份和实际 shader 要一起检验，不能凭 UI 文案声称完成。截图须记录完整相机、视口/DPR、冻结时钟和源摘要；最终美术仍须用户验收。浏览器列表自动滚动可令鼠标落入另一行触发 hover，高亮核验须移开指针，并保留瞬态结果；不能把该情况误作来源错配。
