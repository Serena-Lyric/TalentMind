# 完整宾语、短引文与源上下文解释

## 症状

默认研究把“编写软件采购合同”支持为软件开发，把“优化神经网络”支持为通信网络优化，实际跨批候选会自动关联。原文“协助职责”标题在短引文中丢失后，辅助任务又被当作普通核心候选的同工作。

## 根因

- 从对象内部抽取“软件/网络”与最近动词组合，整句只要有一个 frame 就隐藏剩余对象含义。
- 来源上下文解释只追回 scope 标题，未传递 importance；对裁剪后的引文再次解析，会绕过完整对象限制。整句统一 importance 又会把后半句辅助性质借给前半句。
- v3 的保存输入和校验状态依赖当时 parser。直接升级共享代码会破坏已公开历史结果读回。

## 修复

- 新 `bounded-work-semantics-2` 检查完整宾语；没有解析的复合中心保留具体缺口，不用两个句子的黑名单，也不把所有工作降为未知。
- 共享动词后的并列宾语分别保留：合同与代码同时出现时，代码可形成局部支持，未知合同仍进 gap，整项职责不因此关联。NFKC 匹配保留名词头原文偏移，短引文不能借同句后项的同名对象。
- `source_work` 保存精确引文、完整上下文和控制标题证据，按局部片段传递作用域/重要性。候选比较与默认研究直接消费已绑定解释。上下文可以排除错误支持，不能添加未引用的动作或对象。
- 完整未知原文重复仍可形成独立标记的 literal 观察；被上下文否定的裁剪解释不能借 exact-repeat 通道绕过。
- 新 work v4 的输入、源门禁与候选重要性消费同一源解释。旧 v3 使用冻结 parser；v1/v2/v3 的解释和历史摘要版本保留。修复重解释写新目录，不覆盖旧输出。

## 教训

第二轮复审发现两种仍会随引用裁剪改变意义的情况。无冒号/括号式“协助职责”未进入旧冒号扫描，合法短引丢失辅助限定；若把完整引用中的标题本身继续当未知工作，使用同样辅助职责作对照时，完整引用又会因多出gap被拒绝，而短引用建立关联。新源模式识别整行明确标签、保留原始控制证据，并将结构标题与工作内容分开；主要标题可重置，普通动作叙述和后置辅助不污染前文。

另一个引用边界是完整源工作已有动作/对象，但引文仅为“编写”“软件”“代码”。它们不能走普通未知词汇通道借用未引用事实。新模式在known span局部没有有效frame时保留引用限制并追加`uncited_action_or_object`，包括原来已有普通未知gap的情形；重复局部单位合并也保留该限制。真正未识别的源工作分支不受此规则替代。

为避免修复重解释旧v4，`recover_plain_headings=False`保留旧冒号及局部引用行为，source_explanation和局部view仍标版本2；新默认版本3。固定`312013b`的11组公开合成输出逐项深比较；真实临时CandidateStore长短引用、辅助/核心两种对照、标题重置、NFKC/CRLF原偏移及P1不变均有回归，临时夹具finally清理。实际新工作版本的接收门禁与历史分派须随统一集成核对，不能仅以producer字段存在宣称接通。

同一个正则纯函数通过，不能证明真实消费链安全。必须覆盖默认知识研究、真实 CandidateStore/apply_batch、模型双正回包、合法长短引文、反向裁剪，以及不可变历史读取。旧响应只在提示词完全相同的条件下重校验；任何新提示必须与旧响应分账，不冒充 fresh 模型结果。
