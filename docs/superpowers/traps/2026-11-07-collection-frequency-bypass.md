# 采集频率不能只依赖可调 delay

## 症状与根因

旧 CLI/配置允许 delay=0 或非有限值，列表到首详情、单页跨组合和普通浏览器扩展没有共用频率门禁。调用方各自 sleep 不能阻止另一入口或新进程立即访问；仅在详情提交后限流也不能阻止 DOM 先被读取。

## 修复

三个招聘平台共享私有 SQLite 频率账本，在动作前提交预约，跨进程以 BEGIN IMMEDIATE 串行。默认随机页面15–30秒、组合360–720秒；明确准备搜索 URL 同样按真实组合计数，模板与声明组合不一致拒绝。CDP callback 持跨进程事务锁执行，完成后重新计时，失败保留 unfinished 标记而非自动继续。配置/CLI执行前校验有限值与硬下限，低于5秒的页面稳定参数拒绝。有效冷却等待后重新预约；损坏、存储失败和时钟回拨停止。失败不退还已预约额度。

扩展必须先从受配对保护的端点预约，获准后才读取页面。桥接选择30秒预约，使用期限15秒；组合预约375–720秒补偿许可晚用窗口，提交前通过 SQLite 条件 UPDATE 跨进程原子消耗一次性票据；相同已完成内容可只读返回既有结果。没有票据的旧客户端不能处理新内容。background 及注入函数内部均检查到期，异步调度延迟不能用过期许可读 DOM。严格无正文阻断消息始终可停止任务，不需要为了上报验证页再预约一次采集。

## 验证边界与教训

测试使用真实频率模块、入口和桥接路由、临时SQLite、假时钟和模拟浏览器。包含精确边界、并发竞争、两进程同票据仅一次消费、新解释器重启、跨入口/任务、非法数值、状态损坏和采前授权拒绝；不是实机网站或正式数据库验收。实际试采仍应通过相同模块与频率，不另写跳过门禁的脚本。

账本不应作为可随意删除的缓存。客户端中止不能证明服务端没有提交；持久票据消费用于保守防重复，不宣称跨文件/业务数据库的原子事务或 exactly-once。模块门禁不能控制任意人工浏览或外部工具，不能据此声称全部网站访问都被限速。

跨平台动作共享同一SQLite文件事务锁，长动作可能使另一入口在5秒后报busy并失败关闭，不声称独立并行。会话JSON与业务数据库仍不是同一事务；票据CAS解决单许可多worker重复消费，但不把已有finish/append会话竞态说成已全面解决。
